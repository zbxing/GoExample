## 1. 执行摘要与本轮结论

V126-01 已完成固定 SHA-256 小写 hex 校验 fast path，并将有效综合分提升至 `9.931032/10`。V126-02/V126-03 仍需要真实 edge、正式 IdP/MFA、生产数据服务、灾备设施、容量窗口、远端 provenance 和组织批准，当前工作站不可替代，继续标记为 `not_recorded`。

本轮按照 `docs/评估/测试环境.md` 先执行 Windows 本机可复现门禁，再检查可用的真实进程级依赖。首次 `yarn vuln:server` 发现 `google.golang.org/grpc v1.83.0` 命中 `GO-2026-6348`，该漏洞在 `v1.83.1` 修复。V127-01 已将 Framework、Solutions/Example 和 HealthProbe consumer 三个模块统一升级至 `v1.83.1` 并刷新校验和；升级后 `govulncheck` 报告项目代码受影响漏洞为 0，测试、race、vet、build、API、release、Node 和 evidence 门禁均通过。

工作站已有 `nats-server v2.14.5`，因此额外完成 delivery、restart、三节点 cluster 和 snapshot 四组真实进程合约及独立 verifier。它们只证明 Windows loopback 上的 `local_contract_only` 行为，不证明跨主机 HA、生产权限、生产延迟、容量或 RPO/RTO。WSL2、Docker、Redis Sentinel、PostgreSQL、Nginx Edge 和本地 Kubernetes 当前不可用或未安装；相应旧产物不被沿用，能力状态保持 `not_recorded`。

## 2. 评估方法、证据等级与边界

- 通过 Graphify 查询架构、调用关系和历史清单，再以源码、行为测试、race、漏洞扫描、vet、build、API/SDK 兼容性、evidence manifest 和独立 verifier 复核。
- `local_verified` 只表示 Windows 仓库级门禁通过；`local_contract_only` 只表示本机真实进程或 loopback 合约通过；目标环境事实仍需 `recorded` 级原始证据。
- 性能 benchmark 只用于同一工作站的相对比较，不外推生产 RPS、p95/p99、CPU、RSS、GC、网络延迟、HA 或容量结论。
- 可接受证据必须可重建：源码、测试、兼容性门禁、manifest、checksum 和独立 verifier 均来自仓库或可复现命令。
- loopback、fixture、mock broker、模板、文档和 checksum 不能替代真实 edge/IdP/生产数据/灾备/容量/硬件/provenance/审批证据。
- 任何安全、所有权、生命周期、公开 API、schema、错误 sentinel、`MSFront` 范围或门禁回归都取消本轮增分。

## 3. 架构与所有权评估

### 3.1 Workspace、模块与依赖方向

`go.work` 组合 Framework、Solutions/Example、Services/Billing、双 Go SDK 和 HealthProbe consumer。业务模块依赖 Framework，Framework 不反向依赖业务模块或生成 SDK；API snapshot、consumer matrix、release manifest 和 workflow guard 共同约束公开边界。

### 3.2 入站请求、协议与生命周期

Framework 统一 `net/http` 边界并提供 Fiber 适配、TLS/HTTP2、超时、draining、shutdown、streaming/SSE、标准 HTTP handler 和连接观察。请求上下文、caller deadline、取消、写超时和 shutdown 使用单一结果边界；ETag、CORS、压缩、限流、幂等、Body/header 上限与安全响应头保持既有契约。

### 3.3 出站 HTTP 与依赖背压

标准库 HTTP client 负责 cloned TLS/mTLS、W3C propagation、CLIENT span、proxy、retry、circuit breaker、body ownership 和 bounded timeout；Redis/SQL/NATS 调用在 caller completion 后 fail-closed，不能把未知结果误判成成功或安全重试。

### 3.4 身份、安全与授权

本地 JWT/OIDC 包含 JWKS 单飞刷新、issuer/audience、nonce、ACR/AMR、MaxAuthAge、浏览器会话和外部 IdP 组合根。应用查询/命令在认证、授权、媒体类型、幂等和绑定前遵循固定顺序，审计与指标使用固定低基数并禁止泄露 token、secret、URL 或原始错误。

### 3.5 数据、消息与一致性

Redis Lua 原子状态、Sentinel、PostgreSQL optimistic version/rollback/retry/outbox、broker-neutral queue 和 JetStream adapter 分别拥有存储、消息和结算边界。JetStream 过滤控制头、拒绝多值 header、复制 body/header、确认 publish/ack、bounded pull、lease、DLQ 和 preflight；本轮在本机真实 `nats-server v2.14.5` 上复验 delivery、restart、cluster 和 snapshot，但证据等级仅为 `local_contract_only`。

### 3.6 API、SDK、CI 与交付

OpenAPI、snapshot、双 SDK、consumer matrix、release provenance、Kubernetes/Nginx/Prometheus、workflow lint、manifest/verifier 和 Graphify 共同形成交付证据链。V127-01 消除三个可执行模块中的已知 gRPC 可达漏洞版本；任何新增清单必须加入 evidence contract 与 Node guard，最终 manifest 重新生成并独立校验。

## 4. 性能、容量与本地测试环境

### 4.1 已有运行时覆盖
