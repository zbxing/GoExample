## 2. 评估方法、证据等级与边界

- 通过 Graphify 查询架构、调用关系和历史清单，再以源码、行为测试、永久 benchmark、race、vet、build、API/SDK 兼容性、evidence manifest 和独立 verifier 复核。
- 性能 benchmark 只用于同一工作站的相对比较，不外推生产 RPS、p95/p99、CPU、RSS、GC、网络延迟、HA 或容量结论。
- 可接受证据必须可重建：源码、测试、benchmark、兼容性门禁、manifest、checksum 和独立 verifier 均来自仓库或可复现命令。
- loopback、fixture、mock broker、模板、文档和 checksum 不能替代真实 edge/IdP/生产数据/灾备/容量/硬件/provenance/审批证据。
- 任何安全、所有权、生命周期、公开 API、schema、错误 sentinel、`MSFront` 范围或门禁回归都取消本轮增分。

## 3. 架构与所有权评估

### 3.1 Workspace、模块与依赖方向

`go.work` 组合 Framework、Solutions/Example、Services/Billing、双 Go SDK 和 HealthProbe consumer。业务模块依赖 Framework，Framework 不反向依赖业务模块或生成 SDK；API snapshot、consumer matrix、release manifest 和 workflow guard 共同约束公开边界。

### 3.2 入站请求、协议与生命周期

Framework 统一 `net/http` 边界并提供 Fiber 适配、TLS/HTTP2、超时、draining、shutdown、streaming/SSE、标准 HTTP handler 和连接观察。请求上下文、caller deadline、取消、写超时和 shutdown 使用单一结果边界；ETag、CORS、压缩、限流、幂等、Body/header 上限与安全响应头保持既有契约。

### 3.3 出站 HTTP 与依赖背压

标准库 HTTP client 负责 cloned TLS/mTLS、W3C propagation、CLIENT span、proxy、retry、circuit breaker、body ownership 和 bounded timeout；Redis/SQL/NATS 调用在 caller completion 后 fail-closed，不能把未知结果误判成成功或安全重试。

### 3.4 身份、安全与授权

本地 JWT/OIDC 包含 JWKS 单飞刷新、issuer/audience、nonce、ACR/AMR、MaxAuthAge、浏览器会话和外部 IdP 组合根。应用查询/命令在认证、授权、媒体类型、幂等和绑定前遵循固定顺序，审计与指标使用固定低基数并禁止泄露 token、secret、URL 或原始错误。

### 3.5 数据、消息与一致性

Redis Lua 原子状态、Sentinel、PostgreSQL optimistic version/rollback/retry/outbox、broker-neutral queue 和 JetStream adapter 分别拥有存储、消息和结算边界。JetStream 过滤控制头、拒绝多值 header、复制 body/header、确认 publish/ack、bounded pull、lease、DLQ 和 preflight；V126-01 只触及哈希格式校验的内部 CPU/分配路径。

### 3.6 API、SDK、CI 与交付

OpenAPI、snapshot、双 SDK、consumer matrix、release provenance、Kubernetes/Nginx/Prometheus、workflow lint、manifest/verifier 和 Graphify 共同形成交付证据链。任何新增清单必须加入 evidence contract 与 Node guard，最终 manifest 重新生成并独立校验。

## 4. 性能、容量与资源评估

### 4.1 已有运行时覆盖

已有覆盖包括 auth assurance、Metrics.Render、HTTP handler/middleware matrix、幂等 fingerprint、header 校验、trace carrier、JetStream message conversion、literal subject、control header、delivery option、Redis/SQL operation、session integrity 和 transport benchmark。它们是同机相对证据，不代表目标生产容量。

### 4.2 V126 热路径基线

本轮候选基线命令：

`go test ./sharedstate -run '^$' -bench 'BenchmarkValidSHA256Hex' -benchmem -benchtime=300ms -count=5`

Windows/amd64、Intel i5-10400、Go 1.27.1 的五轮范围为：优化前 `133.1–136.8 ns/op、160 B/op、3 allocs/op`；优化后 `30.21–31.83 ns/op、0 B/op、0 allocs/op`。等价性测试覆盖合法小写、大小写、非 hex、错误长度和 Unicode；结果只用于同机相对比较，不外推生产吞吐。

### 4.3 容量与资源边界

浏览器会话和授权请求的哈希、索引、TTL、payload 关系仍必须 fail-closed；直接校验不能接受大写、非 hex、错误长度或 Unicode 变体。真实 broker、TLS edge、HA、RPO/RTO、容量窗口和硬件性能均未在本工作站记录，保持 `not_recorded`。

## 5. 风险、非目标与停止规则

- V126-01 不改变 `validSHA256Hex` 的规范小写 hex 接受集合或 fail-closed 结果。
- 不改变 Redis key/schema、Lua 原子边界、payload/index/TTL 关系、公开 API、错误 sentinel 或 context 边界。
- 任一行为、race、vet、build、API/SDK、Node、evidence、Graphify、格式或 MSFront 范围门禁失败，恢复 V125 有效综合分 `9.931026`，不计本轮增量。
- 真实 edge/身份/容量及生产恢复/provenance 只有取得原始输出、独立 verifier、不可变制品和批准窗口后才能关闭；本地结果继续 `not_recorded`。
