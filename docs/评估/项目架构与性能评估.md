## 3. V93 本地优化与行为边界

复评发现 `Framework/sharedstate/browser_session_store.go` 的 `ReadBrowserSession` 在发现记录过期后，无条件调用 `deleteBrowserSessionByHash(context.Background(), tokenHex)`。如果 caller 在读取命令返回后已取消，该删除仍会脱离请求继续写 Redis，并生成后台 tracing span。

V93-01 将清理改为：先用 `completedRedisContextError(ctx)` 判断 caller context；仅当 context 仍有效时复用原子删除脚本，否则跳过 best-effort 清理并返回既有 `auth.ErrBrowserSessionExpired`。正常过期读取仍清理记录；取消路径不启动 goroutine、不产生第二条 Redis 命令、不改变错误脱敏。

实现不新增公开 API、配置、schema、operation、连接、锁或重试；未修改 `MSFront`。

## 4. 协议、请求生命周期与中间件

Framework HTTP client 继续提供 caller context 权威性、retry/circuit breaker、response body/header 上限、HTTP/1.1 与 HTTP/2、trace propagation 和 exactly-once body close。SDK 与 OIDC/JWKS 使用独立 bounded transport。真实 DNS、证书、代理、HTTP/2/3 协商与目标 edge 仍需指定环境证据。

## 5. 数据、消息、身份与授权

Redis session、browser session、authorization request 的 Lua 脚本继续校验 hash、索引、TTL、expiry、状态和 payload；V93 只避免取消后 detached cleanup。SQL transaction/optimistic update/outbox、JetStream settlement/retry/backpressure、OIDC/JWKS、审计链与 Prometheus 规则沿用既有合同。正式 HA、PITR、RPO/RTO、KMS/SIEM、IdP/MFA 与 exactly-once 仍不在本机可证范围。

## 6. 性能、内存、并发与容量

正常 browser-session 读取的 Redis 命令、Lua、分配、锁和连接预算不变；caller 已取消时少一次删除尝试和一个潜在 span。该变化改善取消边界和共享状态写入归属，不证明生产吞吐、延迟、RSS、GC、HA 或目标容量提升。目标容量、跨主机连接池和真实恢复必须由外部环境记录。

## 7. 安全、可靠性与可观测性

- 取消请求不再继续删除共享 session，降低竞态误删和审计顺序漂移风险。
- 有效 context 的过期清理仍通过同一原子脚本，索引、TTL 和错误语义保持不变。
- 取消路径只保留一次读取 span；不记录 URL、凭据、raw token 或后端原文。
- 正式 Redis/PostgreSQL/NATS、KMS/SIEM、IdP/MFA、目标容量和远端制品继续 `not_recorded`。

## 8. 验证结果与证据边界

V93 必须通过并已纳入门禁：sharedstate 定向 test、Framework 全量 test/race/vet/build、API compatibility 373、项目合同 26/14、双 SDK check、Node script guards、server-release、evidence manifest/verifier、Graphify update 与 `git diff --check`；最后确认 `git diff HEAD -- MSFront` 为空。

本地 miniredis/tracing 测试只证明过期读取的取消边界、单命令/单 span 和正常回归；不证明生产 Redis HA/TLS/ACL、跨主机恢复、PITR、RPO/RTO、容量、目标网络或远端不可变制品。
