## 1. 互斥分支、范围与证据边界

V89-01 的 health panic 隔离和 evidence contract 已完成；V89-02/V89-03 只剩真实 edge、DNS、证书、代理、HTTP/2/3、正式 IdP/MFA、生产 Redis/PostgreSQL/NATS、KMS/SIEM、跨主机恢复、目标容量、远端制品和组织审批。当前设备没有 Docker/Podman/nerdctl，WSL 没有 Linux 发行版，不能诚实替代这些目标环境。

因此本轮执行互斥分支“全面复评 -> 生成 V90 -> 按 V90 实施”，不回到 V89。fake、httptest、loopback、静态 manifest 和进程级演练只证明仓库合同，不替代生产网络、依赖、容量、HA、PITR、RPO/RTO、远端 provenance 或正式发布。

评分采用 20 个非前端维度，权重直接合计 100%，综合分为 `sum(维度分 x 权重)`，不除以 `0.94`。Graphify 在代码修改后更新；MSFront 在所有查询与门禁中排除。

## 2. 复评方法与架构结论

复评覆盖 workspace/模块、依赖方向、标准生态、API/schema、协议网络、中间件、身份认证、授权审计、配置密钥、并发 context、性能容量、可观测性、数据、消息、测试、供应链、部署弹性、恢复、文档与证据完整性。源码、生成器、双 SDK 测试、Node 守卫、manifest contract 与 Graphify 关系共同作为计分依据。

- `go.work` 固定 Framework、Example、Billing、两套 SDK 和独立 HealthProbe consumer；业务组合根依赖 Framework，Framework 不反向依赖业务或 SDK。
- Framework 提供 transport-neutral HTTP、认证授权、共享状态、SQL、消息、观测、健康检查和服务器生命周期；驱动、业务路由和部署地址位于 adapter 或组合根。
- OpenAPI、26/14 operations、生成 SDK、独立 consumer 和 matrix 形成双项目合同；Framework API snapshot 保持 373 symbols。
- `scripts/go-sdk.mjs` 是两套 `client.gen.go` 的唯一规范源，`sdk:generate/sdk:check` 防止生成漂移；公开 `WithHTTPClient` 仍是调用方显式接管边界。

## 3. V90 本地优化与行为边界

复评发现两套生成 SDK 的默认 `http.Client` 虽已具备 30 秒总超时和首个 3xx wire response 保留，但 `Transport` 为 nil，实际继承可被任意初始化代码替换的进程级 `http.DefaultTransport`。这使代理、HTTP/2、dial/TLS、连接池、响应头和 idle 预算不可审计，也会让无关组件共享同一全局池。

V90 在唯一生成器中增加包私有 `defaultSDKHTTPTransport`：`http.ProxyFromEnvironment`、5 秒 `net.Dialer` connect/TLS、`ForceAttemptHTTP2`、`MaxConnsPerHost=100`、`MaxIdleConns=100`、`MaxIdleConnsPerHost=10`、90 秒 idle、10 秒 response-header 和 1 MiB header 上限。`defaultSDKHTTPClient` 继续使用 30 秒总超时与 `preserveSDKRedirectResponse`；`WithHTTPClient` 不包装、不修改调用方实现。

双 SDK 同包回归测试确定性证明默认 transport 独立、有界且保持代理/HTTP2/redirect；自定义 client、V86 context/body ownership、V87 redirect、V88 total timeout 和 V89 health 行为不变。未新增公开 API、schema、operation、重试、应用 goroutine、网络往返或敏感诊断。

## 4. 协议、请求与生命周期

Framework HTTP client 继续提供 caller context 权威性、retry/circuit breaker、response body 上限、HTTP/1.1/HTTP/2 和 exactly-once close。SDK 默认路径增加 transport 资源隔离，但不改变 context、redirect、body 读取或错误优先级。真实 DNS、证书、代理、HTTP/2/3 协商和目标 edge 仍属于 V90-02 外部证据。

SQL、Redis、JetStream 和 health 的既有 timeout、取消、失败关闭、迟到结果、事务/settlement 与 panic 隔离合同保持；本轮不重复修改这些已完成工作。

## 5. 性能、内存与容量评估

默认 SDK 请求从进程级共享 transport 改为包私有共享 transport，仍由标准库复用连接；不增加 body copy、header clone、retry、锁或每请求 goroutine。显式连接池、idle、dial、TLS 和首部预算让资源占用具备静态上界，减少全局 transport 污染与无关组件争用。

这不是生产吞吐或延迟证明。真实 p95/p99、CPU、RSS、连接复用、DNS/TLS 成本、HTTP/2 多路复用和目标容量必须由 V90-02 在指定环境、版本和负载下提供原始输出与独立 verifier。

## 6. 安全、数据、消息与可观测性

- SDK 默认路径不再依赖可被任意包替换的 `http.DefaultTransport`，降低跨组件配置污染和资源互相影响；不记录 URL、header、cookie、body、凭据或后端原文。
- OIDC/JWKS、session store、Redis 原子脚本、SQL 事务/恢复、JetStream settlement、Prometheus 规则、Kubernetes/edge 模板和审计链沿用已验证合同。
- 生产 KMS/SIEM、Redis/PostgreSQL/NATS HA/PITR、outbox/exactly-once、正式 IdP/MFA、容量和远端 provenance 仍未取得目标证据。

## 7. 测试、供应链与部署门禁

## 10. 最终结论与实施记录

V90-01 已完成：两套生成 SDK 的默认 HTTP client 现在使用包私有、有界、可审计的 transport，不再隐式继承进程级 `http.DefaultTransport`；30 秒总 timeout、redirect wire response、context/body ownership、自定义 client 和公开 API 均保持兼容。该修复把协议与网络能力从 8.6275 提高到 8.6400，综合评分从 9.92080 提高到 **9.92143/10（A-）**。

V90-02/V90-03 仍是提高综合评分的唯一外部路径，必须等待真实硬件、目标网络、正式依赖、生产恢复、远端制品和组织授权；本地模拟不得替代。
