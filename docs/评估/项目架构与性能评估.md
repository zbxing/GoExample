## 2. 架构与所有权复核

### 2.1 模块边界

- Go workspace 由 `Framework`、`Solutions/Example`、`Services/Billing`、SDK、HealthProbe consumer 与固定工具组成；`go.work` 与 `contracts/projects.json` 是事实来源。
- `Framework/auth` 负责 JWT/JWKS、OIDC、PKCE/state/nonce、assurance claims、refresh session 与 opaque browser session；`Framework/httpapi` 只负责 HTTP/Fiber 适配、认证、错误与审计边界。
- `Framework/sharedstate` 是显式 Redis adapter。refresh-session family、token hash、user index 和有限历史均在此持久化；Lua 负责跨 key 原子更新，Go 负责输入与结果完整校验。浏览器 session inventory 已在 V71 收敛为单次有界快照。
- `Framework/sqlclient` 负责事务、取消、乐观更新、transactional outbox 与有界重试；`Framework/queueclient` 隔离 NATS/JetStream 交付、ack、DLQ、lease、preflight 与恢复契约。
- `Solutions/Example` 与 `Services/Billing` 只在 composition root 绑定具体依赖；OpenAPI、SDK、release manifest 和证据脚本由固定工具生成。V72 不改变业务 operation、配置键、持久化 schema、HTTP/OpenAPI/SDK API 或部署拓扑。

### 2.2 已验证能力

身份与会话覆盖 issuer/audience/age、JWKS、PKCE、一次性 state/nonce、`azp`、`acr`/`amr`/`auth_time`、`at_hash`、ID/access-token subject 一致性、hash-only refresh/browser session、CSRF、清单与撤销。共享状态覆盖 SQL transaction/outbox、Redis authorization request/refresh/browser session、JetStream publish/ack/DLQ/redelivery/lease/preflight/restart/snapshot/cluster failover 的仓库内契约。所有外部生产结论仍按证据边界单独记录。

## 3. V72 全面复评发现

### 3.1 可在仓库内闭环的新缺口

`Framework/sharedstate/session_store.go` 的 refresh-token `RotateSession` 原先先执行 `GET token -> familyID`，再执行 Lua 旋转脚本；`RevokeFamily` 也先 GET 再执行 Lua。该实现有两个可验证问题：

1. 高频 rotation 每次至少两次 Redis 往返，连接池占用和跨实例延迟随调用放大；
2. token 映射读取与 family 校验不在同一 Redis 原子边界，family 删除、过期或篡改可在两条命令之间产生窗口。

缺口完全位于 `sharedstate` adapter，可在不改变 `auth.SessionStore`、HTTP、OpenAPI、SDK 或配置 API 的前提下，把 token 映射读取、family key 派生、状态校验、历史上限、轮换写入和撤销统一进一次有界 Lua 调用。脚本只接受 hash-only token key，并对内部 32 字符小写 hex family ID 做格式校验；Go 继续校验返回形状、过期时间和固定错误哨兵。

### 3.2 复评后仍不纳入的事项

真实 Redis Sentinel/Cluster HA、TLS/ACL、目标延迟与容量、跨主机/跨区恢复、生产 outbox dispatcher、broker retention/replicas/ACL、原子 settlement、PITR、批准 RPO/RTO、目标 edge/Kubernetes、正式 IdP/MFA/KMS/SIEM、远端制品 provenance、正式 SDK tag、生产 consumer 矩阵和组织演练仍需仓库外不可变证据，继续 `not_recorded`。不得以 miniredis、loopback、fixture、本地 benchmark 或脚本静态检查宣称 exactly-once、生产吞吐、HA 或恢复能力。`MSFront` 完全排除。

## 6. 性能、容量与一致性结论

V72-01 的仓库级代码推断是：一次 refresh rotation 从至少两次 Redis 命令（独立 token `GET` 加 Lua）变为一次有界 Lua 调用；family revoke 同样从两次变为一次。这样减少网络往返、连接池占用和两命令之间的状态窗口，但 Lua 仍受单个 family 的固定历史上限影响。命令数/telemetry 测试只证明 adapter 行为，不代表生产 Redis 延迟、吞吐、CPU、内存、HA、eviction、跨主机恢复或容量拐点。

V71 已将浏览器 inventory 的数据一致性分项提升至 `9.7600`；V72 进一步关闭 refresh-session rotation/revoke 的双命令窗口，将该分项提升至 `9.7900`。其他已达满分维度不重复加分；测试、文档、schema、API 或 evidence 数量本身不加分。
