## 2. 复评发现

`Framework/sqlclient` 已为普通操作创建有限 context，却没有在 driver 返回 nil 后统一复核 context：

1. Check/Exec 可把取消或 deadline 后的迟到 nil 记为 success，Exec 还返回迟到 `sql.Result`。
2. Query 可在 `QueryContext` 迟到返回 rows 后进入 consumer，使 caller callback 在预算外执行。
3. Versioned/Outbox 可在迟到 result 上继续读取 affected rows；Scan/Lock 可把迟到 nil 记录为成功。
4. Transaction 已有 Begin 后与 Commit 前检查，但只依赖 `ctx.Err()`，未覆盖单调 deadline 已到而 timer 尚未调度的窄窗。

## 4. V81-01 实施约束

1. 私有 helper 必须先读取 `ctx.Err()`，再用单调 `Deadline()`/`time.Now()` 关闭 timer 调度窄窗；正常 context 返回 nil。
2. 只有底层返回 nil error 时，完成的 context 才覆盖 success；显式 driver、consumer、close、rows 和 affected-row error 保持原错误链。
3. Query 必须在获得 rows 后立即建立 cleanup，再检查 context；context 已完成时不得进入 consumer，rows 必须关闭。
4. Versioned/Outbox 必须在 `ExecContext` 返回后及 `RowsAffected` 成功后复核 context，不能在预算外生成 success/conflict/outbox 判定。
5. Transaction 的 Begin 后和 Commit 前边界复用 helper；Commit 明确成功后不再用稍后 cancellation 覆盖，避免错误暗示可安全重试。
6. 不增加公开 API/配置/sentinel；不改变 pool/timeout 默认值、SQLSTATE 40001/40P01 retry、退避、outbox/乐观锁、SQL/参数/行值/driver 原文隐私。
