## 3. V36-01 实施设计

### 3.1 单一 release 总预算

1. 在 `scripts/lib/sdk-release.mjs` 新增 `createSDKReleaseCheckRunner()`，接收仓库 cwd、`go-sdk.mjs` 路径，并允许测试注入 spawn、process executable、timeout 与单调时钟。
2. runner 创建时只读取一次时钟并建立 `deadline = now + 90_000`；每次项目检查前计算 `min(timeoutMs, ceil(deadline - now))`。
3. timeout 必须是 1 至 90,000 的安全整数；时钟必须返回非负有限值。非法输入、时钟异常或剩余预算小于等于零时 fail closed。
4. 全部选中项目共享同一个 runner；不为每个项目重置 deadline。预算耗尽后当前及后续项目不得 spawn。
5. 90 秒内部总预算必须小于 SDK release evidence 已有的 120 秒外层进程预算，为封装、退出和制品写入保留余量。

### 3.2 进程、错误与兼容协议

- 命令保持 `process.execPath <go-sdk.mjs> check --project <name>`，cwd 保持仓库根目录。
- 每次实际启动固定 `encoding: 'utf8'`、`shell: false`、`windowsHide: true`、`maxBuffer: 4 * 1024 * 1024`、`timeout: remaining`、`killSignal: 'SIGTERM'`。
- timeout/`ETIMEDOUT`、输出溢出/`ENOBUFS`、signal、spawn error、缺失 status 与非零退出分别形成稳定错误类别；不做命令 fallback。
- 面向用户只附带 stderr 或 spawn error 的最多 4,096 字符摘要；不拼接 stdout，空诊断也保持明确失败类别。
- `scripts/sdk-release.mjs` 不再直接导入或调用 `spawnSync()`，只在一次 `run()` 中创建 runner 并依项目顺序调用。
- V34 staging/原子写与 V35 formatter 边界保持；release manifest schema、项目选择、source commit、SDK 字节和 API 均不改变。

### 3.3 测试、证据与输入契约

- 在既有 `__test__/node/sdk-release.test.mjs` 新增四项行为测试：成功路径携带完整选项且预算递减；预算耗尽/非法 timeout/非法时钟不 spawn；timeout/signal/overflow/spawn/nonzero 分类；超长 stderr 截断且 stdout 不泄漏。
- 静态守卫锁定 SDK release helper import/call、共享 runner、90 秒/4 MiB/4,096 字符常量、`SIGTERM`、无 shell，并禁止 CLI direct `spawnSync()`。

- Node 主阶段目标由 183 增至 187；release 阶段保持 1，API compatibility 预期保持 356 symbols。
