## 3. V41-01 实施设计

### 3.1 Runner 与命令边界

- `postgres-recovery-contract.mjs` 仅从 `scripts/lib/contract-command.mjs` 获取 runner，不再导入或调用 `node:child_process`。
- 每次命令在 spawn 前校验参数、环境、deadline 和输出上限；共享单调时钟，失败只结算一次。
- stdout 与 stderr 共享 8 MiB 预算；超限或 timeout 先请求 `SIGTERM`，`close` 负责生命周期收口。
- `allowFailure` 只用于探针、日志归档和 cleanup；核心 setup、Go 测试、pg_dump、pg_restore 和报告失败立即进入 finally。

### 3.2 证据、测试与边界

- 保留 `postgres:16` 固定 digest、数据库创建顺序、custom-format dump、single-transaction restore、原始恢复报告和 SHA-256 checksums。
- 静态守卫锁定 runner 导入、分级 timeout 和共享输出上限，并拒绝直接 `spawn()`。
- `contract-command.test.mjs` 继续覆盖安全 spawn 选项、跨流输出溢出、timeout、signal、spawn/missing-status/nonzero、诊断截断和 `allowFailure`；静态守卫覆盖 PostgreSQL 接入。
- 目标 PostgreSQL 恢复、PITR、跨主机 HA、RPO/RTO 和生产容量始终保持 `not_recorded`。
