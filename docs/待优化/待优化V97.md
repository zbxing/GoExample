## 1. 版本边界与互斥判定

V96-01（幂等指纹摘要结果直接写入返回数组）已完成并通过仓库内验收。V96-02/V96-03 仍只依赖真实 edge、DNS、证书、HTTP/2/3、正式 IdP/MFA、生产 Redis/PostgreSQL/NATS、KMS/SIEM、跨主机恢复、目标容量、远端不可变制品和组织审批。按互斥规则，本轮确认 V96 可诚实推进项已完成，重新覆盖架构与性能评估并生成 V97；复评发现幂等指纹的常见 JSON 媒体类型仍重复执行 MIME 解析/格式化，因此执行 V97-01。

评分继续采用 20 个非前端维度，权重直接合计 100%，综合分为 `sum(维度分 x 权重)`。V96 基线为 `9.925675/10`；V97-01 完成为 `9.926425/10`，实际增量 `+0.000750`。

## 2. 全面复评发现

1. `Framework/httpapi.idempotencyRequestFingerprint` 必须把 method、原始 URL、principal、规范化媒体类型、可选 fingerprint headers 与 body 按长度前缀写入 SHA-256；V96 已消除摘要结果临时切片，但每次仍调用 `mime.ParseMediaType` 与 `mime.FormatMediaType`。
2. `application/json` 和 `application/json; charset=utf-8` 是仓库 HTTP JSON 请求的稳定规范值，标准库规范化结果与输入字节一致，可通过常量 fast path 跳过解析与格式化。
3. 该优化位于幂等变更请求的本地热路径，不依赖真实 Redis、broker、硬件或目标网络；非标准大小写、参数顺序、空白和非法值继续走原有 MIME 规范化逻辑。
4. V97-02/V97-03 仍为外部事项，不能用本地 fixture、loopback、miniredis 或文档声明关闭。

## 4. V97-01 实施约束与非目标

1. 不新增公开 API、配置、schema、operation、API version 或 release tag；只改变内部 `normalizedMediaType` 的分支选择。
2. 仅对 `fiber.MIMEApplicationJSON` 与 `fiber.MIMEApplicationJSONCharsetUTF8` 做精确字节匹配并直接返回；其它输入继续使用 `mime.ParseMediaType`、大小写规范化、参数排序和错误回退。
3. 指纹 framing、SHA-256 算法、principal、If-Match 绑定、body 读取、Storage/Locker、ETag、replay header、冲突错误与授权顺序保持不变。
4. 新增 test-only legacy 规范化实现用于分配对照，不进入生产 API；不得把本地 benchmark 外推为生产 RPS、p95/p99、RSS、GC、HA 或容量证据。
5. 不修改、构建、测试或计分 `MSFront`。

## 6. 架构、性能、内存与并发评估

幂等中间件仍先取得 namespaced lock，再计算指纹并绑定 Storage，响应缓存与解锁顺序不变。V97-01 只在两个精确 JSON 媒体类型上绕过 MIME 解析/格式化，实测移除规范化临时分配；V96 的 `digest.Sum(result[:0])` 保持不变。Redis 网络、并发控制、超时、重试和响应体生命周期不变。benchmark 只用于本机相对分配比较，不代表生产吞吐或延迟。

## 7. 安全、可靠性、数据与消息评估

媒体类型 fast path 只返回标准库旧实现已产生的规范字符串，不引入新的信任输入或解析规则；非标准输入仍经过完整 MIME 解析。SHA-256 framing、Storage 绑定、常量时间冲突比较、ETag/replay、认证授权、审计字段、JetStream settlement、SQL outbox、OIDC/JWKS 与 Prometheus 合同不变。真实 HA、PITR、RPO/RTO、KMS/SIEM、正式身份和 exactly-once 继续 `not_recorded`。

V97-01 只有在标准/非标准字节回归、legacy 分配对照、幂等冲突/回放、定向/race、兼容、全量门禁、evidence、Graphify 与差异检查全部通过时才计分。影响归入“数据一致性与持久化”维度：从 `9.9575` 提高到 `9.9700`，6% 直接加权增量 `+0.000750`。
