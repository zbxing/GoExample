## 2. 工作包

### V126-01：固定 SHA-256 hex 校验 fast path（P1，已完成）

复评发现 `validSHA256Hex` 对固定 64 字符哈希先调用 `hex.DecodeString`，再重新编码并比较规范小写字符串。输入契约已经要求 SHA-256 的 64 个小写 hex 字符，现已改为逐字节验证，消除临时解码和编码分配而不改变 fail-closed 结果。

约束：

- 只修改 `Framework/sharedstate` 私有 helper、测试、benchmark、CHANGELOG 和 evidence 记录；不修改公开 API、Redis key/schema、Lua 脚本、payload/index/TTL 关系或错误 sentinel。
- 合法小写 hex、全大写、混合大小写、非 hex、错误长度和 Unicode 输入必须与原 decode/re-encode 语义等价。
- benchmark 输入在循环外构造；五轮结果必须同时记录 `ns/op`、`B/op` 和 `allocs/op`，不把单轮抖动写成收益。
- 任何行为、race、vet、build、API/SDK、Node、evidence、Graphify、格式或 MSFront 范围门禁失败，恢复 V125 分数 `9.931026`。

验收目标：

1. 合法小写 hex、大小写、非 hex、长度和 Unicode 等价性测试全部通过，Redis 状态 fail-closed 行为不变。
2. `BenchmarkValidSHA256Hex` 五轮由 `133.1–136.8 ns/op、160 B/op、3 allocs/op` 改善为 `30.21–31.83 ns/op、0 B/op、0 allocs/op`。
3. `go test ./queueclient/natsjetstream`、`go test -race ./queueclient/natsjetstream`、Framework vet/build、Graphify、evidence manifest/verifier 和 MSFront 范围门禁通过。
