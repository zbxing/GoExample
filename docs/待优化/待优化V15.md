本轮重新评估确认，当前最低分主要来自协议与网络能力 9.1、韧性/故障恢复 9.3、数据一致性与持久化 9.6、标准生态与可替换性 9.81，以及依赖目标环境的身份与发布闭环。多数扣分需要外部系统。仓库内最明确且低风险的新增热点位于 `Framework/httpclient.tracingTransport`：每个 outbound 请求先通过 `http.Request.Clone` 深复制 URL、Header、Trailer、TransferEncoding、Form 等结构，随后又再次克隆 Header；传播逻辑实际上只需要替换 context 并隔离待注入的 Header。

## 6. 本轮已实施优化

### V15-01：消除 outbound tracing 的重复请求深复制

`Framework/httpclient.tracingTransport` 现在通过 `Request.WithContext` 创建独立请求值，只对传播器会修改的 Header 执行一次深复制。URL、Trailer、TransferEncoding、Form 和 PostForm 继续按 `RoundTripper` 的只读请求契约共享，Body 的读取与关闭所有权不变；空 Header 仍会初始化为可写 map。新增行为测试锁定请求值/context 替换、Header 隔离以及调用方 URL、Trailer、TransferEncoding、Form 和 PostForm 不变。既有测试继续覆盖远端 W3C parent、低敏 span 属性、503 分类、响应体关闭时结束 span、总超时和调用方取消；`go test`、`go test -race` 和 `go vet` 均通过。

### V15-02：固定同二进制旧/新请求复制基准

永久 `BenchmarkCloneRequestForPropagation` 在同一测试二进制内比较优化路径与原 `Request.Clone` 后再次克隆 Header 的实现。Windows/amd64、Intel i5-10400、Go 1.27.1、`-benchmem -benchtime=2s -count=5` 结果如下：

| 路径 | ns/op 五轮区间 | B/op | allocs/op |
| --- | ---: | ---: | ---: |
| `optimized` | 313.1–317.7 | 752 | 4 |
| `legacy-deep-clone` | 1,356–1,367 | 2,592 | 18 |

优化路径每个 outbound 请求稳定减少 14 次分配和 1,840 B，延迟区间也不重叠。该结果只证明本机请求复制 helper 的成本变化，不等价于远端 Linux、真实网络、目标依赖吞吐、生产容量或长稳证据；V15-06 至 V15-14 继续保持 `not_recorded`。运行时性能与容量工程由 9.98 保守调至 9.99，未舍入综合评分由 9.8309 升至 9.8316，三位展示值由 9.831 升至 9.832，综合等级仍为 A−；`MSFront` 未修改。

### V15-03：可选流式响应体资源边界

新增 `httpclient.LimitResponseBody` 和稳定哨兵 `ErrResponseBodyTooLarge`。该 API 不改变 `httpclient.New` 的默认流式下载行为，只在调用方对单个响应显式启用正数字节上限后生效：已知超限 `Content-Length` 在读取前关闭；未知长度和 chunked 响应继续逐流读取，到达上限后仅探测一个额外字节以区分精确 EOF 与超限。超限后关闭而不无界排空不受信响应，因此该连接可能不复用；完整读到 EOF 并关闭时仍保持标准 keep-alive 复用。

真实 HTTP 测试覆盖已知长度零读取预拒绝、chunked 越界只返回上限内字节、服务端提前截断保留 `io.ErrUnexpectedEOF`、调用方提前关闭使服务端 context 收敛、调用方取消保留 `context.Canceled`，以及两次完整响应复用同一远端连接。与 `httpclient.New` 组合时，超限还会以固定 `response_body_too_large` 标记并结束 CLIENT span，不记录 URL 或响应内容。包测试、race 和 vet 均通过。

该能力是仓库内标准 `net/http` 资源契约，不证明目标 payload、远端网络、edge、生产容量或长稳，也不为默认客户端伪造全局 body 上限。标准生态与可替换性由 9.81 保守调至 9.82，未舍入综合评分由 9.8316 升至 9.8321；三位展示值仍为 9.832，综合等级仍为 A−。V15-06 至 V15-14 继续 `not_recorded`，`MSFront` 未修改。

### V15-04：显式安全方法有限重试

`httpclient.Config.Retry` 新增默认关闭的 `RetryConfig`。只有调用方将 `MaxAttempts` 显式设置为 2–5 才启用；退避从默认 50ms 指数增长到默认 500ms，配置硬上限为 5 秒。所有 attempt 共用原始 request context、调用方 deadline 和 `http.Client.Timeout`，退避无法在 deadline 前完成时保留当前响应而不启动下一次请求，等待期间取消立即返回。服务端 `Retry-After` 不会扩张客户端的本地等待预算。

重试方法白名单固定为 GET、HEAD、OPTIONS、TRACE。带 body 的请求必须提供 `Request.GetBody`，每次 attempt 使用独立 body；POST、PUT、PATCH、DELETE 和其他自定义方法即使有幂等键也只执行一次。无响应的 transport 错误以及 408/425/429/502/503/504 可触发重试；中间响应只关闭、不为连接复用无界排空。多次 attempt 复用同一个 W3C traceparent 和逻辑 CLIENT span，调用方 Header 不被修改，span 继续只记录规范化 method、最终 status 与固定错误类别。

测试覆盖可重放 GET 两次 503 后成功且三次 body/traceparent 一致、写方法与不可重放 body 单次执行、transport 错误次数上限、中间响应零读取关闭、取消打断退避、deadline 不足时保留当前 503、重放失败固定脱敏错误、退避指数封顶、方法/状态白名单和非法配置拒绝。包级 test、race、vet 与 API compatibility 均通过。该能力只证明仓库内安全请求的有限恢复策略，不证明目标网络、远端依赖可用性、写入幂等、熔断、负载均衡或 exactly-once。韧性、故障与恢复由 9.3 保守调至 9.4，未舍入综合评分由 9.8321 升至 9.8351，三位展示值升至 9.835，综合等级仍为 A−；V15-06 至 V15-14 继续 `not_recorded`，`MSFront` 未修改。

### V15-05：标准 HTTP 应用所有权与 Fiber 兼容决策

新增 `httpapi.HTTPApplication` 与 `NewHTTPApplication`。该类型直接实现 `net/http.Handler`，并以 `Shutdown(context.Context)` 封装同一个内部 Framework app 的 pre-shutdown 生命周期；调用方不再需要接收 `*fiber.App`、手工调用 `NewHTTPHandler`，或自行保证 handler 与 shutdown hook 来自同一实例。Example 与 Billing 生产入口均已迁移为把同一 `HTTPApplication` 同时交给 `server.RunHTTP` 的 `Handler` 和 `ApplicationShutdown`，生产 composition root 继续不导入 Fiber。

ADR 0003 盘点并固定四组公开暴露面：应用构造/路由、响应/SSE、observability middleware 和原生 listener。`New`、`NewHTTPHandler`、`RouteRegistrar`、Fiber response/SSE helpers、observability middleware 与 `server.Run` 在当前兼容行全部保留；标准服务优先使用 `HTTPApplication`、typed `ApplicationQuery`/`ApplicationCommand` 和 `server.RunHTTP`。本轮拒绝把标准 handler 反向适配进 Fiber 再转回 `net/http`，因为双重适配无法诚实保证 caller context、write deadline、flush、hijack 与断连所有权。未来完全标准的自定义流注册必须以新增 transport-neutral descriptor 实现，不修改现有 SSE 签名。

测试锁定标准 handler 接口、caller context 传播、统一响应、shutdown、nil/零值失败边界；Node 静态守卫要求新实现本身不引用 `fiber.`，并要求 Example/Billing 都使用同一个标准应用对象完成 serving/shutdown 配对。旧 API 未删除或改签名。该仓库内所有权边界不证明外部消费者迁移、目标 edge、WebSocket、HTTP/3、远端性能或生产容量；标准生态与可替换性由 9.82 保守调至 9.83，未舍入综合评分由 9.8351 升至 9.8356，三位展示值升至 9.836，等级仍为 A−；`MSFront` 未修改。

V15 清单与 V15-03/V15-04/V15-05 的实现、测试及 ADR 已加入通用 evidence 输入合同及 Node 断言，合同由 250 项增至 258 项，其中 257 项必需、`go.work.sum` 仍是唯一可选输入。该同步只防止后续 manifest 漏绑当前清单和对应实现；证据完整性维度已为 10.0，因此不因合同数量变化额外加分。
