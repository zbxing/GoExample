## 3. 拆分顺序

1. 先完成 V13-01 至 V13-04 的外部信任边界：edge、Redis、身份和审计。
2. 再完成 V13-05 至 V13-07 的数据面、性能与交付实证；这些任务可以共享目标环境，但证据和完成判定必须独立。
3. 最后完成 V13-08 的真实消费者迁移和 V13-09 的综合长稳/恢复审批。

任何任务都不得仅凭配置、workflow、测试替身或本地 loopback 标记完成。无法提供某项强保证时，必须记录已批准的非目标、替代控制和残余风险，不能用文档声明代替运行证据。

## 4. 证据要求

- 每个工作包必须记录目标环境标识、不可变版本/digest、完整命令、开始/结束时间、退出状态、原始输出和制品 SHA-256。
- 远端运行必须记录可访问的 run URL、commit SHA、runner/image/toolchain 指纹和签名或平台 provenance；环境不兼容时不得执行固定性能回归阈值。
- 故障与恢复工作包必须记录注入点、观测到的失败、恢复步骤、数据一致性结果、RPO/RTO 实测值和责任人审批。
- `targetEdge`、`productionSharedStore`、`postgresRecovery`、`natsBroker`、`linuxRemoteBenchmark`、`signedRelease` 等边界只能由严格 verifier 根据完整制品更新，当前未取得的状态继续保持 `not_recorded`。
- `MSFront` 不在 V13 范围内，前端评分沿用现有基线且不因服务器侧工作上调。

The default-branch provenance workflow runs this check before attestation, while the evidence manifest archives the report alongside the release subject. The clean-source release gate now uses `git status --porcelain=v1 --untracked-files=all`, so an untracked file cannot be omitted from the source state checked by `SERVER_RELEASE_REQUIRE_CLEAN=true`. A Node static guard locks this strict mode. This remains a repository-only V13-07 sub-control and does not turn the work package into remote evidence.

Reproducibility report schema v2 now requires each witness to start with a different empty `GOCACHE` and `GOTMPDIR`, confirms that the Go build cache was populated, and records stable isolation identifiers. The verifier rejects cache-isolation metadata tampering. The module cache remains shared and the report states that this same-host result is neither independent nor remote provenance.

The root Node suite now uses `--test-concurrency=1` because its evidence and release tests launch process-heavy Git and Go verification. The 72 regular cases run first, and the repeated empty-cache server release build/tamper case then runs in a fresh Node process so prior Git/Go child-process state cannot destabilize its roughly five-minute workload. This is a test-stability change and does not add another score increment.

The server release now emits schema v1 `source-manifest.json` from the pinned Linux/amd64 `go list -deps` closure instead of a hand-maintained directory list. It records sorted repository-relative paths, byte sizes, and SHA-256 for the selected workspace/module files, release version source, build script, and Go/embed/assembly inputs.
