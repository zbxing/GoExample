## 2. 工作包

### V125-01：bounded AMR 去重（P1，已实施；完整 server test 受 Redis 环境阻断）

目标文件：`Framework/auth/jwks.go`；对应测试和 benchmark 位于 `Framework/auth/jwks_test.go`。

当前 `validIDTokenAssurance` 在 assurance 检查开启时已改为固定 16 项栈数组检测重复项，并用同一数组检查 required AMR。`actualAMR` 已受 `maxOIDCAssuranceValues = 16` 限制，优化覆盖同一精确字符串语义并消除 map bucket 分配。没有 assurance 要求时保留原有快速返回。

实施约束：

- 只改私有校验实现及其测试/benchmark/CHANGELOG/evidence 记录，不改变 `IDTokenClaims`、`JWKSConfig`、JWT 解析选项或错误 sentinel。
- `actualAMR` 为空、单项、多项、顺序变化、重复项和超过 16 项均必须与旧实现等价；required AMR 缺失、重复和大小写不同仍按原规则处理。
- `validOIDCAssuranceValue`、ACR 比较、`MaxAuthAge`、nonce、issuer/audience、签名算法和 context 完成态语义不得改变。
- benchmark 输入在循环外构造；必须同时记录 map 基线与优化路径的结果、`B/op` 和 `allocs/op`，不得只报告吞吐。

验收结果：

1. 有效 assurance、重复 AMR、缺失 required AMR、非法字符、空值、超限和无 assurance 快速路径行为测试全部通过。
2. 定向五轮 `BenchmarkValidIDTokenAssurance` 从 `1292–1321 ns/op、936 B/op、3 allocs/op` 改善为 `1036–1111 ns/op、0 B/op、0 allocs/op`。
3. `go test ./auth`、`go test -race ./auth`、Framework 模块 test/vet/build、Graphify、格式和 MSFront 范围通过；完整 `yarn test:server` 仅因本机 Redis/Sentinel 端口不可用失败，不能据此宣称生产恢复或容量结论。
4. `git diff --name-only -- MSFront` 及 staged diff 为空；不得运行或计分 `MSFront`。
