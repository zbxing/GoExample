复评发现的唯一仓库内增量是 `Framework/queueclient/natsjetstream.receiveNext` 对不可取消且无 deadline 的 context 仍创建 `context.WithTimeout`。该 context 没有可观察的取消边界，而 `jetstream.FetchMaxWait` 已提供同样的单次 pull 上限；可在保持可取消和 deadline context 语义的前提下消除 timer/context 开销。

## 3. V120-01 实施约束

- 仅当 `ctx.Done() == nil` 且 `ctx.Deadline()` 不存在时，才可直接调用 `consumer.Next(jetstream.FetchMaxWait(maximumWait))`；不得放宽 `maximumWait`。
- 可取消 context、deadline-only context、已完成 context 和 pull 内部 deadline 必须继续使用 `context.WithTimeout` + `jetstream.FetchContext`，并保留 parent/child completion precedence 与迟到结果拒绝。
- `ReceiveDelivery` 的消息 body/header clone、W3C trace/baggage 隔离、Publish、Process、lease、confirmed ack、DLQ、consumer preflight、低敏错误和公开 API 不变。
- benchmark 输入在循环外构造，保留 `FetchMaxWait` legacy 对照和 cancellable context 对照；背景 context 路径实测 `86–94 ns/op、136 B/op、3 allocs/op`，cancellable 路径 `608–648 ns/op、416 B/op、7 allocs/op`，不得声称生产吞吐或容量结果。
