## 1. 互斥判断与评分基线

V112 的仓库内确定性工作已闭合。真实 edge/DNS/证书/HTTP/2/3、正式 IdP/MFA、生产 egress 与容量、Redis/PostgreSQL/NATS HA 与恢复、KMS/SIEM、RPO/RTO、远端 provenance 和组织审批不能由本机 fixture、loopback、miniredis、模拟 broker 或文档声明替代，继续 `not_recorded`。

复评发现 `Framework/httpclient.propagationNeedsInjection` 在判定非 nil 自定义 `TextMapPropagator` 前无条件读取 `SpanContext`。自定义传播器不依赖该读取；在每个出站请求上执行它属于可本地确定的热路径冗余。V113-01 将 context lookup 限定在内置 `TraceContext` 分支，保留 typed-nil 反射 fail-closed 和所有传播语义。V112 完成基线为 `9.930800/10`，V113-01 目标为协议与网络能力 `8.6575 -> 8.6580`，综合 `9.930800 -> 9.930825/10`。

## 2. 全面复评结论

1. Workspace、Framework 分层、HTTP/Fiber 边界、认证授权、共享状态、SQL/outbox、queue/JetStream、SDK 生成链、部署模板、CI 与 evidence manifest/verifier 均有源码和回归绑定。
2. V110–V112 已覆盖标准 TraceContext 惰性复制、nil interface、所有 nil-able typed-nil propagator；本轮不重复改变 Header、context、Inject、retry 或 breaker 合同。
3. V113 唯一仓库内确定性缺口是自定义 propagator 路径上的无用 `SpanContextFromContext` 读取；它不依赖外部系统，可由 benchmark、单元回归和 race 确认。同一 Windows/amd64、默认 `GOMAXPROCS=12`、`-benchmem -count=5` 的前后对照中，自定义路径中位数由 `351.0` 降至 `333.8 ns/op`（约 `4.9%`），保持 `736 B/op、4 allocs/op`。
4. 本机 benchmark 仅代表 Windows/amd64 相对资源，不外推生产 RPS、p95/p99、CPU、RSS、GC、HTTP/2/3、HA、容量、exactly-once 或 RPO/RTO。

## 4. V113-01 实施约束与非目标

1. `propagationNeedsInjection` 先处理 nil interface，再处理标准 `TraceContext` 的有效 SpanContext；只有该标准分支读取 context。
2. 自定义传播器仍通过反射识别 typed-nil；非 nil 自定义传播器仍 clone Header 并调用 `Inject`，不改变 caller 隔离。
3. 不新增公开 API、配置、schema、operation、release tag、goroutine、锁、timer、网络往返或无界状态；不改变 W3C 字节、trace privacy、retry/circuit、TLS、response body、错误 sentinel 或 `MSFront`。
4. 性能结论只使用同一 benchmark 的相对结果；不把本机测量写成生产容量承诺。

| 外部边界 | V113-02/V113-03 保持 `not_recorded`，不以本机环境替代真实目标证据 |

## 6. 安全、可靠性、数据与消息边界

- V113 只减少自定义传播器热路径上的无用 context 读取；不改变传播内容、Header 所有权、nil fail-closed、请求 context 替换或 span privacy。
- 有效标准 TraceContext、非 nil custom、retry replay、circuit rejection、response body close、TLS/timeout、JetStream settlement、Redis Lua、SQL rollback/outbox 和 OIDC/JWKS 绑定均保持 V112 语义。
- 真实 edge、正式身份、生产依赖、HA/恢复、KMS/SIEM、容量、RPO/RTO、远端不可变制品和组织审批继续只能由外部证据关闭。
