## 2. 本轮实施项

### V4-01 Go 工具链下载完整性

- 优先级：P0
- 状态：`[x]`
- 问题：`yarn env` 从 `go.dev/dl` 下载工具链后直接解压，没有核对官方 SHA-256；网络、代理或缓存被污染时缺少失败闭环。
- 修改：
  - 从 Go 官方 JSON 下载清单读取与版本、平台、架构完全匹配的 archive checksum。
  - 在解压前流式计算 SHA-256，使用常量时间比较，不匹配则删除临时文件并中止。
  - 为 metadata 匹配、文件散列和不匹配拒绝增加 Node 测试。
  - module 下载后执行 `go mod verify`。
- 验收：`yarn test:node`、`yarn env` 通过；错误 checksum 不会进入解压阶段。
- 实际结果：`yarn test:node` 4/4 通过；`yarn env` 成功读取官方 metadata、校验归档并让 Framework/Example 的 `go mod verify` 均通过。

### V4-02 Go 构建可追溯性与本地执行稳定性

- 优先级：P1
- 状态：`[x]`
- 问题：Docker 构建注入 version/commit/buildTime，本地 `yarn build:server` 没有；Windows benchmark 还可能在系统临时目录受到安全软件锁定。
- 修改：
  - 根构建读取 workspace version、Git commit 和 UTC build time，并通过 `-ldflags` 注入。
  - Go 编排默认把 `GOTMPDIR` 放在被忽略的 `.temp/go-tmp`，仍允许显式环境变量覆盖。
  - CI 在 test 前执行 `go mod verify`。
- 验收：`yarn build:server`、test、race、vet 通过；构建产物带元数据。
- 实际结果：`yarn build:server`、`yarn test:server`、`yarn vet:server` 通过；配置 `CGO_ENABLED=1` 和 WinLibs GCC 后 `yarn race:server` 通过。默认 `.temp/go-tmp` 已解决系统临时目录被锁定问题。

### V4-03 MSFront JSON 存储完整性

- 优先级：P0
- 状态：`[x]`
- 问题：当前读取会吞掉 JSON 损坏和权限错误并返回空集合；写入直接覆盖目标文件，进程中断时可能留下半文件；ID 使用 `Math.random()`。
- 修改：
  - 只有 `ENOENT` 可以使用调用方提供的 fallback，语法、权限和 I/O 错误必须向上抛出。
  - 使用同目录临时文件、flush 后 rename 的原子替换方式，并清理失败临时文件。
  - 文件名限制在数据根目录内，拒绝路径穿越。
  - 支持 `MSFRONT_DATA_DIR`，便于只读部署与测试隔离。
  - ID 改用 `crypto.randomUUID()`。
  - 项目文件存储复用相同安全写入路径。
- 验收：缺失 fallback、损坏拒绝、原子写回、路径穿越拒绝和唯一 ID 测试通过。
- 实际结果：MSFront Vitest 覆盖 JSON 存储和项目 repository；全套 MSFront 测试 7 个文件、25 个用例通过。

### V4-04 密码哈希升级与兼容迁移

- 优先级：P0
- 状态：`[x]`
- 问题：当前同步 scrypt 使用 Node 默认成本，低于 OWASP 当前建议；同步计算阻塞事件循环；已有 seed 哈希没有版本和参数。
- 修改：
  - 改为异步 scrypt，使用 OWASP 建议的 `N=2^17, r=8, p=1`，并设置明确内存上限。
  - 新格式记录算法版本和参数，解析时限制参数上界，避免恶意哈希触发资源耗尽。
  - 保持旧 `salt:hash` 验证兼容；旧哈希成功登录后自动升级。
  - 使用 `timingSafeEqual`，并补充成功、失败、旧格式兼容和升级判定测试。
- 验收：旧演示账号仍能登录，新建/更新密码使用版本化格式，测试期间主线程不执行同步 KDF。
- 实际结果：密码单测覆盖新格式、旧格式兼容、失败和自动升级；7 个 MSFront 测试文件共 25 个用例通过。

### V4-05 Cookie API 同源保护

- 优先级：P0
- 状态：`[x]`
- 问题：Route Handler 依赖 SameSite=Lax，但没有像 Next.js Server Actions 那样比较 Origin；同站子域、代理配置错误和非浏览器 Cookie 请求仍缺少明确策略。
- 修改：
  - 所有使用 Cookie 身份的非安全方法校验 `Origin`。
  - 默认接受与请求 URL 同源；反向代理额外来源通过 `MSFRONT_TRUSTED_ORIGINS` 明确配置。
  - 缺失、`null`、格式错误或不受信任来源返回 403；GET/HEAD/OPTIONS 不受影响。
  - 登录 Route Handler 同样执行同源校验，避免登录 CSRF。
- 验收：同源允许、跨源/缺失拒绝、配置来源允许及原有 401/403/RBAC 测试通过。
- 实际结果：Origin/登录 Route Handler 测试通过；全套 37 个受保护 Route Handler 授权契约通过。

### V4-06 服务探针出站边界

- 优先级：P0
- 状态：`[x]`
- 问题：管理员可配置 `probeBaseUrl`，服务端会直接 fetch；生产环境没有 allowlist，形成 SSRF/内部网络探测风险。
- 修改：
  - 所有 probe URL 必须是无凭据的 HTTP(S) URL。
  - 生产环境只允许主 Fiber API origin 和 `MSFRONT_PROBE_ALLOWED_ORIGINS` 中的来源。
  - 保留现有 5 秒 AbortSignal 超时与 15 秒缓存/请求合并。
  - 管理数据模块显式标记 `server-only`。
- 验收：协议、凭据、生产 allowlist、开发模式和 URL 规范化测试通过。
- 剩余边界：DNS rebinding、IP/CIDR 与网络出口必须由目标网络策略继续限制。
- 实际结果：协议、凭据、生产 allowlist、开发模式和规范化 URL 测试通过；`yarn lint:front`、`yarn typecheck:front` 和 `yarn build:front` 也通过。外部数据目录使用 Turbopack ignore 指令后，production build 不再追踪整个项目。
