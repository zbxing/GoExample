## 3. V37-01 实施设计

### 3.1 独立命令 runner

1. 新增 `scripts/lib/server-release-command.mjs`，允许测试注入 spawn，并在创建时验证默认 cwd 与执行器。
2. 所有调用必须提供安全整数 timeout，最大不超过 600,000 ms；非法 command、args 或 timeout 在 spawn 前失败。
3. 实际启动固定 `encoding: 'utf8'`、`shell: false`、`windowsHide: true`、`maxBuffer: 8 * 1024 * 1024`、`killSignal: 'SIGTERM'`。
4. 正常退出只返回 trim 后 stdout；失败诊断不使用 stdout。

### 3.2 分级时间与失败协议

- Git metadata 与 `go version`：30,000 ms。
- `go list -deps` source closure：120,000 ms。
- Linux `go build`：180,000 ms。
- reproducibility 内嵌 build/verify Node task：600,000 ms。
- `ETIMEDOUT`、`ENOBUFS`、signal、spawn error、缺失 status 与非零 status 形成固定错误类别。
- stderr 或 spawn error 摘要最多 4,096 字符，超限附固定 truncated 标记；stdout 永不进入异常。
- timeout 是同步子进程软上限，不宣称进程组强杀或整个 reproducibility 的总 deadline。

### 3.3 Source attestation、测试与 evidence

- `scripts/server-release.mjs` 不再 import/call direct `spawnSync()`，所有五类调用都通过 helper 并显式传 timeout。
- `scripts/lib/server-release-command.mjs` 加入 server `source-manifest.json` 固定输入；build 和 verify 都必须验证它。
- 既有 `__test__/node/server-release.test.mjs` 新增四项测试：成功选项；非法输入不 spawn；完整失败分类；stderr 截断且 stdout 不泄漏。
- 静态守卫锁定 helper 常量、选项、CLI 调用、source input 和测试名称。
- evidence input contract 新增 V37 文档与 helper，输入由 291 增至 293；测试文件和 CLI 已是既有输入。canonical server release 本轮新增 binary、两个 manifest、reproducibility report 与 SHA256SUMS，制品由 53 增至 58。
- Node 主阶段保持 187，release 阶段由 1 增至 5，API compatibility 预期保持 356 symbols。
