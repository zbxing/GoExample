## 2. 本轮复评发现

`Framework/auth.OIDCClient` 尚未解析 Discovery 的 `token_endpoint_auth_methods_supported`，只按 client secret 是否为空隐式选择 Basic 或无认证。字段缺失按规范默认 `client_secret_basic`，所以 public client 不能把缺失声明当作支持 `none`；confidential client 也不能忽略 provider 显式声明的不兼容方法。

此外，confidential exchange 当前把 `client_id` 同时放入 Basic 和 form，Basic credential 也未显式按 RFC 6749 Appendix B 对 client ID/secret 编码。V69 将在构造期锁定认证方式，在请求期生成唯一且合规的凭据位置，不实现自动降级或 body secret。

## 4. V69-01 实施要求

1. 公开 `OIDCProviderMetadata`、`OIDCClientConfig` 和 `ExchangeCode` API 不变；用内部 wire document 解析 `token_endpoint_auth_methods_supported`，避免 exported struct field 造成未命名 literal 源码不兼容。
2. confidential client 只支持 `client_secret_basic`；字段缺失时采用规范默认值，显式字段必须包含该方法。
3. public client 只支持 `none`；provider 必须显式声明。缺失、`null`、空数组、错误类型、过量值或不含所需方法全部在构造期 fail closed。
4. 协商结果固定在 client 内部；不回退到 `client_secret_post`、JWT、mTLS 或未知方法，不把 secret 放入 form/query。
5. Basic 用户名和密码按 RFC 6749 Appendix B 编码后进入 Authorization；Basic form 不含 `client_id`/`client_secret`。public 请求不含 Authorization，form 含 `client_id`。
6. 所有 discovery 不兼容统一返回 `ErrOIDCProviderUnavailable`，exchange 内部异常统一返回 `ErrOIDCTokenExchange`；错误和请求 body 不泄露 secret、provider body 或私有方法值。
7. 增加协商、请求形状、特殊字符编码、防降级、隐私和既有 token/callback 回归测试；browser provider fixture 必须显式声明 `none`。
8. OIDC browser evidence 升级 schema 3，运行 `./auth ./httpapi` 的 12 个固定测试，绑定 `oidc_client_test.go` checksum 以及认证方法协商/请求绑定断言。
9. 更新 README、CHANGELOG、COMPATIBILITY、威胁模型、静态守卫和 aggregate evidence 输入；API snapshot 保持 373，OpenAPI/SDK 不变。

## 5. 实施结果

- 内部 discovery wire document 已解析 `token_endpoint_auth_methods_supported`。confidential client 的缺失字段按规范默认 `client_secret_basic`，public client 只有在显式声明 `none` 时才允许；null、空、错误类型、过量和不匹配声明均 fail closed。
- Basic 请求已按 RFC 6749 Appendix B 编码 client ID/secret，凭据只进入 Authorization；confidential form 不含 `client_id`/`client_secret`，public 请求不含 Authorization 且 form 含 `client_id`。未实现方法不会回退。
- `Framework/auth` 新增正负向、编码、请求形状、隐私和防降级测试；OIDC browser evidence schema 3 固定运行 `./auth ./httpapi` 的 12 个测试并绑定 auth client test checksum。API snapshot 保持 373，OpenAPI/SDK/consumer 无差异。
- Go 1.25.13 test/race/vet/build、API/OpenAPI、SDK/consumer/release、Node、govulncheck、server release/reproducibility、OIDC/audit/authorization evidence、aggregate manifest、Graphify 和 `git diff --check` 均通过；Linux amd64 发布 SHA-256 为 `ff3cd772e735364ea4fec8b420e18c51cec9723a7878da9e2c3e56a049a09823`。

## 7. 性能与非目标

认证方法只在 discovery 构造期解析一次；exchange 只增加一个固定分支和至多 256-byte secret/有界 client ID 的表单编码。该变化不增加网络往返、JWT parse、JWKS refresh、goroutine、timer、锁、共享状态或普通请求热路径工作，不调整已为 10.00 的性能维度。

V69 不实现 `client_secret_post`、JWT client assertion、mTLS、动态注册或 provider 自动降级；不证明真实 IdP/MFA/HSM、代理日志、浏览器矩阵或生产容量；不修改、构建、运行或计分 `MSFront`。
