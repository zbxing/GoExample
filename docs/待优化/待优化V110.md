## 2. 全面复评结论

1. 架构所有权、Framework 分层、标准 HTTP 入口、SDK 生成链、OpenAPI/API snapshot、部署模板和 evidence manifest/verifier 均有源码与回归绑定。
2. HTTP client 已有有限 transport、TLS/代理/连接池、retry/circuit breaker、response header/body 上限、context 结果权威性、body exactly-once close 和低敏 span；V110 不改变这些公开或内部合同。
3. JetStream 空、单控制、单普通及多控制 header fast path，queue trace carrier，DLQ ID，幂等 fingerprint，MIME/ETag，SDK redirect/timeout/body/context，health panic，Redis 取消清理和 SQL/outbox 均已闭合，不重复实施。
4. 在 Windows/amd64、Intel i5-10400、Go 1.27.1、`GOMAXPROCS=1`、`-benchtime=1s -count=5` 下，完整隔离复制为 `577.8–634.7 ns/op、752 B/op、4 allocs/op`，legacy 深复制为 `2349–2414 ns/op、2592 B/op、18 allocs/op`；V110 完成验收的无有效 trace context 惰性路径为 `180.6–216.7 ns/op、320 B/op、1 alloc/op`，自定义 propagator 隔离路径为 `591.0–645.3 ns/op、736 B/op、4 allocs/op`。这些仅是本机相对资源证据。
5. 身份、数据一致性和消息维度剩余扣分主要来自真实 IdP/MFA、生产共享状态、broker/恢复、容量和组织证据；V110 不用本地测试替代这些边界。

## 4. V110-01 实施约束与非目标

1. 不新增公开 API、配置、schema、operation、API version 或 release tag；只新增包私有 request preparation helper 和同包回归/benchmark。
2. 仅当 propagator 是标准 `propagation.TraceContext`（值或指针形式）且 `trace.SpanContextFromContext(ctx).IsValid()` 为 false 时，跳过 Header clone 和 `Inject`；该 propagator 的 no-op 语义由 OpenTelemetry 实现保证。
3. 有效 SpanContext 必须继续 `request.WithContext` + 一次 `Header.Clone` + `Inject`，保留 W3C traceparent/tracestate 字节、caller Header 隔离和 trace state。
4. 任意自定义 `propagation.TextMapPropagator` 即使当前 context 无效，也必须继续 clone Header 并调用 `Inject`，不得根据接口类型猜测其副作用。
5. nil/空 Header、已有业务 Header、retry replay、circuit rejection、response body、TLS、timeout、错误 sentinel 和公开 API 均不改变；不新增 goroutine、锁、timer、网络往返或无界状态。
6. 不把本机 benchmark 宣称为生产 RPS、p95/p99、CPU、RSS、GC、HTTP/2/3、HA、RPO/RTO、exactly-once 或容量证据；不修改、构建、测试或计分 `MSFront`。

## 6. 安全、可靠性、数据与消息边界

- Header 只在传播器可能写入时复制；内置 TraceContext 的无效分支明确 no-op，不改变已有业务 Header 或用户提供的无效 traceparent。
- 自定义 propagator 永不共享 caller Header；这保证扩展点仍可写入而不产生调用方可见副作用。
- tracing/retry/circuit 的 context 权威性、request/response body 所有权、超时和错误 sentinel 不变；无 URL、query、header、body、凭据或后端错误进入 span/metric。
- JetStream 控制 header 过滤、多值拒绝、body clone、publish-confirmed ack、DLQ ID、lease 与 worker 顺序，SQL optimistic version/rollback/outbox、Redis Lua 和 OIDC nonce/subject 绑定均为非目标。
