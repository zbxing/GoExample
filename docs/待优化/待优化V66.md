## 2. 本轮复评发现

### 2.1 可执行缺口

`queueclient.WorkerGroup` 按单条 delivery 的 handler 结果与 retry budget 独立调用 `Ack`、`Nak` 或 `Term`。`natsjetstream.preflightConsumer` 已只允许 `AckExplicitPolicy`，但把任何非 Explicit Ack 与 nil `ConsumerInfo` 都折叠为 `ErrConsumerPreflight` 并返回零 lease。

nats.go v1.53.1 的 AckAll 会在确认某序列时隐式确认更低序列，可能破坏并发 worker 的逐消息 settlement 隔离；AckNone 无法表达 retry、terminal settlement 或 DLQ 后 source ack；FlowControl 与未来未知值不在 adapter 声明的 durable work-queue 支持面。服务端配置已经成功读取时，应返回独立稳定错误与已计算的 required lease，而不是伪装成读取失败。

### 2.2 必须共同修复的边界

- 通用与 adapter-bound preflight 均以同一次新鲜 `ConsumerInfo.Config` 为准。
- nil `ConsumerInfo` 保持零 lease 与 `ErrConsumerPreflight`；只接受 `AckExplicitPolicy`。
- AckAll、AckNone、FlowControl 与 unknown 返回固定 `ErrConsumerAckPolicy` 与正 required lease。
- ack policy 错误优先于 pause、push、priority 及其他服务端配置错误；context、参数和 Info 读取错误的既有优先级不变。
- 错误支持 `errors.Is`，不暴露 policy 数值、durable、subject、identity、stream、URL、配置值或 backend 原文。
- adapter 不自动修改或迁移 ack policy，不增加控制面写入、第二次 `Info`、公共配置、后台轮询、goroutine 或消息热路径工作。
- 单元测试锁定 policy 矩阵、required lease、单次 `Info`、错误优先级、adapter-bound 路径与隐私。
- 真实 file-backed JetStream 必须证明 AckAll consumer 被拒绝；显式删除并重建 Explicit Ack consumer 后通过并完成原 delivery 合同。
- delivery evidence 升级 schema 13；目标生产 ack 治理、broker 与容量继续 `not_recorded`。

### 2.3 性能与恢复边界

V66 在已有启动 I/O 后增加一次 O(1) 枚举比较并细分错误，不新增网络往返、分配要求、锁、goroutine、timer、buffer、retry 或稳态 telemetry。它提高启动诊断确定性并阻止不兼容 settlement 模型进入 worker，不证明吞吐、p95/p99、CPU/RSS、生产恢复时间或 exactly-once 改善。
