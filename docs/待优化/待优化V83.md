## 2. 复评发现

`httpclient.New` 组合标准 transport、safe-method retry、client-wide circuit breaker 和低敏 tracing，但结果与 body 所有权尚未在所有层统一：

1. transport 可在 caller cancellation/deadline 后迟到返回 response/nil，外层仍把它交给调用方并暂记为成功。
2. circuit/retry 只检查 `ctx.Err()`，遗漏 deadline 已到但 timer/Done 尚未调度的窄窗，过预算结果可参与 jitter 或 breaker probe/failure 记账。
3. circuit-open 或预取消由某层本地短路时，该 RoundTripper 没有统一承担 request body close；迟到或 response+error 的 response body 也可能失去所有权。
4. live context 下的 nil response/nil error 只结束 span，仍返回 nil/nil，未由 Framework 自身提供固定失败合同。
5. 该缺口位于所有出站 HTTP/OIDC/JWKS 调用的共享协议边界，可用私有 helper 与确定性 transport doubles 完整验证，不依赖真实网络或设备。

## 4. 实施约束与非目标

1. 不新增公开 API、配置、环境变量、schema、网络往返、goroutine、timer、锁或正常路径堆分配。
2. 显式 transport/backend error 保持权威；context 只覆盖 nil success。
3. 每层只关闭自己在本地短路或结果拒绝时取得所有权的 body，close error 不覆盖主要错误，禁止 double close。
4. 不改变 retry method/status/attempt/backoff/`Retry-After`、circuit threshold/state、TLS、proxy、pool、redirect 和 response limit 语义。
5. telemetry 只使用现有固定 method/status/error type，不记录 URL、query、header、body、credential、address 或错误原文。
6. 不声称 cancellation 撤销已发送请求，不声称 httptest 等于目标 edge/生产网络，不修改或运行 `MSFront`。

## 5. 所需证据与完成标准

| 类别 | 所需证据 |
| --- | --- |
| helper | live/canceled/elapsed-deadline timer gap；正常路径 `0 allocs/op` |
