## 4. V112-01 实施约束与非目标

1. `propagationNeedsInjection` 先处理 nil interface，再对动态值做 nil-able kind 检查；typed-nil 标准和自定义 propagator 均返回 false，避免调用 nil receiver。
2. nil 分支仍通过 `Request.WithContext` 传递 client span context，但共享原 Header；该分支不执行 Header clone 或 `Inject`，与标准 propagator 的明确 no-op 语义一致。
3. 值形标准 `TraceContext` 在有效 SpanContext 时继续 clone + Inject；所有非 nil 自定义 propagator 无论 context 是否有效都继续完整隔离。
4. OIDC 与 audit-chain evidence 固定 `go test -p=1`，只降低本机并行构建压力；不改变测试矩阵、运行时生产代码或外部边界。
5. 不新增公开 API、配置、schema、operation、release tag、goroutine、锁、timer、网络往返或无界状态；不改动 retry/circuit、TLS、response body、错误 sentinel、trace privacy 或 MSFront。

## 5. 验收矩阵

| 类别 | 必须满足 |
| --- | --- |
| nil interface | `prepareRequestForPropagation` 返回 `inject=false`；RoundTrip 不 panic、不调用 Inject，request context 仍替换 |
| typed-nil 标准 | `(*propagation.TraceContext)(nil)` 与 nil interface 同样 fail-closed；caller Header 内容不变 |
| typed-nil 自定义 | 任意 nil-able 自定义 propagator 不进入 Inject；caller Header 与 request value 不被传播路径改变 |
| 有效标准 trace | W3C `traceparent`/`tracestate` 与 V111 行为一致，caller Header 隔离 |
| 非 nil 自定义 propagator | 自定义 `Inject` 可写入 clone，caller Header 不变；`Fields`/`Extract` 语义不受影响 |
| 组合层 | retry、circuit breaker、response-body limit、context deadline/cancel、错误分类和 span 生命周期回归通过 |
| 性能 | nil 分支复用标准 no-op 惰性路径，仅有受控 nil 判定，不增加同步原语或网络成本；`-p=1` 只影响 evidence 构建并发；本机 benchmark 仅作相对证据 |
| 门禁与范围 | Framework test/race、server test/vet、API/project/SDK、Node guards、evidence manifest/verify、Graphify、`git diff --check` 通过；MSFront staged/unstaged 差异为空 |
| 外部边界 | V112-02/V112-03 保持 `not_recorded`，不以本机环境替代真实目标证据 |

## 6. 安全、可靠性、数据与消息边界

- typed-nil propagator 被视为内部错误配置的 no-op，避免协议传播扩展点触发 panic；不把 nil 作为可写 carrier，也不让 caller Header 产生副作用。
- 有效标准 TraceContext 与所有非 nil 自定义 propagator 的隔离、W3C 字节、trace state、retry replay 和 circuit rejection 语义不变。
- request/response body 所有权、context 权威性、TLS/代理预算、JetStream 控制 header 过滤、多值拒绝、DLQ/ack、SQL rollback/outbox、Redis Lua 和 OIDC/JWKS 绑定不变。
- 真实 edge、正式身份、生产依赖、HA/恢复、KMS/SIEM、容量、RPO/RTO、远端不可变制品和组织审批仍只能由外部证据关闭。
