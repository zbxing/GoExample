本轮覆盖复核 HTTP client/server 生命周期、HTTP API、认证、共享状态、SQL/outbox、queue/JetStream、SDK 生成链、部署模板、CI、evidence verifier 与 Graphify。复评发现 `Framework/sqlclient.startSpan` 的固定 operation（`CHECK`、`EXEC`、`QUERY`、`LOCK`、`UPDATE`、`OUTBOX`、`TRANSACTION`）每次都调用 `strings.ToLower`，在 SQL span 热路径产生临时字符串。该缺口不依赖真实数据库或硬件，可由 helper benchmark、分配回归、SQL 全量测试和 race 确定性验证，因此生成 V114 并实施 V114-01。

## 3. V114-01 实施内容与约束

`startSpan` 现在通过 `postgresOperationName` 将固定大写 operation 映射到不可变小写常量；未知值使用仅处理 ASCII 的小写回退。没有新增公开 API、配置、schema、锁、goroutine、timer、网络往返或状态；`semconv.DBOperationName` 继续接收原始 operation，span 名称仍为 `postgresql.<lowercase-operation>`。

保留的行为边界：SQL timeout/cancel、迟到 driver nil、显式 driver error、rows 关闭、transaction rollback/retry、versioned update、outbox exactly-one-row、panic recovery、低敏 span 属性和错误 sentinel 均不变。不得用跳过 SQL 校验、减少 rollback 或隐藏 driver 错误换取性能分数。

## 4. 复评性能证据

同一 Windows/amd64、Intel i5-10400、Go 1.27.1、默认 `GOMAXPROCS=12`、`-benchmem -count=5`：

| helper | ns/op | B/op | allocs/op |
| --- | ---: | ---: | ---: |
| legacy `strings.ToLower("QUERY")` | 31.0–31.8 | 8 | 1 |
| V114 `postgresOperationName("QUERY")` | 2.37–2.41 | 0 | 0 |

该微基准只覆盖 span 名称准备步骤；不外推 PostgreSQL 网络延迟、driver 行为、锁等待、连接池、吞吐、p95/p99、HA、RPO/RTO 或生产容量。
