## 2. 复评发现

Redis 通过统一 tracing hook 覆盖 dial、单命令和 pipeline，但 hook 目前直接接受 `next` 返回的 nil error：

1. 命令或 pipeline 可在 caller cancellation 或 deadline 后迟到返回 nil，span 仍记录 `success`，上层也可继续接受 GET/SET/DEL/EVAL/SCAN/PING 等结果。
2. Dial 可在预算已完成后返回非 nil connection/nil error，该连接仍可进入 Redis pool，所有权与预算不一致。
3. 只检查 `ctx.Err()` 会留下单调 deadline 已到但 timer/Done 尚未调度的窄窗，必须同时比较 `Deadline()` 与 `time.Now()`。
4. Queue V80 和 SQL V81 已实施同类结果权威性，Redis 统一 hook 是当前最小、最广泛且可确定性验证的仓库内缺口。

## 4. V82-01 实施约束

1. helper 先读取 `ctx.Err()`，再用单调 `Deadline()`/`time.Now()` 关闭 timer 调度窄窗；正常 context 返回 nil。
2. 只有底层 `next` 返回 nil error 时才用 context error 覆盖 success；显式 backend error 保持不变。
3. Dial 超时拒绝时必须关闭已返回 connection，返回 nil conn/context error；close error 不覆盖 context error。
4. 命令/pipeline 迟到 nil 必须让现有 span 以 canceled/timeout 结束，不新增 label、原始错误或业务数据。
5. 不新增公开 API、网络往返、goroutine、timer、锁或堆分配；不改变 Redis 配置与数据模型。
