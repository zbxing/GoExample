## 3. V27-01 实施设计

### 3.1 共享短探测边界

- `runBoundedCommand()` 接受可选 `env`，仅在调用方提供时加入 spawn options；同一次调用的所有 Windows direct candidate 与 shell fallback 必须复用同一环境对象。
- `readBoundedGoVersion()` 和 `readBoundedGitCommit()` 接受并转交可选 `env`，不放宽格式校验。
- 默认 30 秒、最大 30 秒、64 MiB、`SIGTERM`、`shell: false`、`windowsHide: true`、Windows 候选顺序和 fail-closed token 策略保持不变。

### 3.2 精确迁移范围

- `scripts/environment.mjs`：Go version probe；依赖树检查和安装/下载任务不迁移。
- `scripts/go-project.mjs`：12 位 Git build commit 与 GCC `--version` probe；Go task runner 不迁移。
- `scripts/sdk-release.mjs`：prepare 的 source commit；生成 SDK check 不迁移。
- `scripts/server-recovery-drill.mjs`：summary 的 Git commit 与 Go version；60 秒 scenario 不迁移。
- `scripts/lib/transport-benchmark-environment.mjs`：`go env GOVERSION`，必须透传 benchmark environment。
- `scripts/v13-evidence.mjs`：skeleton Git commit；验证和文件处理不受影响。

### 3.3 防回归与证据

- fake spawn 行为测试锁定 env 对象身份、所有有界选项、reader 透传和默认不显式覆盖环境。
- 静态门禁证明 7 个目标文件使用 shared boundary，目标 probe 不再直接调用 `spawnSync()`；保留的 direct 调用必须对应任务型工作。
- 将 V27 文档加入 evidence input contract，输入目标由 278 增至 279。
- helper 被七个领域报告 source inventory 哈希；修改后重建并独立验证 audit chain、authorization、OIDC browser、SDK release、SDK consumer、SDK matrix 与 server recovery 证据。制品 schema 和集合保持不变。
