# GoExample 待优化清单（V96）

生成日期：2026-09-14

## 1. 版本边界与互斥判定

V95-01 已完成，V95-02/V95-03 仍只依赖真实 edge、DNS、证书、HTTP/2/3、正式 IdP/MFA、生产 Redis/PostgreSQL/NATS、KMS/SIEM、跨主机恢复、目标容量、远端制品和组织审批。全面复评发现 `idempotencyRequestFingerprint` 的 `digest.Sum(nil)` 仍创建摘要临时切片，因此本轮执行分支 B：覆盖架构与性能评估、生成 V96，并立即实施 V96-01。

评分沿用 20 个非前端维度，权重直接合计 100%，综合分为 `sum(维度分 x 权重)`。V95 基线为 `9.924925/10`；V96-01 完成为 `9.925675/10`。

## 2. 全面复评发现

1. 幂等指纹已复用一个 `[8]byte` 长度 framing 缓冲，但 `digest.Sum(nil)` 会额外分配 32 字节切片并复制到返回数组。
2. 指纹输入仍必须严格保持 method、原始 URL、最小 principal、规范化媒体类型、可选 fingerprint headers 与 body 的长度前缀和 SHA-256 顺序。
3. 该路径由带幂等 key 的变更请求重复触发，属于仓库内可确定复现的请求一致性热路径，不依赖真实 Redis 或硬件。
4. V96-02/V96-03 仍是不可替代外部事项，不能由本地 fixture、loopback、miniredis 或文档声明关闭。

## 4. V96-01 实施约束与非目标

1. 不新增公开 API、配置、schema、operation、API version 或 release tag；只改变摘要结果的中间写入方式。
2. 保留长度前缀、字段顺序、SHA-256 算法、principal/media-type 规范化、If-Match 绑定和 body 读取语义。
3. 返回值仍为 `[sha256.Size]byte`，只用 `digest.Sum(result[:0])` 填充，不改变任何摘要字节。
4. 不改变 Storage/Locker I/O、常量时间冲突比较、响应缓存、replay header、ETag、认证授权顺序、超时或并发边界。
5. 不把本地 benchmark 宣称为生产吞吐、p95/p99、RSS、GC、HA 或容量证据；不修改、构建、测试或计分 `MSFront`。

## 6. 架构、性能、内存与并发评估

幂等中间件仍先取得 namespaced lock，再计算指纹并绑定 Storage，响应缓存与解锁顺序不变。V96 仅消除 `digest.Sum(nil)` 的临时切片；优化路径五轮均为 `352 B/op、14 allocs/op`，legacy 为 `384 B/op、15 allocs/op`。本机 ns/op 存在调度波动，不作延迟结论；真实 Redis 网络、并发容量、长稳和跨实例恢复仍属外部证据。

## 7. 安全、可靠性、数据与消息评估

指纹仍使用 SHA-256 长度 framing，不引入新密钥、外部状态或可预测字段；Storage 绑定继续用常量时间比较，冲突返回固定错误。If-Match/ETag、响应 replay、审计字段、Prometheus labels 与 queue/JetStream 语义不变。真实 HA、PITR、RPO/RTO、KMS/SIEM、正式身份与 exactly-once 继续 `not_recorded`。
