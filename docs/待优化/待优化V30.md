## 3. V30-01 实施设计

### 3.1 项目级单调总预算

- 新建项目契约 Git runner，默认复用 `maximumCommandDurationMs = 30_000` 和 `runBoundedCommand()`。
- runner 创建时读取一次单调时钟并建立 deadline；每次 Git 调用前计算并钳制正整数剩余毫秒。
- `resolveProjectDocument()` 的 ref、cache、probe、fetch、verify、show 共享 runner；`validateProjectContracts()` 的全部选中项目共享 runner。
- 预算耗尽返回 `null` 且不再 spawn；非法 timeout 或非有限时钟 fail closed。
- 所有调用固定 `raw: true`，确保空 stdout 成功与失败可区分，且 OpenAPI 文档内容不被 trim。

### 3.2 安全与兼容边界

- remote repository 拒绝控制字符；HTTPS URL 拒绝 userinfo、query 和 fragment，错误不复述原值。
- Git 非零退出、timeout、signal、buffer 超限和启动失败不回显原始 stdout/stderr。
- `GIT_TERMINAL_PROMPT=0` 与 `GCM_INTERACTIVE=Never` 使 CI/脚本失败路径不等待交互式凭据输入，同时保留现有进程环境。
- workspace、local path、SSH URL、exact ref、pinned commit、cache key、materialized path 和来源格式保持兼容。
- OpenAPI CLI 删除直接 `spawnSync` 并共享项目 runner；缺失旧 manifest 的 optional 探测仍可返回 `null`。

### 3.3 防回归与证据

- 确定性 fake clock 锁定多条 Git 调用的递减 timeout，并证明预算耗尽后后续调用不会发生。
- 测试覆盖 `cwd`、`raw`、非交互 env、最大预算、非法 timeout/clock、空 stdout、通用失败和 HTTPS/control-character 拒绝。
- 静态守卫保证 `scripts/openapi-compat.mjs` 不再导入或调用 `spawnSync`，且使用共享 Git runner。
- V30 文档加入 evidence input contract，输入由 281 增至 282。
- `project-contracts.mjs` 被 SDK release 与 SDK consumer matrix 的 source inventory 哈希；input contract 又被全部七组领域 evidence 哈希，因此七组均已重建并独立验证。
