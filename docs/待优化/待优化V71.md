## 2. 复评发现

Redis 浏览器 session 清单当前先清理 subject ZSET，再 `ZRANGE` token hash，最后逐条 `GET` payload。该路径有 `2+N` 次 Redis 命令，并在 `ZRANGE` 与逐条读取期间暴露并发撤销/过期窗口；接口要求的是有界、低敏、稳定 inventory，但实现不是单次线性一致快照。该缺口可以在仓库内由有界 Lua 脚本闭环，不依赖真实硬件或生产 Redis。

不纳入本版本：真实 Redis HA/TLS/ACL/容量、生产 outbox/broker settlement、PITR/RPO/RTO、正式 IdP/MFA/KMS/SIEM、远端 provenance、目标 edge/Kubernetes、组织演练和 `MSFront`。

## 4. V71-01 实施约束

1. Redis Lua 脚本必须在一次执行中完成 ZSET 过期清理、最多 `limit` 个 token 选择和 payload 读取；脚本结果有界，不能按无上限库存返回。
2. Go 端继续限制 payload 大小，并校验 JSON、subject hash、session ID、创建/到期时间、claims、device name；任何错误都 fail closed，不泄露 Redis 原文。
3. 不改变 `BrowserSessionStore`、`BrowserSessionInventoryStore`、HTTP、OpenAPI、SDK 或配置 API；不新增后台 goroutine、锁或跨请求缓存。
4. 继续只持久化 hash-only session/CSRF 和公开随机 SessionID；日志、span、错误和测试输出不得出现 raw credential 或 subject 明文。
5. 本地/`miniredis` 结果只证明仓库行为和命令边界，不证明生产 Redis 延迟、吞吐、HA、容量或跨主机恢复。
