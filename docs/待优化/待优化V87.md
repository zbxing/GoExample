## 2. 复评发现

1. `scripts/go-sdk.mjs` 生成的 `NewClient` 当前直接使用 `http.DefaultClient`，而标准 client 默认自动跟随 3xx，最多尝试 10 次 redirect。
2. Example OpenAPI 将 `startOIDCBrowserAuthorization` 的 `302`、`Location` 和 `Set-Cookie` 定义为正式业务响应；默认 SDK 会在 `Client.do` 取得 response 前跟随到 IdP，调用方无法观察原始 302 和绑定 cookie。
3. redirect target 可以离开构造时验证的 base URL，并产生额外 DNS/连接/TLS/请求；301/302/303 对写操作还可能改写 method。标准库对部分敏感头有保护，但这不等于 SDK 已建立零额外目标请求边界。
4. V86 的 context、异常 response 和 body 所有权检查都发生在 `HTTPClient.Do` 返回后，无法恢复已经被默认 client 消费的中间 redirect response。
5. `http.ErrUseLastResponse` 是标准库为 `CheckRedirect` 提供的明确停止信号，会把首个 3xx 与未关闭 body作为 nil-error response交还调用方，正好可以进入 SDK 现有有界读取和关闭流程。
6. `WithHTTPClient` 是显式注入边界，V87 不应包装或改变它；修复仅限 SDK 自有默认 client。
7. 该缺口可由两个本地 server确定性证明：源 server返回 302，目标 server计数；修复前目标被访问，修复后目标零调用且原 status/header/body保留。

## 4. V87-01 实施约束与非目标

1. 规范源为 `scripts/go-sdk.mjs`；Example/Billing 的 `client.gen.go` 必须由生成命令产生，不手工漂移。
2. 默认 client和 redirect callback保持包私有；不新增公开 API、option、配置、环境变量、schema、operation、API version或 release tag。
3. `CheckRedirect` 对第一个 redirect 统一返回 `http.ErrUseLastResponse`，不按 host、scheme、status 或 method 放行，避免策略分支形成绕过。
4. 原始 response继续受 `DefaultMaxResponseBytes`/`WithMaxResponseBytes`、V86 context复核与 body exactly-once close约束。
5. `WithHTTPClient` 完全覆盖默认 client；调用方显式 client 的 redirect/timeout/proxy/jar 行为不被包装。
6. 原 302 的 status、`Location`、`Set-Cookie` 和 body必须保留，redirect target必须零调用；正常 2xx 和 typed operation保持。
7. 不新增 retry、goroutine、timer、锁、body copy、header clone或正常路径网络往返；默认 client只初始化一次并并发复用。
8. 不把本地 redirect测试宣称为真实 IdP、edge、HTTP/2/3、生产 egress或容量证据，不修改、构建、测试或计分 `MSFront`。

## 6. 性能与资源边界

V87 非 redirect 热路径只把共享默认 client从标准全局值换为包私有全局值，不增加 per-request heap、retry、网络往返、goroutine、timer或锁。3xx 路径停止后续 redirect，减少无计划外部 I/O；不据此虚构生产吞吐或延迟提升。

本地双 `httptest` 只能证明 wire response透明性、目标调用次数和资源关闭，不能证明真实 DNS/TLS/proxy/HTTP/2/3、跨区网络、生产 IdP、CPU、RSS、连接池或容量。
