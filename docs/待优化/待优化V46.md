## 2. 全面复评发现

### 2.1 架构与边界

- `go.work`、Framework、Solutions/Services、SDK、consumer、证据工具和受控 manifest 已形成分层边界；Go 工具链选择、`GOROOT` 隔离、子进程预算和证据 verifier 均有共享约束。
- 标准 `net/http` handler、HTTP/TLS 生命周期、认证授权、SQL/queue/Redis 合同、SDK 生成与恢复证据已有行为测试和失败关闭语义。
- `MSFront` 目录、依赖树检查、前端 E2E 和前端生命周期明确排除，不在 V46 改动或评分。

### 2.2 环境引导网络缺口

`scripts/environment.mjs` 的 `installGo()` 需要访问 Go 官方元数据接口并下载归档。V45 已约束后续 Yarn/Go/tar 子进程，但两个 `fetch` 没有 `AbortSignal` 或请求级 timeout；连接建立、首字节等待或响应体读取无响应时，初始化可能无限等待。

V46-01 只为这两个请求设置固定网络预算，使用 `AbortController` 在预算耗尽时取消，并把 abort/网络失败归一化为低敏错误。保留 URL、HTTP 状态检查、响应体流、`.part` 文件清理、SHA-256 校验和解压命令不变；不改 `yarnTreeIsCurrent(frontRoot)`。

### 2.3 性能、资源与生命周期

- Framework 热路径和传输基准不需要修改；固定 Linux、真实 payload、生产依赖和长稳容量仍需外部证据。
- V45 的子进程边界已收敛，V46 只补齐网络请求生命周期，避免在工具链下载阶段占用无限连接/任务。
- 预算只定义最坏等待上限，不宣称 Go 下载速度、外部网络可用性、生产容量或远端服务 SLO。
