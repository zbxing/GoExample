## 2. 复评发现

Redis refresh session 的 user-wide revoke 与 active-family count 均以一次 Lua 处理 per-user zset，但脚本在没有绝对基数上限的情况下执行 `ZRANGE 0 -1`，直接把未验证 family ID 拼接为 key，也不核对 family hash 的 `user_hash` 与 active global-index membership。

两个脚本当前还会边遍历边修改。后续成员包含非法时间字段或污染映射时，先前 family 可能已经被撤销或从索引删除；Redis 脚本运行时错误不会回滚这些写入。该缺口位于 `Framework/sharedstate`，无需真实硬件、生产 Redis 或外部批准即可关闭。

## 4. V75-01 实施约束

1. 在 `ZRANGE` 和任何 cleanup/revoke 前校验 now/user hash/maximum，并通过 `ZCARD` 拒绝超过 10,000 的 per-user family 索引。
2. family ID 在派生 Redis key 前必须通过 32 字符小写 hex 校验；`CreateSession` 必须在执行 Redis 命令前维护相同不变量。
3. existing family 必须核对 `user_hash`；active family 必须在 global family zset 中存在，且索引 score 与 absolute expiry 一致。
4. 第一段仅校验并缓存 exists/absolute/expires/revoked 等状态；第二段才清理 missing/expired family、设置 revoked 或计数，任何预检失败都不得留下写入。
5. 保持每条路径单次 Lua、O(N) 且 `N <= 10000`；不新增 goroutine、锁、后台状态、公开 API、配置键或 schema。
6. 本地测试只证明 adapter 的有界性、索引完整性和失败原子性，不证明生产 Redis latency、throughput、HA、TLS/ACL、capacity、eviction 或 recovery。
