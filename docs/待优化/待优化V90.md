## 2. 复评发现

1. 两套生成 Go SDK 的默认 `http.Client` 已有 30 秒总预算和首个 3xx 保留，但 `Transport` 为 nil，实际继承进程级 `http.DefaultTransport`。
2. 进程级 transport 允许任意初始化代码替换全局 transport；SDK 因而无法证明自己的代理、HTTP/2、连接池、dial、TLS 握手、响应头和空闲连接预算，多个 SDK 客户端也可能与不相关组件共享并争用全局连接池。
3. 该缺口完全位于仓库内，可由同包测试确定性证明，不依赖真实 DNS、证书、硬件或生产网络；它直接影响“协议与网络能力”的可替换性、资源上界和失败隔离。
4. V85 JetStream context/settlement、V86 SDK context/body、V87 redirect、V88 SDK 总超时和 V89 health panic/evidence contract 已完成，本轮不重复实现或计分。
5. 当前设备没有 Docker/Podman/nerdctl，WSL 没有 Linux 发行版；真实 edge/DNS/证书/HTTP/2/3、正式 IdP/MFA、生产 Redis/PostgreSQL/NATS、恢复、容量、远端 provenance 与组织审批仍不可替代。

## 4. V90-01 实施约束与非目标

1. 不新增公开 API、option、环境变量、schema、operation、API version 或 release tag；只改变包私有默认 client 的 transport。
2. 默认 transport 使用 `http.ProxyFromEnvironment`、`net.Dialer`、`ForceAttemptHTTP2` 和有限连接池；不读取、不记录 URL、header、cookie、body、凭据或后端原文。
3. `http.Client.Timeout` 继续为 30 秒；caller 更短 context、redirect、V86 body ownership 和 V89 结果权威性不变。
4. `WithHTTPClient` 仍直接保存调用方实现，不包装、不修改其 timeout、transport、proxy、jar 或 redirect 行为。
5. 包私有 transport 可被 SDK 客户端并发复用；不新增每请求 goroutine、retry、timer、锁、网络往返或无界状态。
6. 本地 `httptest` 和配置断言只证明代码合同，不替代真实 HTTP/2/3 协商、DNS、证书链、代理、吞吐、p95/p99 或容量证据；不修改、构建、测试或计分 `MSFront`。

## 6. 性能、内存与并发评估

默认路径只从进程级共享 transport 改为 SDK 包私有共享 transport；每个请求仍使用标准库连接复用，不增加 body copy、header clone、retry 或应用 goroutine。每主机连接上限变为可审计边界，避免被全局 transport 替换或不相关组件争用；idle 与 response-header 预算限制空闲连接和首部等待占用。连接池上限不是目标吞吐证明，真实 p95/p99、CPU、RSS、TLS/DNS 成本和 HTTP/2 多路复用仍需 V90-02 的目标环境证据。

## 7. 安全、可靠性与可观测性评估

- SDK 默认路径不再依赖可被任意包替换的 `http.DefaultTransport`，降低跨组件配置污染和资源互相影响。
- 代理、TLS 最低行为、redirect wire response、caller context 和错误优先级保持不变；不泄露敏感诊断。
- Framework/httpclient、SQL、Redis、JetStream 与 health 的既有边界不因本轮改变；V90 只修改生成 SDK 模板及其回归测试。
- 真实证书、IdP、KMS、SIEM、生产共享状态、消息恢复、容量、远端制品和组织审批仍保持 `not_recorded`。
