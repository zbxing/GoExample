## 3. V35-01 实施设计

### 3.1 Formatter 执行协议

1. 在既有 `scripts/lib/sdk-generation.mjs` 新增 `formatGoFileWithCandidatesSync()`，接收 staged client、候选列表、仓库 cwd，并允许测试注入 spawn 与存在性检查。
2. 每次实际启动固定 `encoding: 'utf8'`、`shell: false`、`windowsHide: true`、`timeout: 30_000`、`maxBuffer: 64 * 1024 * 1024`、`killSignal: 'SIGTERM'`。
3. 30 秒和 64 MiB 直接复用 `bounded-command.mjs` 导出常量，不在 SDK 层复制魔数。
4. 绝对路径不存在时跳过；只有 `status === null` 且错误码为 `ENOENT`/`EINVAL` 的启动失败允许下一个候选。
5. timeout、signal、`ENOBUFS`、`EACCES`、spawn 抛错和非零退出立即失败，不再继续 PATH fallback。

### 3.2 错误、资源与兼容边界

- 优先报告 timeout、输出溢出、signal、退出码或启动错误分类；stderr/错误消息裁剪为固定最大字符数，不拼接 stdout。
- 全部候选缺失时保留 `gofmt was not found; run yarn env or set GOFMT_BINARY` 的既有指引。
- `go-sdk.mjs` 保留 `GOFMT_BINARY -> versioned repository toolchain -> generic repository toolchain -> PATH` 顺序，只调用 helper 并通过既有 `fail()` 输出错误。
- V34 的唯一 staging、cleanup、client/VERSION 原子发布和普通同步回滚不变；formatter 仍只操作 staged client。
- 不把单次 formatter timeout 宣称为 SDK check/release/evidence 全流程总预算，也不宣称 `SIGTERM` 能强制清理所有后代进程或不可中断 I/O。

### 3.3 测试与证据

- 新增 4 项 helper 行为测试：成功调用携带完整进程上限；`ENOENT`/`EINVAL` 才 fallback；timeout/signal/overflow/权限/非零退出不 fallback；大 stderr 生成有界错误。
- 静态守卫锁定 helper import/call、共享常量、fallback 白名单、诊断上限，并禁止 `go-sdk.mjs` 直接导入或调用 `spawnSync()`。
- `docs/待优化/待优化V35.md` 加入 evidence input contract，输入由 289 增至 290；既有 helper 与测试已在输入中，制品保持 53。
- Node 主阶段目标由 179 增至 183；release 阶段保持 1，API compatibility 预期保持 356 symbols。
