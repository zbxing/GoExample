## 2. 本轮复评发现

### 2.1 可执行缺口

锁定的 `nats.go v1.53.1` 将 `ConsumerConfig.HeadersOnly=true` 定义为 consumer 只接收 headers、不接收 payload。当前 `PreflightConsumer` 会接受该配置；`fromJetStreamMessage` 随后只能看到空正文，并会把它作为合法 `queueclient.Message.Body` 交给业务。原消息确实为空与 broker 系统性省略正文无法在运行时区分，handler 可能确认错误输入，构成静默业务数据丢失。

### 2.2 必须共同修复的边界

- 使用既有新鲜 `ConsumerInfo`，要求 `HeadersOnly == false`，不得从单条消息正文长度推断配置。
- 失败返回固定 `ErrConsumerPayloadUnavailable`，支持 `errors.Is`，不暴露 identity、subject、配置值或 backend error。
- 继续保持 V56 持久性、redelivery、AckWait/BackOff、context 和 required lease 语义，不增加第二次 Info。
- 单元 fake 与真实 file-backed JetStream 共同验证从拒绝到 full payload 通过。
- delivery evidence 升级 schema 5；目标生产 broker 和容量继续 `not_recorded`。

### 2.3 一致性边界

本轮只阻止 broker 被配置为系统性省略 payload，不禁止合法空业务消息，也不证明 filter subject、deliver policy、retention、replicas、有限 MaxDeliver 耗尽策略、跨 broker 原子 settlement、ordering、全局去重或 exactly-once。
