## 2. 复评发现

Redis refresh-session 的 rotation 与 family revoke 已各自收敛为单次 Lua，但仍把合法形状的 token-to-family mapping 当作授权事实，未完整校验 family hash 的 owner、current token、两个状态位、时间关系、global/per-user zset score 以及 used-token 反向 mapping。

因此，污染 mapping 可以把伪造 token 指向真实 family：rotation 会把它解释为 reuse 并撤销该 family，revoke 会直接撤销。malformed family 状态也可能在返回 expired/reuse/limit 前被写成 revoked/expired。Go adapter 同时缺少 nil context、相同 old/new hash 和 1,024 history 绝对上限的命令前拒绝。以上均位于 `Framework/sharedstate`，不需要真实硬件、生产 Redis 或外部批准即可关闭。

## 4. V76-01 实施约束

1. `user_hash`、`current` 和每个 used token 必须为 64 字符小写 hex；family ID 必须为 32 字符小写 hex，未验证值不得用于派生 key。
2. `absolute`、`expires` 必须为正整数毫秒并满足 `expires <= absolute`；`revoked`、`expired` 只能为 `0/1`，且 `expired=1` 必须同时 `revoked=1`。
3. absolute 未到期的 family 必须同时存在于 global 与 owner 的 per-user zset，两个 score 都必须等于 absolute expiry。
4. 传入 token mapping 必须对应 family 的 current token 或 used-token set 成员；current 和全部 used token 的反向 mapping 必须指回同一 family。
5. `RotateSession` 在 Redis I/O 前拒绝 nil context、相同 old/new hash、`historyLimit <= 0` 和 `historyLimit > 1024`；`RevokeFamily` 在 Redis I/O 前拒绝 nil context。
6. 两个 Lua 脚本必须先只读验证，之后才允许成功 rotation、合法 reuse/limit/expiry 标记或 revoke；异常状态只返回既有固定 sentinel，不得部分修改。
7. 正常路径继续为一个 `redis.evalsha`；used-token 验证为 O(H)，且在 `SMEMBERS` 前强制 `H <= 1024`。不新增 goroutine、锁、后台状态、公开 API、配置键或 Redis schema。
8. 本地测试只证明 adapter 的一致性、有界性和命令边界，不证明生产 Redis latency、throughput、HA、TLS/ACL、capacity、eviction 或 recovery。
