## 3. V32-01 实施设计

### 3.1 原子物化协议

- `scripts/lib/project-contracts.mjs` 导入现有 `writeFileAtomicallySync()`，删除对物化目标的直接 `writeFileSync`。
- 保留“目标不存在或内容不同才写”的短路；内容相同不创建临时文件、不执行 `fsync`。
- 写入时使用目标同目录随机临时路径与 `wx` 独占创建，固定执行 `write -> fsync(file) -> close -> rename`；rename 前旧缓存保持完整。
- 不改变 `.temp/contracts/<project>/<commit>/<document>`、bare Git cache、固定 commit 验证、30 秒总预算、64 MiB 单命令输出上限、OpenAPI 内容或 `content/source/path/commit` 返回契约。

### 3.2 失败、并发与平台边界

- 写入、同步、关闭或 rename 失败时抛回主错误；helper 尽力关闭 descriptor、删除临时文件，不先截断或删除旧缓存。
- 并发物化同一固定 commit 时，各写者使用独立随机临时文件；最终目标只能由一次 rename 切换到完整且相同的 commit 内容。
- 当前 Windows 真实文件系统必须证明既有目标可被完整替换；测试同时检查目标目录没有 `.tmp` 残留。
- file `fsync` 不等于父目录项持久化；系统崩溃、突然断电、网络卷和所有文件系统语义均不列为已证明能力。

### 3.3 防回归与证据

- 扩展现有外部 Git contract 测试：初次物化后人为写入旧缓存，注入发布失败并证明旧值保持，再使用真实 helper 修复为完整 Git 内容。
- 断言成功和失败路径均不残留与目标对应的临时文件；静态守卫断言项目契约模块调用 helper 且不再使用 `writeFileSync(target, ...)`。
- 保留 V26 至 V31 历史文档断言，增加 V32 修复前/完成目标、V32-01 和九个 `not_recorded` 工作包断言。
- V32 文档加入 evidence input contract，输入由 284 增至 285；共享 input contract 变化后重建并独立验证七组领域 evidence。

## 6. 修复前证据

```text
external project contract materialization (before V32)
  git show <fixed-commit>:<document> -> complete result in memory
  writeFileSync(target, result, 'utf8')
  existing target: truncated before the new payload is complete
  concurrent/subsequent reader: may observe empty, partial, or complete bytes
  failed/interrupted writer: may destroy the last complete materialized cache

required after V32
  temporary path: same directory + unpredictable + exclusive create
  publish order: write -> fsync(file) -> close -> atomic rename
  reader visibility: complete old cache OR complete new cache
  pre-rename failure: old target preserved; temporary file cleaned best effort
```

一次远端文档解析仍为 `O(Git output + document bytes)`；内容相同时继续零写入。V32 的额外成本是变更物化时一个 document-sized 临时文件、一次 file `fsync` 和一次同目录 rename，不增加服务请求分配、延迟、RPS 或容量结论。
