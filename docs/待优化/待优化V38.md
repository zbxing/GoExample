## 3. V38-01 实施设计

### 3.1 Helper 合约

- 新增 `scripts/lib/go-project-command.mjs`，导出可注入 runner、20 分钟最大总预算、`SIGTERM` 与 4,096 字符诊断常量。
- 一次任务读取单调时钟形成 deadline；每个顺序命令只使用 `ceil(deadline - now)`，耗尽时不 spawn。
- runner 校验 task/executable/commands/cwd/args/environment/timeout；错误不拼接参数、stdout 或 stderr。
- finite command 固定 `stdio: 'inherit'`、`shell: false`、`windowsHide: true`、remaining timeout 和 `SIGTERM`。
- spawn、timeout、signal、缺失 status 与非零退出只结算一次，首次失败后不启动后续命令。

### 3.2 任务预算与兼容边界

- `api-compat`、`api-snapshot`：5 分钟。
- `vet`、`build`：10 分钟。
- `test`、`cover`、`bench`：15 分钟。
- `bench-transports`、`soak-transports`、`race`、`vuln`：20 分钟总预算。
- `run`：显式 `null`，不传 timeout/`killSignal`，保持开发服务器长期运行语义。
- 多命令 `vuln` 与 `bench-transports` 共享一次总预算，不按项目或 profile 重新计时。

### 3.3 测试、证据与计分

- 新增专用行为测试：剩余预算、runtime 例外、非法输入、预算耗尽、timeout kill、spawn/signal/status/exit 分类和失败停止。
- `script-guards` 固定 helper import、预算映射、`run: null`、无 CLI direct `spawn()` 与 evidence 输入。
- evidence input contract 新增 V38 文档、helper 与专用测试，输入从 293 增至 296；制品目标保持 58。
- 本轮只提高控制面生命周期、CI runner 回收确定性与开发失败体验，不改 Go 服务热路径，不记运行时性能分。
