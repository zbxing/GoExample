## 2. 全面复评发现

### 2.1 架构、性能与边界

- Framework、Solutions/Services、SDK、consumer、OpenAPI、部署、恢复和 evidence 工具保持明确分层；V48 不改变 Go 运行时热路径、公开 API 或业务协议。

### 2.2 基线/provenance 双文件一致性缺口

V47 后，`prepare` 对候选完全校验成功后依次原子发布 `baseline.json` 与 `baseline-source.json`。若第一项提交后第二项发生同步 I/O 或 rename 失败，新基线会与旧 provenance 并存；当前共享 helper 只保证单文件完整，没有多输出同步失败恢复合同。

`trusted-baseline` job 上传这两个文件，下一 job 下载后只依据 `baseline.json` 是否存在决定是否比较，未重新校验 provenance 中的 bytes/SHA-256、schema、scope、generatedAt 和环境指纹。该缺口可能让残留、崩溃边界或 artifact 漂移形成的不一致组合进入报告器。

### 2.3 可执行优化边界

V48-01 由两层保证组成：第一层在当前进程的同步失败中快照并恢复已提交输出；第二层在跨 job 使用前重新验证状态和内容绑定。第一层不是崩溃/断电/跨文件系统事务，第二层负责让未恢复的不一致状态失败关闭。
