## 2. 复评发现

1. Framework 的 OIDC discovery/token exchange 与 JWKS refresh 在未注入 `HTTPClient` 时都创建 `http.Client{}`，其 nil `Transport` 会隐式继承可被任意初始化代码替换的进程级 `http.DefaultTransport`。
2. 认证出站路径因此无法静态证明代理、HTTP/2、dial/TLS、连接池、响应头等待和空闲连接预算；OIDC 与 JWKS 还可能与无关组件争用同一全局连接池。
3. 该缺口完全位于仓库内，可由同包测试确定性证明，不依赖真实 IdP、DNS、证书、硬件或生产网络；它直接影响身份认证治理中的资源隔离、失败边界和可审计性。
4. V85 JetStream context/settlement、V86 SDK context/body、V87 redirect、V88 SDK 总超时、V89 health panic/evidence contract、V90 SDK 默认 transport 已完成，本轮不重复实现或计分。
5. 当前设备没有 Docker/Podman/nerdctl，WSL 没有 Linux 发行版；真实 edge/DNS/证书/HTTP/2/3、正式 IdP/MFA、生产 Redis/PostgreSQL/NATS、恢复、容量、远端 provenance 与组织审批仍不可替代。

## 4. V91-01 实施约束与非目标

1. 不新增公开 API、option、环境变量、schema、operation、API version 或 release tag；仅改变 OIDC/JWKS 默认 client 的包私有 transport。
2. 默认 transport 使用 `http.ProxyFromEnvironment`、有界 `net.Dialer`、`ForceAttemptHTTP2`、TLS 1.2 最低版本和有限连接池；不读取、不记录 URL、header、cookie、body、凭据或后端原文。
3. OIDC/JWKS 各自的 HTTP timeout、禁止重定向、响应体上限、caller context、缓存发布和错误优先级保持不变。
4. 显式 `HTTPClient` 仍由调用方完全接管，不包装、不修改其 timeout、transport、proxy、jar 或 redirect 行为。
5. 包私有 transport 可被认证客户端并发复用；不新增每请求 goroutine、retry、timer、锁、网络往返或无界状态。
6. 本地 `httptest` 和配置断言只证明代码合同，不替代真实 IdP、DNS、证书链、代理、HTTP/2/3 协商、吞吐、p95/p99 或容量证据；不修改、构建、测试或计分 `MSFront`。

## 6. 性能、内存与并发评估

认证请求从进程级共享 transport 改为 Framework/auth 包私有共享 transport，仍由标准库复用连接；不增加 body copy、header clone、retry、应用 goroutine 或每请求锁。显式 connect、TLS、连接池、idle、response-header 和 header-size 预算让认证出站资源具备静态上界，降低全局 transport 污染与无关组件争用。

50/50/10 的连接池上限是本地资源合同，不是生产吞吐证明。真实 IdP 的 p95/p99、CPU、RSS、DNS/TLS 成本、HTTP/2 多路复用、密钥轮换和目标容量仍需 V91-02 的指定环境证据。

## 7. 安全、可靠性与可观测性评估

- OIDC/JWKS 默认路径不再依赖可被任意包替换的 `http.DefaultTransport`，降低跨组件配置污染和资源互相影响。
- TLS 最低版本、代理、redirect wire response、caller context、响应体上限和错误脱敏保持不变；不泄露敏感诊断。
- Session、authorization request、Redis 原子脚本、SQL、JetStream、health、审计链和 Prometheus 规则沿用已验证合同；V91 只改变认证默认 transport。
- 正式 IdP/MFA、KMS/SIEM、生产共享状态、消息恢复、容量、远端制品和组织审批仍保持 `not_recorded`。
