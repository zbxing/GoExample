## 3. V26-01 实施设计

### 3.1 Windows fallback 的 fail-closed 字符契约

- 在 `scripts/lib/bounded-command.mjs` 增加私有构造器，只在命令与每个参数都是非空、无空白且仅含保守字符集合时生成 fallback 字符串。
- 明确拒绝空参数、空白、双引号、`%`、`!`、`&`、`|`、`<`、`>`、`^`、`(`、`)`；不依赖难以跨 batch/runtime 统一证明的临时转义算法。
- 拒绝只作用于 `cmd.exe` fallback。原名、`.cmd`、`.exe` 三个 `shell: false` 候选仍接收原始 argv，已存在的真实可执行文件行为不变。
- 安全 fallback 增加 `/v:off`，关闭 delayed environment expansion；候选顺序、`ENOENT`/`EINVAL` 分类、30 秒、64 MiB、`SIGTERM` 和 `string | null` 契约不变。

### 3.2 防回归与证据

- fake spawn 正向测试锁定 `tool -> tool.cmd -> tool.exe -> cmd.exe` 顺序、安全参数字符串、`/v:off` 和所有执行上限。
- 反向矩阵逐一证明危险命令或参数在三个直接候选失败后不会启动 command shell，并返回 `null`。
- 将 V26 文档加入 evidence input contract，输入目标由 277 增至 278。
- `bounded-command.mjs` 已被七个领域报告 source inventory 哈希；修改后重建并独立验证 audit chain、authorization、OIDC browser、SDK release、SDK consumer、SDK matrix 与 server recovery 证据。制品 schema 和集合保持不变。

## 6. 修复前证据

```text
unsafe fallback construction:
  [command, ...args].join(' ')

reproduction:
  command = tool
  args    = ["value & echo REINTERPRETED"]
  shell   = cmd.exe /d /s /c "tool value & echo REINTERPRETED"

required invariant:
  unsafe token -> direct shell:false candidates only -> null
  safe token   -> existing cmd.exe compatibility fallback
```
