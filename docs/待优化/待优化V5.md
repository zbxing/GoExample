评估日期：2026-08-17

## 1. 本轮完成项

### V5-01 Route Handler 运行时输入契约

- 优先级：P0
- 状态：`[x]`
- 修改：
  - 引入 Zod 4.4.3，为登录、系统用户/角色/菜单/API/Casbin、项目和访问管理写接口定义严格 schema。
  - 20 处 `request.json()` + TypeScript cast 全部改为 `readJsonBody(request, schema)`。
  - 流式读取请求体，默认上限 1 MiB；在超过上限时取消读取，不依赖可信 `Content-Length`。
  - 接受 `application/json` 和 `application/*+json`，分别返回稳定错误码 `UNSUPPORTED_MEDIA_TYPE`、`PAYLOAD_TOO_LARGE`、`INVALID_JSON`、`INVALID_REQUEST_BODY`。
  - validation issues 最多返回 10 条，只包含字段路径和安全错误文本。
- 验收：裸 `request.json()` 数量为 0；单测覆盖 415、413、400、422 与成功路径；类型检查通过。

### V5-02 API 内部错误脱敏

- 优先级：P0
- 状态：`[x]`
- 修改：
  - 系统 API 使用 `jsonApiError`，管理 API 使用 `apiErrorResponse`。
  - 只公开请求体校验错误；未知 repository、数据库、文件系统和实现异常只在服务端记录，客户端收到稳定 fallback 文本。
  - 系统 envelope 与管理 API 均保留稳定的请求错误 code。
- 验收：单测证明未知 `Error.message` 不会进入响应，服务端仍记录原始错误。

### V5-03 路由失败、加载与 404 状态

- 优先级：P1
- 状态：`[x]`
- 修改：增加根 `error.tsx`、`loading.tsx` 和 `not-found.tsx`，提供可恢复重试、无障碍 live region、减少动态效果偏好和返回控制台入口。
- 验收：Next production build 识别自定义 `/_not-found`，lint、typecheck 和 build 通过。

### V5-04 MSFront 响应安全头

- 优先级：P1
- 状态：`[x]`
- 修改：统一增加有限 CSP、防嵌入、MIME 嗅探、Referrer Policy、Permissions Policy、COOP/CORP 和 HSTS，并关闭 `X-Powered-By`。
- 边界：当前 CSP 只约束 `base-uri`、`form-action`、`frame-ancestors` 和 `object-src`；完整 script/style nonce 策略需结合真实部署和第三方资源验证。
- 验收：lint、typecheck 和 production build 通过；运行时 smoke 验证响应头。

### V5-05 测试契约防回退
