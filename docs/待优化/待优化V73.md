## 2. 复评发现

Redis browser-session 的 token revoke 与 subject-bound public-ID revoke 都先执行一次映射 `GET`，再执行 Lua compare-and-delete。虽然原脚本可避免误删，但仍有额外网络往返、连接池占用和读取到删除之间的命令窗口。该缺口位于 `Framework/sharedstate`，不需要真实硬件、目标 Redis 或外部批准即可关闭。

设备名更新仍需 Go 严格解码完整 payload 并以 CAS 保留 TTL；V73 不以减少命令数为由削弱 claims、CSRF、subject、session ID、时间和 payload 上限校验。

## 4. V73-01 实施约束

1. 不新增 goroutine、锁、后台状态、公开 API、HTTP/OpenAPI/SDK operation、配置键或持久化 schema。
2. token、owner 和 session ID 必须在用于派生 Redis key 前通过 64 字符小写 SHA-256 hex 校验。
3. token revoke 必须核对 `metadata token -> owner:sessionID` 与 `id sessionID -> owner:token`；ID revoke 必须核对相反方向，任一不一致均不得删除。
4. 成功路径一次性删除 payload、ID mapping、metadata mapping、global zset 和 subject zset 成员；payload 不存在仍按既有语义清理索引并返回 `ErrBrowserSessionInvalid`。
5. 原始 token、CSRF、subject 明文、payload、Redis key/value 与 backend 错误不得进入公开错误、日志或 span。
6. 本地 miniredis/telemetry 只证明 adapter 命令边界，不证明生产 Redis latency、throughput、HA、TLS/ACL、capacity、eviction 或 recovery。

## 6. 本轮已实施优化

V73-01 已完成。`deleteBrowserSessionScript` 与 `deleteBrowserSessionByIDScript` 现在自行读取映射、校验 SHA-256 hex/subject ownership/双向索引，然后原子删除 payload、映射与索引；Go 端不再先执行独立 `GET`。新增：

- `TestRedisBrowserSessionRevocationsUseOneAtomicScriptCommand`
- `TestRedisBrowserSessionRevocationsFailClosedForMalformedMappings`
- `TestRedisBrowserSessionRevocationsFailClosedForInconsistentMappings`

预热后的两个成功路径均只产生一个 `redis.evalsha` span；malformed 或双向索引不一致均不会误删有效 session。设备名 CAS 路径没有纳入 V73，也不是 V73 未完成项。

本轮 `yarn vuln:server` 已执行，但受沙箱网络策略限制，无法访问 `https://vuln.go.dev/index/modules.json.gz`，因此没有取得 V73 的新漏洞扫描结论，也不记为通过。V72 留存的零可达漏洞结果仅是历史证据，不替代本轮扫描。
