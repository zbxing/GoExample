## 3. V29-01 实施设计

### 3.1 单一总截止时间

- 使用 Node `performance.now()` 单调时钟，在 `runBoundedCommand()` 开始时只建立一次 `deadline = now + timeoutMs`。
- 每次 direct candidate 与 guarded shell spawn 前计算 `ceil(deadline - now)`；结果小于等于零时直接返回 `null`。
- 剩余预算不得超过原始 `timeoutMs`，防止注入测试时钟回拨扩大单次上限。
- timeout、signal、普通非零退出继续立即失败；只有 `ENOENT`/`EINVAL` launch failure 可在剩余预算内进入下一候选。

### 3.2 防回归与证据

- fake clock 锁定四阶段预算递减，并证明预算耗尽后 shell 或下一 direct candidate 不会启动。
- V26 token policy、`/v:off`、V27 env 对象身份、V28 explicit/native/batch/unknown/absolute 命令计划不得回归。
- 30 秒最大配置、64 MiB 输出、`SIGTERM`、`shell:false` 和上层 `string | null` 契约保持不变。
- V29 文档加入 evidence input contract，输入目标由 280 增至 281。
- helper 被七个领域 source inventory 哈希；修改后重建并独立验证 audit chain、authorization、OIDC browser、SDK release、SDK consumer、SDK matrix 与 server recovery 证据。
