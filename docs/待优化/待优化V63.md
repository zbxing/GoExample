## 2. 本轮复评发现

### 2.1 可执行缺口

nats.go v1.53.1 的新鲜 `ConsumerInfo` 返回服务端权威的 `Paused` 与 `PauseRemaining`。当前 `PreflightConsumer` 已读取同一个 Info，却只验证静态配置和 lease；活动暂停的 consumer 仍可通过启动门禁。Worker 随后进入有界 pull 循环但没有业务交付，启动方无法用固定错误区分“当前被暂停”与正常空队列。

### 2.2 必须共同修复的边界

- 通用与 adapter-bound preflight 均以同一次新鲜 `ConsumerInfo.Paused` 为准；不得用本地时钟猜测 `Config.PauseUntil`。
- `Paused=true` 返回固定 `ErrConsumerPaused` 与正 required lease，支持 `errors.Is`，不暴露 identity、stream、subject、URL、pause deadline、remaining duration 或 backend 原文。
- `Paused=false` 继续既有持久性、DeliverAll、ReplayInstant、MaxDeliver、payload、subject、request expiration 与 AckWait/BackOff 校验。
- adapter 不调用 `PauseConsumer`/`ResumeConsumer`，不增加第二次 `Info`、控制面写入、公共配置、后台轮询或消息热路径工作。
- 单元测试锁定 paused/unpaused、required lease、单次 Info、错误优先级与隐私。
- 真实 file-backed JetStream 必须证明活动暂停被拒绝，显式恢复后同一 consumer 通过并完成原 delivery 合同。
- delivery evidence 升级 schema 10；目标生产 pause 治理、broker 与容量继续 `not_recorded`。

### 2.3 性能与恢复边界

V63 把服务端已经明确的不可交付状态提前为启动失败，避免把活动暂停表现为长期空等待。合法 consumer 只增加启动期一次 O(1) 布尔分支；不新增网络往返、分配要求、锁、goroutine、timer、buffer、retry 或稳态 telemetry，不能据此宣称合法路径吞吐、p95/p99、CPU/RSS 或生产恢复时间改善。
