## 2. 本轮复评发现

### 2.1 可执行缺口

`PreflightConsumer` 已使用服务端新鲜 `ConsumerInfo` 验证 explicit ack 和 lease，但没有验证 consumer 的持久性与最低自动重投。ephemeral、memory-backed、配置 inactivity deletion 或 `MaxDeliver=1` 的 consumer 都可通过；前几类会削弱停机/重启状态连续性，最后一类在首次未确认后没有任何 broker redelivery 机会。

### 2.2 必须共同修复的边界

- consumer 必须有明确 durable identity、非 memory state，且不配置自动 inactive cleanup。
- `MaxDeliver=-1` 代表无限重投；有限值必须至少为 2，保证最低一次未确认后的自动 redelivery。
- 持久性和 redelivery 错误使用不同固定 sentinel，可 `errors.Is`，但不泄露 identity、配置值或 backend error。
- existing Info、AckPolicy、AckWait/BackOff、context 和 lease budget 语义保持，不增加第二次 Info。
- 真实 JetStream 与 unit fake 共同验证；目标生产策略继续 `not_recorded`。

### 2.3 一致性边界

持久 consumer 与至少一次 redelivery 只构成仓库最低可靠投递线。有限 `MaxDeliver` 仍可能最终耗尽；stream retention、consumer limits 继承、磁盘/副本、业务幂等、DLQ/source 原子性、ordering 与 exactly-once 均不由本轮证明。
