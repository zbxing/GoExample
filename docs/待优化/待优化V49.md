## 2. 全面复评发现

### 2.1 已有能力与边界

- 非 MSFront 的 Framework、Solutions/Services、SDK、consumer、OpenAPI、部署、恢复和 evidence 工具保持明确分层。
- transport 基准已有固定 Linux runner、GOMAXPROCS、环境指纹、九组 capacity、三组 scenario、五轮采样、soak 和跨运行阈值。
- 真实硬件、真实 payload、生产依赖、目标 edge、正式身份和远端制品仍须外部不可变证据。

### 2.2 五轮离散度缺口

`transport-benchmark-report.mjs` 对每个矩阵单元只要求五轮齐全，然后直接取中位数。当前不记录 min/max，也不拒绝同组极端快慢样本。中位数能够抵抗单个异常值，但可能隐藏两个异常轮次，进而影响容量膝点、方向比率和跨运行阈值的可信度。

独立 soak 与环境指纹不能关闭该缺口：soak 使用不同 workload，环境指纹只约束运行环境身份，二者都不验证每个 capacity/scenario 单元的五轮离散度。

### 2.3 可执行优化边界

V49-01 只增强测量证据质量，不修改 Go 服务热路径、benchmark 请求数、workload、跨运行回归阈值或生产结论。固定 `2.0` 的 `max/min` 上限只拒绝超过两倍的极端轮次差异，不声称统计显著性；真实分布后续可用远端历史数据复评。
