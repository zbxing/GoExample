## 3. V21-01 实施设计

### 3.1 共享环境约束

- 新 helper 接收环境和覆盖项，返回新对象；不得修改 `process.env` 或调用方对象。
- 合并后按键名大小写不敏感删除所有 `GOROOT`，不写入仓库路径或机器路径作为替代。
- 发布、workflow lint 和 Prometheus rule runner 使用同一 helper；后两者的 `go version` 探测与 `go build` 都使用清理环境。
- 保留 `GO_BINARY`、固定 Go 版本校验、各自 cache/temp、`GOWORK=off`、发布 `GOTOOLCHAIN=local`、Linux/amd64、CGO、固定模块和 evidence 合约。
- 不修改 `environment.mjs`、`go-project.mjs` 等普通开发入口的用户可配置语义。

### 3.2 回归与端到端验证

- 单元测试注入 `GOROOT`、`GoRoOt` 及覆盖项，验证全部删除、普通键保留且输入不变。
- 脚本守卫断言三个严格入口导入并调用共享 helper，防止回退为直接复制 `process.env`。
- 使用当前真实 `GOROOT=E:\DevTools\GO` 环境重跑 `yarn workflow:lint` 与 `yarn prometheus:rules`，并独立 verify 生成证据。
- 完整 Node 测试、evidence manifest/verify、`git diff --check` 与图谱更新全部通过后才能计分。
