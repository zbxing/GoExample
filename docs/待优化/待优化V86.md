## 2. 复评发现

1. V83 只保护 `Framework/httpclient` transport 链；两套生成 Go SDK 公开允许注入任意 `HTTPClient`，不能依赖其遵守 request context。
2. 当前生成器只拒绝 nil context。pre-completed caller 仍会执行 body encode、request editor 和 `Do`；editor 内取消后返回 nil也会继续后续 editor/transport。
3. `Do` 忽略 context 后迟到返回 valid response/nil 时，SDK 会继续读取并返回成功；`ctx.Err()` 本身还遗漏 deadline 已到但 Done 未调度的窄窗。
4. response body `Read` 没有独立 context 参数，body 可在 caller 完成后迟到返回 valid bytes，当前实现仍接受 payload。
5. response+error 当前不关闭 response body；nil response/nil error及 nil body会 panic，缺少固定失败合同。
6. transport 前本地拒绝时 request body仍归 SDK 所有，尤其 editor 可替换 body；必须 exactly-once close。transport 后 SDK只清理取得所有权的 response body，不能 double-close request body。
7. 缺口应在 `scripts/go-sdk.mjs` 规范源修复并重新生成 Example/Billing；不需要公开 API、版本、schema、operation、goroutine、timer、锁、retry 或额外网络 I/O。

## 4. V86-01 实施约束与非目标

1. 规范源为 `scripts/go-sdk.mjs`；两套 `client.gen.go` 必须由生成命令产生，不手工漂移。
2. 不新增公开 API、配置、环境变量、schema、operation、API version、release tag、网络往返、retry、goroutine、timer、锁或共享状态。
3. 私有 helper 同时检查 `ctx.Err()` 与已到达的单调 deadline；live `context.Background()` 快路径保持 `0 allocs/op`。
4. nil context、显式 editor error、transport error、body read error与 response-too-large 保持既有优先级；context 只拒绝迟到 nil success。
5. pre-completed caller 不进入 editor/HTTP client；每个 editor 返回后、transport 返回后、body read 后和最终组装前复核 caller。
6. transport 前本地拒绝关闭当前 request body；transport 调用后不重复关闭 request body。
7. response+error、迟到 valid response、nil-body response的非 nil body均由 SDK关闭；close error不覆盖主要错误；成功路径原 body关闭一次并重置为 payload reader。
8. nil response/nil error与 nil body必须固定失败，不得 panic；固定错误不得包含 URL、query、header、body、credential 或 backend 原文。
9. 不声称取消能撤销已发请求或强杀忽略 context 的实现，不声称 fake/httptest 等于目标网络或生产容量。
10. 不修改、构建、测试或计分 `MSFront`。

## 6. 性能与资源边界

V86 正常路径仅增加 O(1) context 状态与 deadline 比较，不增加堆分配、body copy、网络往返、retry、goroutine、timer、锁或后台状态。pre-completed 路径减少无效 encode/editor/Do，迟到边界停止后续 body parse/header clone。

本地 fake、benchmark 和 `httptest` 只能证明生成客户端控制流、分配、清理与兼容，不证明生产吞吐、p95/p99、CPU、RSS、HTTP/2/3、edge、跨区网络、连接池或容量。
