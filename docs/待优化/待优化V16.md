## 1. 版本边界

V15 的 5 个仓库内工作包已全部完成。固定 Linux、真实 PostgreSQL/Redis/IdP/broker、目标 edge/集群、远端制品、长稳与审批证据仍不可在当前工作区伪造，因此原状态迁移。V16 只把能够通过仓库实现、行为测试、race、兼容门禁和证据合同验收的新增边界列为可执行项；生成本文件本身不加分。

重新评估确认，当前最低的可改善维度是“韧性、故障与恢复”9.4。`httpclient` 已有有限 retry，但连续依赖故障仍会让每个逻辑请求耗尽连接/重试预算；仓库没有 circuit breaker 状态机，也没有半开探针并发边界。该缺口可以在不依赖真实硬件的情况下由确定性 transport 测试诚实验收，因此列为首项。

## 4. V16-01 至 V16-02 设计约束

1. `CircuitBreakerConfig.FailureThreshold == 0` 必须保持现有客户端行为。
2. breaker 位于 retry 外层，只观察一次逻辑请求的最终结果；单次请求内的中间 503 不重复计数。
3. 失败只包括无 caller cancellation/deadline 的 transport error 和固定瞬态 HTTP 状态；普通 4xx/5xx、成功响应会重置连续失败。
4. open 状态返回稳定哨兵，不访问底层 transport；错误与 span 只使用固定 `circuit_open` 分类。
5. open timeout 后最多一个 half-open probe；并发旧请求的迟到结果不得关闭新一代 breaker 状态。
6. 状态必须有界且并发安全。首版为 client 级单一 failure domain，调用方应为不同依赖创建独立 client，避免维护无界 host map。
7. 配置必须有固定阈值和时间上限，非法值在 `New` 阶段失败。
8. observer 只接收 `State` 和 `Event`；状态固定为 `closed/open/half_open`，事件固定为 `opened/rejected/probe_started/probe_succeeded/probe_failed/probe_canceled`。
9. observer 同步且必须快速返回，在 breaker 状态锁外调用；panic 被隔离。breaker 禁用时配置 observer 必须在 `New` 阶段失败。

## 6. 本轮已实施优化

### V16-01：出站 HTTP 有界 circuit breaker

`httpclient.Config.CircuitBreaker` 新增默认关闭的 `CircuitBreakerConfig`。启用时失败阈值限制为 1–100，open timeout 默认 30 秒且最大 5 分钟。breaker 位于 retry 外层，只观察一次逻辑请求的最终结果：无 caller cancellation/deadline 的 transport error、nil response 及固定 408/425/429/500/502/503/504 状态计为依赖失败；其它响应会重置连续失败。open 状态直接返回稳定 `ErrCircuitOpen`，不调用底层 transport；trace 只记录固定 `circuit_open`，不含 URL、host 或 backend error。

open timeout 到期后只允许一个 half-open probe，其它并发请求继续快速失败。状态 generation 会隔离打开前已放行的迟到请求，防止旧成功结果关闭新一代 open 状态；probe 成功关闭，失败重新开始 open timeout，caller cancellation 只释放 probe 而不污染失败计数。首版有意采用 client 级单一 failure domain，避免按 host 保存无界状态；不同依赖应创建独立 client。

行为测试覆盖两次失败打开/快速失败/成功探针关闭、并发单探针、stale in-flight success 隔离、caller cancellation 与 404 不计失败、retry 中间 503 后成功不打开而最终逻辑失败只计一次、固定 trace 分类、默认值和全部非法配置。包级 test、race、vet 与 356-symbol API snapshot 均通过。该能力不证明目标网络、生产依赖可用性、跨副本共享 breaker、吞吐/延迟、负载均衡、写入幂等或 exactly-once。韧性、故障与恢复由 9.4 保守调至 9.5，未舍入综合评分由 9.8356 升至 9.8386，三位展示值由 9.836 升至 9.839，等级仍为 A−；`MSFront` 未修改。

### V16-02：circuit breaker 低基数状态观测

`CircuitBreakerConfig.Observer` 新增可选同步 `CircuitBreakerObserver`。每次回调只接收含 `State` 与 `Event` 两个字符串字段的 `CircuitBreakerObservation`；状态值固定为 `closed/open/half_open`，事件值固定为 `opened/rejected/probe_started/probe_succeeded/probe_failed/probe_canceled`。接口不接收 URL、host、request、response、错误或任意调用方标签，因此不会把动态维度扩散到 metrics。回调在 breaker mutex 外执行，panic 被恢复且不改变响应或状态机；调用方必须快速返回。breaker 禁用时配置 observer 会在 `New` 阶段失败，避免静默接受无效观测配置。

确定性测试验证完整打开、拒绝、取消探针、失败探针、重开和成功关闭序列；反射断言观测结构只有两个公开字段且每个值均属于固定集合。并发测试证明 half-open 只产生一个 `probe_started`，generation 测试证明 stale in-flight success 不产生关闭事件，panic 测试同时获取状态锁以证明回调在锁外执行并继续验证状态机。包级 test、race、vet 与 356-symbol API snapshot 均通过。该 observer 不提供异步队列、metrics backend、跨进程状态、请求级诊断或目标环境告警投递保证。韧性、故障与恢复由 9.50 保守调至 9.55，加权贡献由 0.2850 调至 0.2865；未舍入综合评分由 9.8386 升至 9.8401，三位展示值由 9.839 升至 9.840，等级仍为 A−。可观测性维度已为 10.0，不重复加分；`MSFront` 未修改。

### V16-03：transport-neutral 自定义路由与 SSE 描述符

新增 `ApplicationRoute`、`ApplicationRouteRequest`、`ApplicationRouteResponse`、`ApplicationRouteHandler`，以及 `ApplicationEventStream`、`NewEventStream`、`NewAuthenticatedEventStream`、`NewAuthorizedEventStream`。普通 handler 固定使用 `/api/v1` 下的 canonical static path，默认 GET 也可声明标准 HTTP method；handler 只接收 `context.Context` 与请求快照（多值 query、headers、body 防御性复制），响应状态、headers、body 均有界且在写出前校验。事件流 source 只接收 `context.Context` 和受限 `Last-Event-ID`，因此项目代码不需要导入 Fiber；运行时复用 `SendServerSentEventsFromSource` 的有界编码、心跳、stream timeout、caller/disconnect/shutdown 取消和错误边界。认证与 any-of 角色授权复用现有 Framework 适配器，角色目标固定为 `application_event_stream`。

启动阶段验证 canonical path、nil source、禁止 `Options.Events`、SSE heartbeat/byte/timeout 上限、大小写不敏感重复、默认路由冲突、GET/HEAD query 冲突、stream 间冲突、与 `RegisterRoutes` 混用及认证/角色配置；旧 `RouteRegistrar`、Fiber SSE helper 和 query/command API 均保持兼容。标准应用测试覆盖 caller context value/deadline、Last-Event-ID 传递、SSE wire output、认证 401、角色 403/成功及完整负向配置矩阵；Node 静态守卫和 evidence 输入同步。

启动阶段还拒绝 handler/stream 同时配置、nil handler、非法 method、非法响应状态、禁止状态体、超大响应体或 header，以及默认路由、query、command、GET/HEAD 和 stream 重叠；`ApplicationRoutes` 与 `RegisterRoutes` 互斥。普通 handler 与 SSE 的行为测试覆盖 context、请求快照、响应边界、wire output 和完整负向配置矩阵，API snapshot、compat、Node 静态守卫及 evidence 输入同步通过。该增量将“标准生态与可替换性”由 9.86 保守调至 9.88，加权贡献由 0.4930 调至 0.4940；未舍入综合评分由 9.8416 升至 9.8426，三位展示值由 9.842 升至 9.843，等级仍为 A−。它不证明 durable replay、跨副本 stream state、目标 edge buffering、HTTP/3 或真实容量。

### V16-04：出站恢复组合矩阵

`httpclient.Config` 新增默认关闭的 `MaxResponseBodyBytes`。客户端固定按 tracing → circuit breaker → retry → transport 组合；breaker 只统计 retry 完成后的逻辑请求结果，client timeout 与 caller deadline 仍由 `net/http`/请求 context 负责，响应体上限在响应返回后由 tracing/body 生命周期负责。已知超大 `Content-Length` 在 `Do` 阶段返回固定 `ErrResponseBodyTooLarge` 并关闭底层 body；未知长度在读取越界时返回同一哨兵并结束 span。响应体超限不回写 breaker 失败计数，避免把消费边界误判为依赖可用性故障。

新增组合行为测试覆盖“503 重试 → 200 超限 → 后续请求成功”、固定错误分类、响应体关闭与 span 结束，以及负值配置拒绝；既有 retry cancellation/deadline、breaker 并发 probe/stale result、response body chunked/提前关闭/取消测试继续通过。`go test`、`go test -race`、`go vet` 与 API snapshot 均通过。该能力证明仓库内组合顺序和失败所有权，不证明目标网络、真实依赖、HTTP/3、生产容量或长稳恢复。韧性、故障与恢复由 9.55 保守调至 9.60，加权贡献由 0.2865 调至 0.2880；未舍入综合评分由 9.8426 升至 9.8441，三位展示值由 9.843 升至 9.844，等级仍为 A−；`MSFront` 未修改。
