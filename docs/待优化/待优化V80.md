## 2. 复评发现

`Framework/queueclient` 已为 publish/process、ack/DLQ 和 lease extension 创建有限 context，但 callback 的返回值与 context 完成存在竞争：

1. `Client.run` 无条件进入 callback；parent 已取消时 broker/application callback 仍可能执行。callback 在 operation deadline 后返回 nil 时，Process/Publish 和 span 仍可记 success。
2. `settleDelivery` 的 result 分支只检查 parent context，不检查 settlement 子 context。ack/DLQ 在自身 deadline 后返回 nil 时，result 可与 timeout 同时 ready，并被错误接受为 acknowledged/dead-lettered。
3. `callDeliveryLeaseExtension` 具有同构竞争；迟到 nil 可被记为 lease extended，handler 继续并最终结算。

这会使超出预算的 handler 继续 ack，或把不再可信的结算/续租结果记为成功。缺口属于 queue 确认顺序和数据一致性，可在仓库内确定性修复，不依赖真实硬件或生产 broker。

## 4. V80-01 实施约束

1. 在 `Client.run` 进入 callback 前检查 operation context；已取消或 deadline 已到时直接返回 context error，callback 调用数必须为零。
2. callback 返回 nil 后必须复核 operation context；可观察取消或已到 deadline 覆盖 nil success，并让 span 使用 canceled/timeout 固定结果。
3. deadline 判断必须同时考虑 `ctx.Err()` 与 `ctx.Deadline()` 的单调时间，不能依赖 select 恰好优先选择 `Done()`。
4. ack/DLQ result 分支必须先复核 parent，再复核 settlement 子 context；子 deadline 后的 nil/非 nil 结果均不可形成 success observer，固定折叠为 `ErrDeliverySettlement`。
5. lease-extension result 分支必须先复核 delivery parent，再复核 extension 子 context；子 deadline 后结果固定折叠为 `ErrDeliveryLeaseExtension`，取消 handler、停止 extension，并禁止 ack/DLQ。
6. parent cancellation 仍按正常 worker stop 收敛；显式 callback error/panic、retry、jitter、静态/动态 lease 公式和 observer panic 隔离保持。
7. 不新增公开 API、配置、goroutine、timer、锁、共享状态、网络往返或 broker 命令。现有 async callback goroutine 无法强杀忽略 context 的调用方代码，文档必须保留此限制。
8. message、header、destination、callback 内容、deadline 数值和 backend error 不进入固定错误、span 或 observer。

## 5. 验收矩阵

| 类别 | 验收要求 |
| --- | --- |
| pre-cancel | Publish/Process 的 canceled/deadline parent 均返回原 context error且 callback 零调用 |
| late handler | handler 观察 operation deadline 后返回 nil，Process 不成功；可靠 delivery 不 ack，按既有策略 retry 并在耗尽后 DLQ |

## 6. 性能与资源边界

V80 只在既有 callback 边界增加 O(1) context 状态与 deadline 比较，不增加消息复制、网络往返、broker I/O、retry attempt、goroutine、timer、锁或后台状态。正常路径仍执行原有一次 callback；settlement/lease 仍使用现有有界 goroutine 结构。

本地测试只能证明 deadline 后不再接受成功，不能证明 callback 忽略 context 时会被强制终止，也不能证明生产延迟、吞吐、CPU、RSS、broker capacity、HA、atomic settlement 或 exactly-once。
