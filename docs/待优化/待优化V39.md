## 3. V39-01 实施设计

### 3.1 Runner 合约

- `createContractCommandRunner({ cwd, spawn, now, setTimeout, clearTimeout })` 可注入，便于在无 Docker 环境下验证生命周期。
- command、args、cwd、env、timeout 和 output limit 在 spawn 前校验；参数、密码和 stdout 不进入抛出错误。
- timer 在 spawn 前建立，覆盖慢启动；timeout 或 output overflow 请求 `SIGTERM`，并只结算一次。
- 使用 `close` 作为流和进程生命周期收口；signal、spawn failure、missing status 和非零退出具有稳定分类。
- 普通命令抛出带有界诊断的错误；`allowFailure` 返回 `{ status, signal, stdout, stderr, outputExceeded }`，供探活和归档使用。

### 3.2 Redis 合同接入

- git/go/docker 版本、镜像拉取、容器启动、redis-cli 探活、Go 集成测试、docker logs 和 cleanup 全部经过 runner。
- 默认单命令 timeout 为 60 秒；镜像拉取显式 120 秒，Go 合同显式 150 秒，日志与 cleanup 显式 30 秒。
- 输出上限为 8 MiB；超过上限立即终止并在证据中记录失败，不允许内存无界增长。
- 保留 Linux Docker 前置条件、固定 Redis image digest、容器拓扑、ACL 分离、证据 report schema 和 `target_redis_ha=not_recorded`。

### 3.3 测试与证据

- 新增 `__test__/node/contract-command.test.mjs`：安全 spawn 选项、timeout 递减、timer 覆盖慢启动、输出溢出、timeout、signal、spawn/missing-status/nonzero、诊断截断和失败停止。
- `script-guards.test.mjs` 固定 Redis 合同只导入 runner，不直接导入/调用 `spawn()`，并锁定所有关键 timeout 与 8 MiB 上限。
- 将 V39 文档、helper 和新测试加入 evidence input contract；完成态重建并独立验证六组共享 evidence、manifest、SHA-256、Node/Go/API/SDK/release 门禁。
