## 2. 优化清单

### V2-01 健康检查刷新与 goroutine 收敛

- 优先级：P1
- 状态：`[x]`
- 修改：
  - 缓存 miss 时只启动一轮后台 refresh，调用方通过 channel 等待并可响应自己的 context 取消。
  - refresh 使用 `context.WithoutCancel` 保留调用值但不被首个客户端取消，再统一派生 `HEALTH_CHECK_TIMEOUT` 总预算。
  - 每项检查只使用一层 goroutine；总预算到期后未返回检查标记 failed。
  - 忽略 context 的检查仍可能遗留一个 goroutine，这是 Go 无法强制终止函数的边界，必须在文档中保留契约。
- 验收：首个/等待调用取消不污染缓存；并发只刷新一次；timeout、revision、draining 正确；测试无死锁。

### V2-02 基础设施端点响应策略

- 优先级：P1
- 状态：`[x]`
- 修改：
  - `/livez`、`/readyz`、`/startupz`、`/api/health*`、`/metrics`、`/debug/pprof*` 设置 `Cache-Control: no-store`。
  - 把 Fiber ETag/Compress 直接限定到 `/api/v1` 业务路由，基础设施 handler 自行设置 no-store。
  - 业务 JSON 路由继续保留 ETag 和压缩。
- 验收：probe/metrics 无 ETag、无 Content-Encoding 且 no-store；hello 在合适请求下仍保留 ETag/压缩。

### V2-03 补充 Go runtime metrics

- 优先级：P1
- 状态：`[x]`
- 修改：
  - scrape 时读取 Go runtime 状态，不增加请求热路径工作。
  - 增加 goroutines、GOMAXPROCS、heap alloc/in-use/objects、GC cycles、GC pause total。
  - 使用 Prometheus base unit 与 counter/gauge 类型声明，不增加高基数标签。
- 验收：`/metrics` 含 runtime 指标及 HELP/TYPE；原 HTTP histogram 测试继续通过。

### V2-04 CORS credentials 最小权限

- 优先级：P1
- 状态：`[x]`
- 修改：
  - 新增 `CORS_ALLOW_CREDENTIALS`，默认 false。
  - 只有显式 true 时返回 credential header。
  - wildcard origin 仅在 credentials=true 时拒绝；文档说明 Bearer API 通常不需要 credentials。
- 验收：默认响应不含 `Access-Control-Allow-Credentials`；显式开启时存在；wildcard + credentials 启动失败。

### V2-05 JSON media type 契约

- 优先级：P1
- 状态：`[x]`
- 修改：
  - login、echo、validate 接口要求 `application/json` 或以 `+json` 结尾的 structured syntax suffix。
  - 缺失或错误 Content-Type 返回统一 415 envelope。
  - media type 参数通过标准库解析，不使用字符串前缀猜测。
- 验收：JSON 和 vendor JSON 正常；text/plain、缺失或非法 Content-Type 为 415；原 body limit/validation 保持。

### V2-06 可测试的进程生命周期

- 优先级：P1
- 状态：`[x]`
- 修改：
  - signal 创建留在 `main`，将可取消 context 和日志输出注入 `run`。
  - 保持依赖组装、draining、传播延迟和 shutdown 行为不变。
  - 新增真实随机端口 listen、健康请求、cancel、shutdown 测试。
- 验收：`cmd/server` 不再为 0% 覆盖率；取消后服务退出且无残留 listener。
