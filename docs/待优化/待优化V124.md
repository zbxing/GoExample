### V124-01：Metrics.Render label scratch buffer（P1，已完成并验收）

目标文件：`Framework/observability/metrics.go`，测试位于 `Framework/observability/metrics_test.go` 和 `Framework/observability/benchmark_test.go`。

当前 `Render` 对每个 snapshot 调用 `metricLabels(key) string`，临时创建 `[]byte`、status 字符串和最终 labels 字符串，再复制到已有 `strings.Builder`。现已改为复用 256-byte scratch buffer 生成 labels，并以等价的 `strconv.AppendInt` 写入状态码；每个 snapshot 只生成一次 labels，histogram 行复用同一段字节。

实施前定向基线（Windows/amd64、Intel i5-10400、Go 1.27.1，`-benchmem -benchtime=300ms -count=5`）：

| 场景 | ns/op | B/op | allocs/op |
| --- | ---: | ---: | ---: |
| `BenchmarkMetricsRender`（32 snapshot） | `102040–123232` | `243929–243932` | `10` |

已完成：

- `metrics.go` 已删除 `metricLabels(key) string`，使用可复用 scratch buffer；状态码仍为十进制等价输出。
- 已增加含 quote、反斜杠和 status 的动态 label 输出测试；定向测试通过。
- 五轮定向 benchmark 为 `102040–123232 ns/op`、`243929–243932 B/op`、`10 allocs/op`，相对实施前 `109128–125083 ns/op`、`250185 B/op`、`138 allocs/op` 改善。

- 空、单、多个 snapshot 的完整输出逐字节等价；method/route 中的 quote、反斜杠和 status 保持原有 `strconv.Quote` 语义。
- HELP/TYPE、histogram 所有 bucket、`+Inf`、sum/count、uptime 和 runtime metrics 均存在且顺序不变。
- 增加或保留行为测试，验证 snapshot 所有权、并发 Render、无效/边界 label，且 `go test -race` 通过。
- 五轮 benchmark 相对基线改善，不得增加 `B/op` 或 `allocs/op`；不能缓存完整 metrics 文本，不能删除指标。
- Framework 全量 test/race/vet/build、Node/API/SDK、evidence manifest/verifier、Graphify 和 `MSFront` 范围守卫全部通过。

最终记录：Node 215/215、server release 5/5；manifest 为 400 inputs、126 artifacts，独立 verifier 已通过；综合评分更新为 `9.931020/10`。manifest sha256 以最终 verifier 输出为准，避免把自引用摘要写入被 manifest 收录的文档。
