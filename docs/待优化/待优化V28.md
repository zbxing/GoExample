## 3. V28-01 实施设计

### 3.1 Windows command plan

- 新增私有纯函数，根据 `platform`、绝对路径和小写扩展名返回 direct candidates 与是否允许 shell fallback。
- 非 Windows 永远只尝试原命令；Windows 绝对路径和任意显式扩展永远不追加扩展名。
- Windows 相对无扩展名命令保持 `command`、`command.cmd`、`command.exe`；安全 token 失败后仍可进入 `cmd.exe`。
- `.cmd`/`.bat` 大小写不敏感，direct failure 后允许 guarded shell；`.exe`/`.com`/其他扩展失败后直接返回 `null`。

### 3.2 防回归与证据

- fake spawn 锁定 `go.exe` 只调用一次，即使 `go.exe.cmd` 可返回看似合法的 Go identity 也不得触达。
- 正向矩阵覆盖 `.cmd`、`.CMD`、`.bat`、绝对 batch 和无扩展名；反向矩阵覆盖 `.exe`、`.com`、`.ps1`、复合扩展和危险 token。
- V26 的保守 token policy、`/v:off`，V27 的 env 对象身份，以及 30 秒/64 MiB/`SIGTERM` 契约不得回归。
- V28 文档加入 evidence input contract，输入目标由 279 增至 280。
- helper 被七个领域报告 source inventory 哈希；修改后重建并独立验证 audit chain、authorization、OIDC browser、SDK release、SDK consumer、SDK matrix 与 server recovery 证据。
