## 2. 全面复评发现

1. `Framework/queueclient.Process` 在带 `traceparent`/`tracestate` 的消息路径调用 `traceCarrier`，为只读提取创建临时 `propagation.MapCarrier`。
2. OpenTelemetry `TraceContext.Extract` 只需要 `TextMapCarrier.Get`；当前 map carrier 没有业务必要的写入或 key 枚举。
3. 历史 mixed-case trace carrier 门禁为 `2 allocs/op`；这是仓库内可确定复现、无需硬件或目标 broker 的热路径分配。
4. V94-02/V94-03 仍是不可替代外部事项，不能由本地 fixture、loopback、miniredis 或文档声明关闭。

## 4. V94-01 实施约束与非目标

1. 不新增公开 API、配置、schema、operation、API version 或 release tag；只改变内部 trace 提取 carrier 的存储形式。

3. 不改变 `Publish` 注入逻辑、消息 body/header clone、header 限制、baggage 隔离、span 名称/属性、deadline、ack/DLQ 或 broker adapter。
4. 不把本地 benchmark 宣称为生产吞吐、p95/p99、RSS、GC、HA 或容量证据。

## 6. 架构、性能、内存与并发评估

`Process` 仍先 clone 并校验消息，再在 bounded consumer span 中调用 handler；V94 只移除 trace header 提取的临时 map。无 trace 路径保持零分配，带 trace 路径从历史 map carrier 的 2 次分配降为 0；broker I/O、消息大小/数量上限、超时和并发语义不变。

## 7. 安全、可靠性、数据与消息评估

carrier 只暴露 W3C 两个 header，不会把 baggage 或任意业务 header交给提取器；invalid traceparent、reserved flags 和 tracestate 解析规则沿用 OpenTelemetry。JetStream settlement、DLQ 两阶段操作、Redis Lua、SQL outbox、OIDC/JWKS、审计链与 Prometheus 合同不变。真实 HA、恢复、RPO/RTO、KMS/SIEM、正式身份和 exactly-once 仍为 `not_recorded`。
