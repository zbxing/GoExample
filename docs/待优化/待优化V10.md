## 1. 当前状态

V10 把实施工作拆为 12 个工作流。当前已完成以下本地可验证优化：

- **V10-00 超时预算门禁：已完成。** `HTTP_READ_TIMEOUT`、`HTTP_WRITE_TIMEOUT` 不得超过 `HTTP_IDLE_TIMEOUT`；drain delay 加 read/write/request timeout 必须分别小于 shutdown timeout。配置错误在启动前失败，并有负向测试。
- **V10-05 登出 CSRF 边界：已完成。** MSFront logout 要求可信 Origin，跨站请求返回 403，成功响应清除 HttpOnly cookie 且设置 `Cache-Control: no-store, no-transform`，已有行为测试。
- **V10-09 可访问性回归：已完成。** 修复 dashboard 图表刻度的 WCAG AA 对比度，production E2E 的桌面/移动 Chromium 8 个场景全部通过；bundle/Lighthouse/Web Vitals 和 Firefox/WebKit 仍待完成。
- **V10 第二批边界强化：已完成。** drain 加 write timeout 纳入 shutdown 总预算；慢请求体真实 TCP 返回 408；Go/Next login/me/logout、Proxy 401 与限流响应统一禁缓存；Go/Next JWT 强制关键 claims、最大年龄与有界角色数组；system/management API 的 JSON 响应统一经 `privateJson` 禁缓存，并以 Node 守卫、服务器测试、前端单元测试和生产 E2E 菜单响应断言闭环。
- **V10 第三批错误响应边界：已完成。** Go 统一 `failure`/error handler、认证私有响应和基础私有路由使用 `no-store, no-transform` 与 `Pragma: no-cache`；`/api/v1` 缓存验证器移除禁存储响应的 ETag，真实测试覆盖 API 404、413、校验错误、非法幂等键、超时、panic、认证和诊断未授权，并在 gzip 请求头下确认错误/认证响应不被压缩。
- **V10 第四批跨栈响应转换边界：已完成。** MSFront `disableResponseCaching` 同步使用 `no-store, no-transform`；Vitest、logout 行为测试、Node 守卫和生产 Chromium E2E 覆盖登录、me、菜单、登出及跨站拒绝响应。
- **V10 第五批会话重定向边界：已完成。** MSFront proxy 对匿名保护页和已登录登录页重定向统一设置 `no-store, no-transform` 与 `Pragma: no-cache`；proxy 单测、Node 守卫和生产 Chromium E2E 覆盖状态码、Location 与响应头。
- **V10 第六批启动配置边界：已完成。** Next `PHASE_PRODUCTION_SERVER` 在运行时配置加载阶段校验生产 JWT 密钥（长度与默认值）和 `MSFRONT_TRUSTED_ORIGINS` 格式，instrumentation 复用同一校验作为纵深防护；两种非法配置的真实 `next start` 均以退出码 1 终止，Vitest 覆盖非法/合法配置，Node 守卫、类型检查和生产构建通过。
- **V10 第七批 Bearer 协议契约：已完成。** Go 受保护 API 对缺失令牌返回基础 Bearer challenge，对无效令牌返回 `invalid_token`；metrics/pprof 使用独立 realm，CORS 暴露 `WWW-Authenticate`；OpenAPI 将密码登录普通 401 与 Bearer 401 分离，Go 行为测试和路由契约共同守卫。
- **V10 第八批 secret 域隔离：已完成。** Go production 配置禁止 metrics token 复用 JWT secret；启用 pprof 时还禁止其 token 复用 metrics 或 JWT 凭据。三种错误组合均在 `config.Load()` 阶段失败，开发默认不受影响；环境示例明确独立随机材料，KMS/Vault 与自动轮换仍未完成。
- **V10 第九批 JWT audience 绑定：已完成。** Go demo JWT 新增 `JWT_AUDIENCE` 配置，签发时写入目标 `aud`，验证时强制存在且匹配；同一 issuer/secret 下缺失或错误 audience 的令牌均由负向测试拒绝，Example 环境与部署说明同步更新。
- **V10 第十批 Request ID 输入治理：已完成。** Go 只接受不超过 128 字节的字母、数字、点、下划线和连字符 Request ID；超长或含分隔字符的值在日志链路前被清除并安全换发，原值不进入日志，替换次数由无标签 Prometheus counter 记录，合法/非法行为均有测试。
- **V10 第十一批可信代理边界：已完成。** Go production 配置拒绝 IPv4/IPv6 catch-all `TRUSTED_PROXIES`；真实 TCP 契约证明未命中 allowlist 的连接无法用 `X-Forwarded-For` 改写限流所依赖的客户端 IP，只有明确可信的代理地址才会启用转发头。
- **V10 第十二批流式背压与写超时：已完成。** Go 请求日志对未知长度流记录 `response_bytes=-1`，不再调用 `Response.Body()` 物化流；缓存验证器跳过流 body，同时保留普通弱 ETag/304 与 `no-store` 语义；真实 TCP 慢读客户端通过受控 socket 缓冲触发 `WriteTimeout`，底层写入返回 timeout 且流生产提前终止，普通重复测试和 race 均通过。

其余条目仍处于未完成或部分完成状态。当前没有 Redis/等价共享存储、OTel collector、目标 edge、Kubernetes、PostgreSQL recovery、签名发布或远端 Linux benchmark 的可核验证据。

## 3. P0 实施项

### V10-00 超时、连接与停机预算

状态：**第一批已完成**。

已完成：

- `HTTP_MAX_CONNECTIONS` 限制 transport 并发，真实 TCP 容量耗尽返回 503。
- `HTTP_MAX_IN_FLIGHT` 限制业务 admission，拒绝带 `Retry-After`，探针不占业务 slot。
- 请求头 budget、slow header timeout、request deadline、draining 和 shutdown 均有真实 TCP 契约。
- 新增 read/write/idle 关系与 read/write/request/drain/shutdown 总预算校验。
- 慢请求体在 read timeout 内返回 408，且不会触达业务 handler。
- 慢读客户端在真实 TCP 背压下安装并触发 write deadline，socket 返回 timeout，流生产端提前终止；日志与 ETag 均不再物化流 body。

仍需完成：

- 在目标 edge 校准 client -> edge -> app -> downstream 的严格超时阶梯。
- 为 transport 连接拒绝增加 edge/内核侧可观测证据，当前应用 middleware 无法计数。
- 加入 keep-alive、半关闭和 FD 收敛测试。

验收：错误预算配置启动失败；真实 edge 的 408/413/431/502/503/504 行为与 runbook 一致；shutdown 后连接、goroutine 和下游任务在上限内收敛。

### V10-01 框架决策与真实性能基准

目标：用数据回答 Fiber 是否值得其标准生态和协议成本。

实施：

- 固定目标 workload：JSON、validation failure、JWT/RBAC、模拟 PostgreSQL/RPC、keep-alive、TLS edge、不同 payload 和并发。
- Fiber 与 Chi/`net/http` 必须复用相同 typed use case、JSON schema、日志与模拟 I/O；根据结果再加入 Gin/Echo/Hertz。
- Linux 固定 runner 至少 5 轮，记录 throughput、p50/p95/p99、错误率、CPU、RSS、alloc、GC、FD、连接、网络和取消后残留任务。
- 使用 benchstat 或等价统计方法；保存原始输出、CPU/heap/profile、硬件、内核、Go 与依赖版本。
- 按 ADR 0001 的预设门槛给出保留 Fiber、迁移或延后决策，禁止事后移动标准。

验收：远端 run 与 artifact 可追溯；profile 指向 HTTP/JSON 热路径；结论能被一条根命令重复；单轮噪声不作为发布门禁。

### V10-02 目标 edge、断连与流式协议

目标：把 loopback baseline 升级为生产部署契约。

实施：

- 选择实际 Nginx、Envoy、Ingress 或云 LB，记录 TLS 终止、HTTP/2/3、header limit、buffering、idle/request timeout 与 drain。
- 自动验证 client -> edge 协议握手、edge -> app upstream、trace/request ID、错误码与 envelope。
- 测试客户端断连、edge timeout、上传中断、slow reader/writer、SSE/WebSocket（仅有业务需求时）、backpressure 和内存上限。
- 若 Fiber 仍不能提供所需取消语义，定义可控补偿或触发 `net/http` 迁移。

验收：目标 edge 自动化测试通过；断连后的昂贵下游工作有终止上限；长连接 drain 无非预期 5xx；不能用 Go loopback 替代目标 edge 证据。

### V10-03 外部共享状态与多实例一致性

目标：使 limiter、idempotency、session/revocation 在多副本下语义不变。

实施：

- 选定 Redis 或等价系统，定义 key schema、TTL、容量、原子操作、clock、故障模式和数据分类。
- limiter 使用跨节点原子计数/窗口，不沿用未经证明的读改写竞争语义。
- idempotency 原子声明 key，绑定 method/path/principal/body hash，区分 in-progress/completed/failed。
- 提供集中 session/revocation，定义 fail-open/fail-closed、timeout、重试、连接池与指标。
- 两个应用实例并发测试相同 quota/idempotency key；覆盖超时、断连、主从切换、eviction 和重连。

验收：轮询节点不能绕过配额；相同幂等 key 只执行一次副作用；production 无外部状态时 fail-fast；故障策略可由自动测试复现。

### V10-04 OpenTelemetry 与 SLO 运行闭环

目标：让 MSFront -> Go -> database/outbound 的错误和延迟可串联、可告警。

状态：**部分完成**。W3C 传播、低基数应用指标、SLO rules 与 Request ID 输入边界已有自动测试；OTel SDK/exporter/collector 和告警演练仍缺失。

本轮已完成：客户端 Request ID 必须为不超过 128 字节的安全 token；非法值在 request logger 前由服务端换发，原值不会进入日志，替换事件只进入无标签 counter，避免用攻击者输入制造指标基数。

实施：

- 接入 OTel Go/Node SDK、Fiber server instrumentation、outbound HTTP、PostgreSQL 和关键 use case span。
- OTLP exporter 必须有 batch、有界 queue、timeout、sampling、drop/retry 指标，collector 不可用不能阻塞请求。
- 部署 collector、Prometheus、Alertmanager 和 dashboard；使用 `promtool` 校验 rules。
- 故障注入触发 availability/latency/saturation/burn-rate 告警，并按 runbook 完成处置。
- 属性做基数与敏感信息测试，不允许用户 ID、原始 URL、token 或任意错误文本进入 metrics label。

验收：一次跨层请求在 trace 中完整；日志可按 trace ID 检索；collector outage 不拖垮 API；告警和恢复时间有 artifact。

### V10-05 正式身份、会话与密钥治理

状态：**部分完成**。JWT/RBAC/Origin/cookie、认证禁缓存与 logout 防护已有测试；正式身份体系缺失。

实施：

- 接入 OIDC Authorization Code + PKCE、state、nonce、issuer/audience 和 JWKS rotation。
- 实现短 access token、refresh rotation、token family、重用检测、设备会话、集中 revoke 和 MFA。
- 统一 Go 与 MSFront principal/permission 模型，增加租户与资源级授权测试。
- secret 进入 KMS/Vault/平台 secret manager，建立 rotation、break-glass、泄漏响应和审计保留。
- 登录防爆破必须支持多实例共享状态；Origin、SameSite 不是登录风控替代品。

本轮已完成：logout route 拒绝缺失/不可信 Origin；Go `/api/v1/auth` 与 MSFront login/me/logout、system/management API、Proxy 401 统一禁止缓存；MSFront JWT 强制 `sub`/`iat`/`exp`、12 小时最大年龄及有界角色数组；Go JWT 强制 `sub`/`iat`/`nbf`/`exp`/`jti`、配置 TTL 最大年龄、有界且一一对应的角色 claims 及目标 `aud`，缺失/错误 audience 和其他异常令牌整体拒绝。

验收：production 禁止 demo/local provider；key rotation、provider outage、refresh replay、revoke、MFA 和越权场景均有集成测试与 runbook。

### V10-06 PostgreSQL 容量、故障与恢复

目标：证明持久化在目标数据量和故障下保持一致与可恢复。

实施：

- 在可核验 CI/预发布环境运行所有 migration 与 integration tests。
- 为更新引入显式 optimistic concurrency/版本冲突契约，避免静默覆盖。
- 覆盖 deadlock、serialization retry、连接耗尽、statement/query timeout、锁等待、failover 和事务隔离。
- 使用目标数据量执行 `EXPLAIN (ANALYZE, BUFFERS)`，为慢查询和索引设预算。
- 执行 backup restore、PITR，定义并验证 RPO/RTO；恢复后检查约束、行数、关键业务 invariant。

验收：schema upgrade/rollback 兼容；故障重试不重复副作用；恢复 artifact 可追溯且达到 RPO/RTO。

### V10-10 安全模型、审计与故障矩阵

状态：**部分完成**。production 已拒绝明显的全网代理信任，可信/不可信转发头行为有真实 TCP 测试；完整 threat model、审计保留与外部故障矩阵仍缺失。

本轮已完成：`TRUSTED_PROXIES` 继续严格解析 IP/CIDR，并在 production 拒绝 `0.0.0.0/0` 与 `::/0`；未受信连接的伪造 XFF 被忽略，明确 allowlist 的代理才可提供客户端 IP。目标 edge 覆盖/清理转发头仍是部署验收项。

- 编写 threat model：资产、信任边界、数据分类、攻击面、滥用场景和残余风险。
- 映射 OWASP API Top 10：对象/属性/功能授权、资源消耗、SSRF、错误配置、inventory、第三方 API 消费。
- 敏感日志清洗、审计不可抵赖、保留周期、访问控制与告警。
- 建立 edge、DB、Redis、OTel、OIDC、磁盘、DNS、证书、网络分区故障矩阵。

验收：每个高风险场景有 owner、门禁、告警和 runbook；受控故障可重复触发预期降级。
