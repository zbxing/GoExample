## 1. 本轮目标

V7 已补齐 PostgreSQL migration CI、OpenAPI 完整性、CodeQL、dependency review 与 Dependabot。本轮选择剩余评分中最可在本地形成真实证据的缺口：MSFront production browser E2E、可访问性、响应式布局和独立浏览器 CI。

原则：

- 测试真实 `next build` + `next start`，不只测试组件 mock。
- 测试数据与 `MSFront/data` 隔离，失败或中断后可清理。
- 使用 role/label 等可访问定位器，保留 Playwright strict mode。
- axe 发现的问题直接修复，不加入忽略清单规避。
- 本机证据与远端 CI 证据分开表述。

## 2. 已完成优化

### V8-01 根浏览器工具链与数据隔离（完成）

- 根项目增加 `@playwright/test@1.62.1`、`playwright-core@1.62.1` 与 `@axe-core/playwright@4.13.0`。
- 新增 `yarn test:e2e`，保持根 Node 项目负责跨工程命令编排。
- `scripts/e2e-msfront.mjs` 将 `MSFront/data` 复制到系统临时目录，通过 `MSFRONT_DATA_DIR` 注入，结束后递归清理。
- Windows 自动使用本机 Chrome/Edge；CI 使用 Playwright 管理的 Chromium。
- 使用单 worker 避免演示文件仓储被多个登录流程并发改写。

验收：根依赖可 frozen install；源数据运行前后不发生改动；Playwright CLI 可列出 8 个用例。

### V8-02 production 认证与恢复 E2E（完成）

- 未登录访问 `/projects` 必须重定向到带 redirect 参数的登录页。
- 错误凭据必须显示可访问 alert，且不能改变登录状态。
- `admin/admin123` 必须进入 dashboard。
- 退出后再次访问 dashboard 必须重定向回登录页。
- 受保护的未知路径必须显示 404，并能通过“返回控制台”恢复。
- 伪造 `Origin: https://attacker.example` 的登录请求必须返回 403。
- production session Cookie 必须为 HttpOnly、Secure、SameSite=Lax。

验收：Desktop Chrome 与 Pixel 7 项目均通过以上流程。

- 登录页页脚、breadcrumb、指标增量、图表刻度、表头、辅助标签和时间文字使用满足 AA 的色阶。

### V8-05 Windows race 环境自发现（完成）

- 根 Go runner 在 `race` 任务中自动设置 `CGO_ENABLED=1`。
- Windows 依次发现 `CC`、`GCC_ROOT`、`E:\DevTools\GCC\mingw64\bin\gcc.exe`、常见 MinGW 路径和 PATH 中的 gcc。
- 找不到编译器时在启动 `go test -race` 前返回可操作错误，不再只暴露 Go 的通用 CGO 错误。
- 已在当前未包含 GCC PATH、默认 `CGO_ENABLED=0` 的 shell 中验证 `yarn race:server` 全包通过。

## 5. V9 建议顺序

1. OpenTelemetry + SLO：优先提升当前最低的可观测性维度，并为后续性能与故障测试提供测量基础。
2. 共享 limiter/idempotency store：解除水平扩容的结构性限制。
3. 真实 PostgreSQL failure/recovery：把静态与 CI 配置转换为目标环境证据。
4. Bundle/Web Vitals budget：在已有浏览器框架上增加可重复性能门禁。
5. OIDC 与会话轮换：替换 demo 身份边界，需要单独威胁模型与迁移设计。
