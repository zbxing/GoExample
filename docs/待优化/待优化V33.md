## 3. V33-01 实施设计

### 3.1 原子发布协议

1. `scripts/lib/sdk-release.mjs` 导入 `writeFileAtomicallySync()`；`writeSDKReleaseManifest()` 保持三项必需参数，并新增默认值为该 helper 的可选 `writeOutput` 注入点。
2. manifest 继续先由 `encodedManifest()` 在内存中形成相同的 two-space JSON 与结尾换行；目标仍由 `manifestPath()` 解析。
3. helper 在目标目录以不可预测名称和 `wx` 创建临时文件，完整写入并 file fsync，关闭后同目录 rename 到 canonical 路径。
4. rename 前发生 open/write/fsync/close 错误时不触碰旧目标；未发布临时文件尽力清理，原始错误优先返回。
5. 不修改 `buildSDKReleaseManifest()`、`verifySDKReleaseManifest()`、manifest schema、source commit、expected tag、publication 状态或 artifact 哈希。

### 3.2 失败、并发与平台边界

- 行为测试先写入一个有效 manifest，再用新 manifest 完整替换并按精确字节 verify。
- 注入 publication failure，断言调用次数、路径、字节和编码参数，且旧 manifest 保持逐字节不变。
- 成功替换后检查 SDK 目录不存在匹配 `.^release-manifest.json.*.tmp` 的残留文件。
- 共享 helper 的 open/write/fsync/close/rename/cleanup 故障矩阵继续由既有测试覆盖；SDK 测试只验证领域接入和旧值保留。
- 当前 Windows 真实文件系统替换不能外推到全部 Linux 文件系统、容器卷、网络盘或断电恢复；单文件原子替换也不是 SDK client/VERSION/manifest 的多文件事务。

### 3.3 防回归与证据

- 静态守卫读取 `scripts/lib/sdk-release.mjs` 与其测试，锁定 helper import、默认注入、调用参数和移除直接 `writeFileSync`。
- 保留 V26 至 V32 历史文档断言，增加 V33 修复前/完成目标、V33-01 和九个 `not_recorded` 工作包断言。
- V33 文档加入 evidence input contract，输入由 285 增至 286；共享 input contract 变化后重建并独立验证七组领域 evidence。
- 完整 Node 主阶段目标由 173 增至 174；release 阶段保持 1，API compatibility 预期保持 356 symbols。
