## 3. V25-01 实施设计

### 3.1 共享严格身份读取器

- 在 `scripts/lib/bounded-command.mjs` 增加 `readBoundedGoVersion()` 和 `readBoundedGitCommit()`，只调用现有 `runBoundedCommand()`。
- Go 只接受完整 `go version goX.Y.Z os/arch`；Git 只接受 40 位 lowercase 十六进制 commit。执行失败、空输出或格式异常都返回 `null`。
- 不改变 `maximumCommandDurationMs = 30_000`、64 MiB `maxBuffer`、`SIGTERM`、Windows fallback 与 `string | null` 契约。

### 3.2 调用面迁移与 source 绑定

- 迁移 audit chain、authorization、OIDC browser、SDK release、SDK consumer 的 Go/Git 探针，以及 SDK matrix、server recovery 的 Git 探针。
- 移除这 7 个库对 `node:child_process` 的直接导入；长时间 Go 测试、构建和恢复 drill 继续使用各自任务级 timeout，不纳入本轮迁移。
- 保留各模块现有 `cannot resolve ...` 错误文案、Go 命令选择和 cwd。
- 7 组 report source inventory 加入 `scripts/lib/bounded-command.mjs`，确保独立 verifier 对共享执行边界做文件哈希绑定。

### 3.3 防回归与证据

- fake runner 覆盖命令、固定参数、cwd、成功值、`null`、空值和畸形 Go/Git 身份。
- 静态守卫确认 7 个库都导入共享读取器、不再直接导入或调用 `spawnSync()`，并把 bounded helper 纳入 source inventory。
- 将 V25 文档加入 evidence input contract，目标输入数从 276 增至 277。
- 重建并独立验证 audit chain、authorization、OIDC browser、SDK release、SDK consumer、SDK matrix 与 server recovery 证据；制品 schema 与集合不变。
