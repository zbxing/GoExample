## 3. V23-01 实施设计

### 3.1 共享选择契约

- 在 `scripts/lib/go-toolchain-environment.mjs` 增加 `selectRepositoryToolCommand()`，输入为显式命令、仓库候选和 PATH fallback；helper 统一裁剪显式命令的外围空白。
- 非空显式命令无条件胜出，即使它是相对/PATH 名称或最终不可执行；真实 spawn 负责给出失败，选择器不得静默替换。
- 仅仓库候选使用文件存在性检查；命中时返回 `repositoryManaged: true`。无显式值且无仓库候选时返回 fallback 和 `repositoryManaged: false`。
- 返回新对象，不排序、不覆盖、不删除调用者数组或环境对象。

### 3.2 迁移边界

- 迁移 audit chain、authorization、OIDC browser、SDK consumer、SDK release、server recovery、server release 与 `go-project.mjs` 的同类三层选择。
- 严格 evidence/recovery/release 继续按 V22 契约隔离继承 `GOROOT`；普通项目入口只在 `repositoryManaged` 为真时隔离。
- `environment.mjs`、workflow lint、Prometheus rules 的固定版本探测及 transport benchmark 的外部工具语义不同，保持现状。
- 缓存、临时目录、PATH 注入、`GOWORK`、`GOFLAGS`、CGO/race、测试范围、超时、最大输出、schema、artifact、checksum 和 verifier 不变。

### 3.3 防回归与证据

- 单元测试覆盖：显式无效/PATH 命令优先、首个存在仓库候选、fallback、来源标记、空值和输入不可变。
- 脚本守卫断言全部迁移入口调用共享选择器，并继续断言 V22 的条件/无条件 `GOROOT` 隔离。
- 将 V23 文档加入 evidence input contract，修复后重新生成所有受影响制品；不得通过放宽 verifier 或删除失败输出来通过。
