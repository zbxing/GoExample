## 3. V24-01 实施设计

### 3.1 时间与输出双重边界

- 在 `scripts/lib/bounded-command.mjs` 导出 `maximumCommandDurationMs = 30_000`，并把它作为默认 `timeoutMs`。
- `timeoutMs` 必须是 `1..30_000` 的安全整数；`0`、负数、浮点数、非数值、非安全整数和超过上限全部在 spawn 前抛出。
- 每个直接候选和 Windows shell fallback 都传递 `timeout: timeoutMs`、`killSignal: 'SIGTERM'`、现有 64 MiB `maxBuffer`、UTF-8、`shell: false` 和隐藏窗口。
- 继续返回 `string | null`；成功输出的 raw/trim 行为不变，超时不引入新的公开返回类型。

### 3.2 Windows fallback 与失败分类

- 非 Windows 或绝对命令只执行一个候选。
- Windows 相对命令依次探测原名、`.cmd`、`.exe`，但只有 `result.error.code` 为 `ENOENT` 或 `EINVAL` 时才继续。
- 候选一旦启动，状态 0 正常返回；非零状态、信号、`ETIMEDOUT` 或其他错误立即返回 `null`，不得被下一个候选掩盖。
- 所有直接候选都是启动失败后，才允许通过 `cmd.exe /d /s /c` 保留 Yarn wrapper 兼容。

### 3.3 防回归与证据

- fake spawn 测试断言 timeout、kill signal、输出上限与选项对所有路径透传。
- 分别覆盖 timeout 停止后续候选、非零退出停止候选、`ENOENT`/`EINVAL` 进入 shell fallback、非法 timeout 拒绝。
- 运行一个真实短超时子进程，并保留超过 1 MiB 输出与非零退出测试。
- 将 V24 文档加入 evidence input contract，目标输入数从 275 增至 276；不得放宽 manifest/verifier schema 或删除制品。
