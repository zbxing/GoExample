## 2. 复评发现

1. V80 在通用 `queueclient.Client`/worker callback 外层拒绝 handler、settlement 和 lease 的迟到结果，但 `natsjetstream.Adapter` 是可直接调用的独立公开边界，不能依赖调用方必然经过通用层。
2. `publish` 不拒绝 pre-completed context，并在 `PublishMsg` 返回后直接接受 valid `PubAck`；忽略 context 的 publisher 可在 caller deadline 后形成 adapter success。
3. `PreflightConsumer` 仅在 `Info` 返回 error 时查看 `ctx.Err()`，valid 迟到 info 会被继续校验并成功；deadline 已到但 Done 未调度也未覆盖。
4. `receiveNext` 只在 `Next` 后检查 parent `ctx.Err()`；忽略 `FetchContext` 的 consumer 可迟到返回 valid message。`ReceiveDelivery` 在 conversion 和交付前也没有 caller completion boundary。
5. `ExtendLease` 只检查 `ctx.Err()`；`Acknowledge` 和 `DeadLetter` 不在 valid result 后复核 completed context。`InProgress` 无 context，无法强杀，但可以拒绝迟到 nil success。
6. DLQ/quarantine 是 publish-before-source-ack 两阶段操作。迟到 valid DLQ ack 当前仍可触发源 `DoubleAck`，在 caller 已完成后继续产生第二次 broker 副作用。
7. 这些缺口可由私有 helper、可控 fake 与确定性 deadline-only context 完整证明，不依赖真实 NATS、网络、容器或设备；实现无需增加 API、goroutine、timer、锁、网络往返或 broker command。

## 4. V85-01 实施约束与非目标

1. 不新增公开 API、配置、环境变量、schema、共享状态、goroutine、timer、锁、网络往返或 broker command。
2. 私有 helper 同时检查 `ctx.Err()` 与已到达的单调 deadline；live 快路径保持 `0 allocs/op`。
3. 纯本地参数错误优先级保持：nil adapter/dependency、nil context、invalid message ID/config 仍使用既有 sentinel。
4. preflight/publish/receive 必须在 broker callback 前拒绝 completed caller，并在 callback 与本地 parse/conversion 后拒绝迟到结果。
5. `receiveNext` 必须区分 adapter-owned fetch timeout 与 parent completion；前者仍作为空 pull，后者返回 parent error。
6. lease extension 在 `InProgress` 前后复核 caller；ack 在 `DoubleAck` 前后复核 caller。各操作继续使用既有低敏错误映射。
7. DLQ/quarantine 在 metadata、publish、source ack 的每个阶段复核 caller；迟到 publish ack 不得继续 source ack，迟到 source ack 不得形成 success。
8. 不声称 context 能撤销 broker 已接收的 publish/ack 或强杀忽略 context 的实现。任何 timeout/cancel 后的 broker 实际状态仍可能未知，调用方只能按稳定 dedupe ID 与既有 retry 合同恢复。
9. 不改变 subject、header filtering、message clone、message ID、PubAck 校验、consumer preflight、AckWait/BackOff、retry/jitter/lease 或 observer 语义。
10. 不修改、构建、测试或计分 `MSFront`。

## 6. 性能与资源边界

V85 只在既有同步边界增加 O(1) context 状态与 deadline 比较。正常路径不增加堆分配、消息复制、网络往返、broker command、retry attempt、goroutine、timer、锁或后台状态；pre-completed 路径减少无效本地准备和 broker 调用。

本地 fake、benchmark 与 loopback 只能证明 adapter 控制流、分配边界和固定错误，不证明生产吞吐、p95/p99、CPU、RSS、NATS capacity/HA、跨主机恢复、原子 settlement 或 exactly-once。
