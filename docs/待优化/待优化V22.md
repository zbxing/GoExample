## 3. V22-01 实施设计

### 3.1 选择与环境语义

- `go-project.mjs` 将显式 `GO_BINARY`、仓库托管候选和 PATH fallback 分开判定。只有自动选中 `.temp/toolchain` 候选时调用 `isolatedGoToolchainEnvironment()`；缓存、临时目录、PATH 前置、race/CGO/GCC 与全部任务参数不变。
- `environment.mjs` 的 Go 选择结果记录是否为仓库托管。找到仓库候选或刚完成仓库安装时隔离 `GOROOT`，显式 `GO_BINARY` 与 PATH Go 保留调用者工具链环境；逐 module `GOWORK=off` download/verify 不变。
- audit chain、authorization、OIDC browser、SDK consumer 和 server recovery 属于固定、可审计的 evidence/演练入口，统一调用共享 helper；`GO_BINARY` 仍决定二进制，不再允许父进程 `GOROOT` 改变标准库来源。
- 不修改只运行 `gofmt` 的 SDK 生成器、不修改 Docker 容器内 PATH Go、不修改只读取制品的 verifier，也不修改 `MSFront`。

### 3.2 防回归与证据

- 保留 V21 helper 单元测试：复制输入与覆盖、大小写不敏感删除所有 `GOROOT`、不修改输入对象、不写入机器特定替代值。
- 脚本守卫断言七类入口导入并调用共享 helper，同时断言 `go-project`/`environment` 保留外部工具链条件分支。
- 将 V22 文档、`environment.mjs` 和所有受影响入口保持在 evidence input contract；不得修改 evidence schema、checksum subject、verifier、超时或输出上限来规避失败。
- 修复后重新生成 authorization 及全部受影响 evidence，确保默认目录不残留失败报告。
