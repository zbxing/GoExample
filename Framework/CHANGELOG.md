# Framework changelog

All notable Framework changes are recorded here. Versions follow Semantic Versioning, with module-scoped tags described in `COMPATIBILITY.md`.

## Unreleased

### Added

- Direct strict W3C `traceparent`/`tracestate` extraction for inbound server spans, replacing the per-request OpenTelemetry map carrier while preserving remote parent IDs, sampled/random flags, valid trace state, invalid-tracestate isolation, and the existing version/lowercase/reserved-flag policy. The parser path is guarded at zero allocations, and a permanent traced hello benchmark records the end-to-end allocation contract without claiming latency or throughput gains.
- Bounded `httpapi.SendServerSentEvents` support for standard HTTP/1.1 and HTTP/2 entrypoints, with fixed EventSource headers and wire encoding, bounded heartbeat/event sizes, request/disconnect/shutdown cancellation, and no internal event queue. The additive `SendServerSentEventsFromSource` entrypoint accepts a transport-neutral `ServerSentEventSource`, validated 1024-byte `Last-Event-ID` cursor and stream lifetime context for application-owned replay. The additive `ServerSentEventOptions.StreamTimeout` lets an SSE producer replace the ordinary request timeout with an explicit limit of at most 24 hours without losing a shorter caller deadline, client cancellation or application shutdown; zero retains the original request and server write budgets. On `NewHTTPHandler`, a positive value also uses standard `http.ResponseController` write-deadline control so `server.RunHTTP.WriteTimeout` cannot silently truncate the longer stream; producer cancellation remains exact and transport cleanup has a fixed one-second allowance. Multi-line data framing scans twice and writes directly through the bounded buffer instead of allocating a slice and aggregate string proportional to the number of lines. These repository contracts do not claim target-edge behavior or durable replay storage.
- Conditional browser-session self-service routes for bounded low-sensitivity inventory, caller-supplied device-name update, subject-bound single-session revocation, and revoke-all. Bearer and browser-session authentication share the same subject boundary; unsafe cookie-authenticated calls retain CSRF enforcement, cross-subject and unknown IDs are indistinguishable, and inventory/metadata backend failures return a private fail-closed response. OpenAPI and the generated Go SDK advance additively to `1.4.0` with 26 operations; device fingerprinting/UI and production identity infrastructure remain external.
- Opt-in `httpapi.OIDCBrowser` start/callback/logout routes that bind one-time OIDC state to a Secure, HttpOnly, SameSite=Lax `__Host-` cookie, consume state before exchange, verify nonce and matching ID/access-token subjects, then establish a bounded opaque application session without returning provider tokens. Unsafe session-authenticated methods require a stored-hash-bound `__Host-` CSRF cookie/header pair; logout immediately revokes the session and clears both cookies. The additive OpenAPI/Go SDK contract advances to `1.2.0` with 22 operations; this does not claim device metadata/self-service UI, target IdP deployment or a completed MFA enrollment/challenge flow.
- Bounded `auth.BrowserSessionManager` and pluggable `BrowserSessionStore`: raw session/CSRF credentials are returned once and persist only as SHA-256, session lifetime is capped by both configuration and verified access-token `exp`, claims are copied, global count is bounded, and read/delete failures remain fail closed. The additive `BrowserSessionInventoryStore`, public random session IDs and manager list/single-revoke/revoke-all methods add per-subject limits and subject-scoped centralized revocation without expanding the legacy store interface. `sharedstate.Redis` uses hashed subject/session-ID indexes and Lua for atomic cross-client global/per-subject creation and revocation; local mode has matching semantics, while production Example browser OIDC still requires external shared state. This is not a device metadata/UI or production identity-platform deployment.
- Pluggable `auth.AuthorizationRequestStore` with compatible context-aware start/complete methods. The Redis implementation keys requests only by the state SHA-256, stores a bounded PKCE verifier/nonce payload, applies an atomic global pending limit, and consumes each request with one Lua read/delete/index removal. Dual-client tests cover concurrent exactly-once consumption, expiry, tamper, limit and outage failure without claiming production Redis HA.
- Transport-neutral bounded resource authorization contract with deny-by-default decisions, tenant/resource/action/attribute validation, function adapters, and typed query/command integration. Resource policies run after Bearer/role and typed input validation but before application execution; commands also authorize before preconditions and idempotency state. Error, invalid decision, timeout, and panic outcomes collapse to private 403 responses. Example preview/describe now enforce subject-owned tenant access while preserving existing clients through a subject fallback when the optional tenant input is absent.
- Pluggable `auth.TokenVerifier` support that separates Bearer-protected routes from the demo password login and HS256 issuer.
- Bounded RS256 JWKS verifier with synchronous startup fetch, fixed issuer/audience and required claim profile, RSA/token/response/key limits, collapsed unknown-key refreshes, cache-expiry fail-closed behavior, and credential-safe errors.
- Bounded OIDC ID-token verifier reusing the RS256/JWKS boundary and requiring issuer/audience, subject, expiration/issued-at age, nonce, and multi-audience `azp` checks. Optional assurance policy requires an exact `acr`, every configured `amr` method and a present, fresh `auth_time`; authorization requests send the same bounded `acr_values` hint. Missing, stale, malformed, duplicate or mismatched assurance claims collapse to the private invalid-token result without changing access-token verification. Target IdP MFA enrollment/challenge and provider deployment remain external.
- Bounded OIDC discovery and authorization-code exchange client with exact issuer/endpoint and `code`/S256 capability checks, redirect refusal, JSON/timeout/response limits, PKCE verifier validation, fixed token response validation, and credential-safe failures. It is a repository protocol boundary only; target IdP deployment, MFA, durable state, and production egress remain external.
- One-time OIDC callback composition that consumes pending state before exchange, binds ID-token verification to the original nonce, collapses provider failures to fixed sentinels, and prevents callback replay after exchange or claims failure. Browser routing, MFA, opaque access-token policy, and production identity deployment remain external.
- Bounded transport-neutral refresh session manager with SHA-256-only token storage, absolute and rolling TTLs, refresh-family rotation, replay-triggered family revocation, user/family revoke operations, concurrent access protection, family/token-history bounds, and a configurable family bound.
- Pluggable `auth.SessionStore` persistence for refresh families, plus an atomic Redis implementation with namespace-scoped hash-only indexes, Lua rotation/reuse detection, family/user revoke, active-family queries, bounded family/history limits, and fail-closed outage behavior. Local `miniredis` coverage proves cross-client semantics only; production Redis HA and identity-platform deployment remain external.

Without a Store it keeps hash-keyed local state; an injected store enables cross-process consumption. It still stops before MFA, profile mapping or target IdP deployment.

Legacy receive callbacks remain fail-fast; an opt-in mutually exclusive delivery mode adds private ack/dead-letter callbacks, at most 10 cloned handler attempts with finite exponential backoff, explicit non-retryable failures, bounded settlement, and cancellation-safe fail-closed behavior without claiming ordering, deduplication, persistence, or exactly-once.

### Changed

- Application shutdown now cancels active request deadlines and claimed SSE stream deadlines through one bounded application-scoped registry instead of installing an application-context `AfterFunc` for every request. Caller cancellation, request timeouts, stream timeout replacement, late-request rejection, standard write deadlines, and shutdown convergence remain covered by focused behavior and race tests; local endpoint benchmarks verify fewer allocations without claiming latency, throughput, remote-capacity, or target-environment gains.
- Restricted-origin API responses now preseed the existing `Vary: Origin` contract, skip Fiber CORS only when a non-OPTIONS request has no `Origin`, and coalesce the common compression value through a precomputed `Origin, Accept-Encoding` header. Exact success, allowed-origin, wildcard-origin, preflight, handler-error, and non-API tests preserve wire behavior while the local hello benchmark verifies two fewer allocations per request without claiming byte, latency, throughput, remote-capacity, or target-environment gains.
- Default, blank, and explicit `Fiber` hello queries now reuse a pre-encoded success envelope with the same JSON body and content type as Fiber's standard encoder; custom names retain standard JSON escaping. Full wire, weak ETag, conditional request, and escaping contracts protect the fast path, while local benchmarks show three fewer allocations per request and a non-overlapping byte range without claiming latency, throughput, remote-capacity, or target-environment gains.
- Example hello query handling now reuses Fiber's decoded query bytes, returns a constant default message, and uses a pre-sized builder only for custom names. Exact contracts preserve plus and percent decoding, Unicode whitespace trimming, and repeated-parameter semantics, while local benchmarks show a lower allocation range without claiming byte, latency, throughput, or remote-capacity gains.
- Fixed-field Example hello, delay, and authenticated private responses now use package-private typed JSON data instead of per-request maps. Exact wire-contract tests retain the existing field names, values, and ordering, while the local hello benchmark verifies five fewer allocations per request without claiming remote throughput.
- Weak response ETags now use the same Q-polynomial CRC32 wire value as Fiber while encoding directly into a fixed 25-byte stack buffer; requests without `If-None-Match` also skip the comparison string conversion. Byte-for-byte compatibility and zero-allocation generation guards preserve streaming, cache-control, existing-tag, status, and conditional-response behavior without claiming remote throughput.
- Sampled standard-method OpenTelemetry span finalization now reuses one combined route/status attribute configuration for finite Fiber route templates and valid HTTP statuses, avoiding the second SDK attribute-slice growth after warmup. Unknown methods and out-of-range statuses retain dynamic fallback paths and cannot expand the cache; behavior and allocation guards preserve final method, route, status, and span-name semantics without claiming remote throughput.
- OpenTelemetry request trace state now keeps the raw server and parent span contexts in one context wrapper, encodes the response `traceparent` directly from those IDs, and formats the public `TraceContext` only on first access. Nested child spans retain the request server-span identity; allocation guards cover one-allocation attachment and zero-allocation cached reads, while the local endpoint benchmark verifies three fewer allocations per request without claiming remote throughput.
- Request deadlines now carry the SSE lifetime and standard response write-deadline capability through the Go context chain instead of Fiber Locals. Wrapped request contexts retain values, deadlines, cancellation, and stream discovery while the local endpoint benchmark verifies three fewer allocations per request without claiming remote throughput.
- Standard HTTP methods now reuse immutable OpenTelemetry server-span start names and options prepared when the tracing middleware is constructed; custom methods retain the dynamic path without entering an unbounded cache. Behavior and allocation guards cover the standard fast path and custom fallback, and the full local endpoint benchmark verifies fewer per-request allocations without claiming remote throughput.
- W3C server response `traceparent` values now use a fixed 55-byte encoder instead of `fmt.Sprintf`; the Fiber middleware copies those bytes directly into the response header while the public `TraceContext.Traceparent` API retains its canonical string result. A focused allocation guard limits the public formatter to one allocation, and the full local endpoint benchmark verifies the middleware hot path reduction without claiming remote throughput.
- Request logging now checks the configured `slog` level before extracting request attributes and emits a fixed-capacity `slog.Attr` set through `LogAttrs`, reducing successful-request allocations while preserving the existing structured fields and status-derived levels.
- The Example composition root can enable mutually exclusive external OIDC/JWKS resource-server mode; external Bearer verification does not register the local demo login route.
- External shared-state validation now requires an atomic limiter implementation; Redis locks use a namespace distinct from cached idempotency responses.
- Application query definitions now fail at startup when they conflict with a Framework default GET route.
- Application query paths must be canonical and static; ambiguous routes and case-insensitive collisions fail before registration.
- Application command paths receive the same startup validation and cannot collide with default POST routes or mix with the advanced Fiber registrar.
- Bearer-protected API responses now set private no-store headers before both successful and rejected handlers.
- The Example preview query now requires the exact `demo` role and documents its 403 contract in OpenAPI.
- The Example describe command now registers only with authentication enabled, requires the exact `demo` role, and passes the verified subject into the application use case.
