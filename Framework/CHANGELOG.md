# Framework changelog

All notable Framework changes are recorded here. Versions follow Semantic Versioning, with module-scoped tags described in `COMPATIBILITY.md`.

## Unreleased

### Security

- Updated the indirect `google.golang.org/grpc` dependency from `v1.83.0` to `v1.83.1` across Framework and its executable workspace consumers to remediate `GO-2026-6348`. The repository vulnerability gate now reports no vulnerabilities affecting project code; public APIs and generated contracts are unchanged.

### Added

- Browser-session and authorization-state SHA-256 hex validation now scans the required 64 lowercase hexadecimal bytes directly instead of allocating decode and canonical re-encode buffers. Invalid length, uppercase, non-hex, Unicode, payload/index, TTL, Redis Lua, fail-closed, and public API behavior remain unchanged; the permanent benchmark improved from `133.1–136.8 ns/op, 160 B/op, 3 allocs/op` to `30.21–31.83 ns/op, 0 B/op, 0 allocs/op`.

- OIDC ID Token assurance validation now uses a bounded stack-backed index for the maximum 16 `amr` values instead of allocating a temporary map on each verification. Exact-string duplicate rejection, required-AMR containment, ACR validation, nonce/issuer/audience checks, fail-closed errors, and public claims remain unchanged; the full assurance benchmark improved from `1292–1321 ns/op, 936 B/op, 3 allocs/op` to `1036–1111 ns/op, 0 B/op, 0 allocs/op`.

- `Metrics.Render` now reuses a scratch label buffer for each request snapshot and formats the status code with `strconv.AppendInt`. Prometheus output bytes, escaping, label order, histogram/runtime metrics, snapshot ownership, concurrency, and public APIs are unchanged; the local 32-snapshot benchmark improved from `109128–125083 ns/op, 250185 B/op, 138 allocs/op` to `102040–123232 ns/op, 243929–243932 B/op, 10 allocs/op`.

- JetStream literal subject validation now rejects `*` and `>` inside the existing rune scan instead of traversing valid subjects once with `strings.ContainsAny` and again for token and Unicode checks. Length, empty-token, wildcard, Unicode whitespace/control, configuration sentinel, and public API behavior remain unchanged.

- JetStream literal subject validation now scans the subject once instead of creating a token slice with `strings.Split`. Empty tokens, wildcard rejection, 255-byte bound, Unicode whitespace/control rejection, and configuration error behavior remain unchanged; valid and invalid local benchmarks now report `0 allocs/op` (about `97–99 ns/op` for a valid subject and `41–52 ns/op` for invalid boundaries versus V121's `1 alloc/op`).

- JetStream message conversion now validates all application header cardinalities before cloning the broker body. Invalid multi-valued deliveries therefore fail without retaining an unreturned body clone, reducing the local failure-path benchmark from about `275 ns/op, 308 B/op, 2 allocs/op` to `235 ns/op, 300 B/op, 1 alloc/op`; successful empty, control-only, single-value, and multi-header messages retain the existing defensive body ownership and error contracts.

- JetStream `receiveNext` now uses the broker's bounded `FetchMaxWait` directly for contexts that have neither cancellation nor a deadline, while retaining the child `FetchContext` path for cancellable and deadline-bearing callers. A monotonic post-return check still rejects late SDK or test-double results at the adapter boundary; message ownership, cancellation/deadline precedence, error sentinels, settlement, and public APIs are unchanged.

- Broker-neutral message header validation now uses a fixed-capacity, stack-backed open-addressing index for case-insensitive duplicate detection across the default 9-64 header range. ASCII-folded hashing and final `EqualFold` checks remove normalized-name map and lowercase-string allocations while preserving collision correctness, visible-ASCII names, CR/LF/NUL rejection, count and byte limits, custom limits above 64, caller ownership, trace propagation, error sentinels, and public APIs.

- Broker-neutral message header validation now keeps case-insensitive duplicate detection stack-backed for sets of up to eight headers. The bounded path avoids normalized-name map and lowercase-string allocations while preserving visible-ASCII names, CR/LF/NUL rejection, count and byte limits, caller ownership, trace propagation, error sentinels, and public APIs; sets of 9-64 headers retain the normalized map path.

- Redis command tracing now maps the bounded command vocabulary to immutable lowercase span operations and uppercase `db.operation.name` values. The common go-redis lowercase path, case-insensitive compatibility path, and unknown-command `_other/_OTHER` path avoid temporary case-conversion strings while preserving span names, low-cardinality telemetry, context/error behavior, Redis commands, public APIs, and configuration.

- SQL span names now map the fixed internal operation vocabulary (`CHECK`, `EXEC`, `QUERY`, `LOCK`, `UPDATE`, `OUTBOX`, and `TRANSACTION`) to immutable lowercase strings instead of calling `strings.ToLower` on every operation. Unknown package-local operation values retain an ASCII lowercase fallback; span names, `db.operation.name`, SQL timeout/rollback/retry behavior, telemetry privacy, and public APIs remain unchanged. The fixed helper path is allocation-free.

- Outbound HTTP propagation now avoids extracting a span context on the custom `TextMapPropagator` path. The context lookup remains scoped to the built-in `TraceContext` no-op decision, while typed-nil fail-closed handling, header isolation, W3C propagation, retry, circuit-breaker, body ownership, timeout behavior, and public APIs remain unchanged.

- Outbound HTTP propagation now treats every nil-able typed-nil `TextMapPropagator` (including custom pointer implementations) as an explicit no-op, preventing nil-receiver `Inject` panics while retaining request-context replacement and caller-header isolation for real propagators. The standard non-nil `TraceContext` fast path, W3C propagation, retry, circuit-breaker, body ownership, and timeout behavior are unchanged; this is an internal fail-closed guard with no public API or configuration change.

- Outbound HTTP propagation now treats a nil or typed-nil `TraceContext` propagator as an explicit no-op, avoiding a nil-interface panic while retaining request-context replacement and the existing caller-header isolation contract for real propagators. `New` continues to install the standard non-nil propagator; this fail-closed guard only affects internal transport composition and does not change public APIs, W3C propagation, retry, circuit-breaker, body ownership, or timeout behavior.

- OIDC discovery, authorization-code exchange, cached JWKS verification, and JWKS refresh now share an auth-private caller-context result boundary. Pre-completed calls perform no provider I/O or token verification; responses observed after cancellation or the monotonic deadline are closed and rejected through the existing fixed sentinels, and a late JWKS response cannot publish shared cache state. JWKS refresh remains single-flight, but contending callers can now leave on their own cancellation instead of waiting for another caller's provider timeout. Public APIs, configuration, OIDC/JWT/RSA policy, cache intervals, response limits, and live-context allocation behavior are unchanged; cancellation still cannot prove that a provider did not receive a request.

- Outbound HTTP tracing, retry, and circuit-breaker transports now enforce one caller-context result boundary and explicit body ownership. Pre-completed requests are rejected before the next transport and close their request body; late or response-plus-error results close the response body, preserve explicit transport errors, and convert only nil success to the original cancellation or monotonic deadline error. Live nil response/nil error is a fixed private failure, retries perform no post-completion jitter or attempt, and breaker accounting ignores caller completion while retaining the fixed `probe_canceled` half-open event. Public APIs, configuration, retry policy, breaker thresholds, telemetry fields, and normal-path allocation behavior are unchanged; a timeout still cannot prove that a downstream request was not accepted.

- Redis tracing hooks now treat cancellation and the monotonic deadline as authoritative after a nil dial, command, or pipeline result. A connection returned after that boundary is closed instead of entering the pool; late command and pipeline success is returned as the original context error and receives the existing fixed canceled/timeout span classification. Explicit dependency errors, public APIs, configuration, Redis commands, pool behavior, data schemas, and telemetry privacy are unchanged. This cannot undo a command already accepted by Redis, so a timeout remains an unknown outcome rather than permission for an unconditional retry.

- Bounded `sqlclient` operations now treat cancellation and the monotonic operation deadline as authoritative after a nil driver/consumer result. Late `PingContext`/`ExecContext`/`QueryContext` success is classified by the original context error; `Exec` withholds the late result, query rows are closed before any caller consumer can run, affected-row helpers check both sides of `RowsAffected`, and transaction begin/commit boundaries reuse the same completion check. Public APIs, pool/timeout defaults, PostgreSQL retry policy, explicit error authority, commit ownership and telemetry privacy are unchanged. This cannot undo SQL already executed by a non-transactional driver, so a timeout remains an unknown outcome rather than permission for an unconditional retry.

- Queue publish/process callbacks now treat their bounded operation context as authoritative immediately before invocation and after a nil return, so already-canceled work is not started and a late nil cannot be recorded as success. Reliable-delivery handler timeouts continue through the existing bounded retry and exhausted-attempt DLQ policy instead of acknowledging; settlement and lease-extension callbacks likewise reject results observed after their child deadline through the existing fixed sentinels and never emit a success observation. Public APIs, configuration, retry/lease formulas, telemetry privacy, and the limitation that Go cannot forcibly terminate a callback which ignores its context are unchanged.

- Redis-backed browser-session inventory now rejects an oversized subject index before cleanup and returns only sessions whose bounded payload, positive-TTL bidirectional mappings, and global/subject integral expiry scores agree in one Lua snapshot. Device-name updates now use a complete read-only snapshot plus a second full-state compare-and-swap Lua command; any intervening payload, mapping, index, score, or TTL loss fails closed without overwriting the observed state. Invalid direct-store inputs perform no Redis I/O, and the warmed update path drops from two `GET` commands plus Lua to two `EVALSHA` commands while public APIs, configuration, payload fields, and key schema remain unchanged.

- Redis-backed browser-session create now validates direct-store hashes, millisecond lifetimes and limits before I/O, rejects global or subject indexes above the absolute 10,000-entry bound before cleanup, and refuses to adopt target orphan members. Authentication reads snapshot the payload, positive-TTL bidirectional mappings, and both expiry scores in one bounded Lua command; Go accepts only strict JSON whose subject/session-ID hashes and integral scores agree exactly. Corrupt state fails closed without changing another session, while public APIs, configuration, payload schema, key schema, and the one-command create/read boundary remain unchanged.

- Redis-backed OIDC authorization requests now reject a global pending index above the absolute 10,000-entry bound before cleanup, refuse to adopt an existing orphan index member, and consume the payload plus expiry score in one Lua result. Go accepts the one-time state only when strict payload decoding and the integral index score agree on the exact expiry; missing or mismatched state is atomically consumed and fails closed without changing another request. Sub-millisecond and non-positive millisecond inputs fail before Redis access, while public APIs, configuration, key schema, and the one-command create/consume paths remain unchanged.

- Refresh-session Redis single-family rotation and revoke now validate all family fields and state relationships, active global/user index scores, the current token reverse mapping, and every used-token reverse mapping before mutation. Incoming tokens must belong to the current/used set, history traversal is capped at 1,024, mapped replacement tokens are rejected, and invalid adapter inputs fail before Redis access. Corrupt or forged mappings cannot revoke or overwrite a valid family; successful paths remain one Lua command and public APIs, configuration, and Redis schema are unchanged.

- Refresh-session Redis user-wide revoke and active-family count now reject more than 10,000 indexed families before traversal, validate canonical family IDs, ownership, fields, and both index scores in a read-only pass, and only then clean up, revoke, or count in the same Lua command. `CreateSession` enforces the same family-ID and absolute-limit boundary before Redis access. Corrupt state fails closed through the existing invalid-session sentinel without partial mutation; public APIs, configuration, and Redis schema are unchanged.

- Browser-session Redis whole-subject revocation now rejects an index above the absolute 10,000-session bound before expiry cleanup or traversal, validates lowercase SHA-256 subject/token/session-ID values and the reverse public-ID mapping for every member, and only then removes the complete set in one Lua call. The validation pass retains session IDs for deletion, so reverse-index reads replace redundant metadata reads instead of increasing per-session lookups. Malformed, missing, cross-subject, or inconsistent mappings fail closed without partially deleting active sessions; public contracts and serialized state are unchanged.

- Browser-session Redis token revoke and subject-bound public-ID revoke now read their hash-only mappings, validate owner/token/session-ID shape and bidirectional-index consistency, and delete the payload, mappings, and global/subject indexes in one bounded Lua call each. This removes the previous `GET + EVALSHA` round trip and consistency window while preserving fixed fail-closed errors and public contracts. Warmed local telemetry observes one `redis.evalsha` span per path without claiming production latency, throughput, HA, capacity, eviction, or recovery.

- Refresh-session Redis rotation and family revoke now read the token-to-family mapping and mutate family state in one bounded Lua call each, removing the previous `GET + EVALSHA` round trip and two-command consistency window. Family IDs are format-checked inside the script, old token mappings remain until TTL for replay detection, and malformed mappings fail closed through the existing sentinels. Public `SessionStore`, HTTP/OpenAPI/SDK APIs and telemetry privacy are unchanged; warmed local tests observe one `redis.evalsha` span per operation without claiming production latency, HA, capacity or recovery.

- Browser-session inventory on Redis now uses one bounded Lua snapshot command to remove expired index entries and read payloads atomically. This removes the prior `ZRANGE + N*GET` round trips and split-read window while preserving Go-side payload, subject, expiry, session-ID, device metadata, fail-closed validation, public APIs, and the limitation that local command-count tests do not prove production Redis latency, HA, or capacity.

- OIDC discovery and token responses now reject bounded JSON documents with duplicate object keys, including escaped or case-folded duplicates, before `encoding/json` decoding. Malformed documents and multiple top-level values remain fixed-sentinel failures; normal single-key JSON, unknown fields, public APIs, API snapshot 373, and OIDC evidence schema 3 remain compatible. The scanner is limited to the existing 64 KiB discovery/token bodies and adds no ordinary request-path work.

- OIDC discovery now negotiates the token endpoint client authentication method before returning a client. Confidential clients require explicit `client_secret_basic` support or the specification default when the discovery field is absent; public clients require an explicit `none` declaration. Null, empty, malformed, oversized, or incompatible declarations fail with the fixed provider-unavailable sentinel and never downgrade to body secrets or unimplemented JWT/mTLS methods. Basic credentials apply RFC 6749 form encoding and appear only in Authorization, while public client IDs appear only in the form. Public Go, OpenAPI, and SDK APIs are unchanged; local OIDC evidence is schema 3 and remains non-production.
- OIDC Authorization Code callbacks now use additive `(*JWKSVerifier).VerifyIDTokenWithAccessToken` to bind an optional ID-token `at_hash` to the actual access token returned by the same token response. The RS256-only verifier uses the OIDC SHA-256 left-half Base64URL digest, preserves compatibility when the claim is absent, and fails closed on malformed or mismatched values without exposing token material. Transport-neutral and browser callbacks use the binding while retaining access-token verification and subject comparison; local OIDC browser evidence is schema 3 and remains explicitly non-production.

- JetStream dead-letter and invalid-message quarantine settlement now requires the same non-empty PubAck stream and sequence as ordinary and explicitly deduplicated publishes before acknowledging the source message. - Typed JetStream `Adapter.PublishDeduplicated` for caller-owned stable message IDs. - Bounded positive jitter for reliable-delivery handler retries. Static `MinimumDeliveryLease` preflight now budgets every retry at the same maximum jitter bound, while dynamic lease extension retains its interval/callback/margin formula. - Bounded positive jitter for each existing safe-method HTTP retry wait. The random increment is at most half of the effective local/`Retry-After` delay and is truncated by remaining `MaxBackoff`; the jittered delay must still fit the original request deadline before an intermediate response is closed. The private scheduling PRNG does not change public API, retry eligibility, attempt limits, tracing, or telemetry.
- Bounded `Retry-After` handling for the existing safe-method HTTP retry policy. Valid delta-seconds and HTTP dates can lengthen an exponential delay only within `MaxBackoff` and the original request deadline; over-budget values preserve the current response and stop automatic retries, malformed values retain local backoff, and header contents remain outside telemetry.
- Additive transport-neutral `httpapi.ApplicationRoute` descriptors with standard-method static `/api/v1` paths, defensive request snapshots, bounded response validation, and startup overlap checks. - Additive, default-disabled `httpclient.CircuitBreakerConfig` with bounded client-level closed/open/half-open transitions outside the retry policy. - JetStream message conversion now avoids a duplicate header scan for common small header maps while retaining exact capacity hints for larger maps.
